# 最近開啟的檔案（#73）

工作卡 [#73](https://github.com/winner0988/Pdf-reader/issues/73)；規格 §3「最近使用檔案清單」。畫面見 [screen-map.md](../ux/screen-map.md) §2「空狀態」。

## 決定

規格原本寫「預設僅記錄檔名而非完整路徑」，但只有檔名就無法從清單重新開啟檔案。負責人在 [#73](https://github.com/winner0988/Pdf-reader/issues/73#issuecomment-5890248031) 決定：

- **完整路徑只存在 app 的本機資料資料夾**；
- **畫面只顯示檔名**，前端也只拿得到檔名與代號。

## 儲存

| 項目 | 內容 |
|---|---|
| 位置 | `%LOCALAPPDATA%\io.github.winner0988.pdfreader\recent.json`（Tauri 的 `app_local_data_dir`） |
| 為什麼是 Local | 不是 Roaming：網域的漫遊設定檔不會把清單同步到其他電腦 |
| 誰能讀 | 資料夾預設只有目前的 Windows 使用者（與系統管理員）能讀 |
| 內容 | `files`：完整路徑，最新的在前，最多 20 筆；`excluded`：「不記錄此檔案」的雜湊值；`salt` |
| 寫入 | 先寫暫存檔再改名取代，當機時不會留下半份清單；清單與「不記錄」都是空的時候刪除整個檔案 |
| 讀取 | 超過 512 KiB、不是 JSON、版本不對或有未知欄位時當成沒有清單，下次變更時覆寫；不是絕對路徑的項目略過 |

- 超過 4,096 bytes（UTF-8）的路徑、不是有效 Unicode 的路徑不記錄。
- `PDF_READER_DATA_DIR` 設為絕對路徑時改用那個資料夾。E2E 測試以此讓每次執行有自己的資料夾，不碰使用者的清單（見 [e2e.md](e2e.md)）。能設定 app 環境變數的程式本來就能做更多事，這不在威脅模型內（同 WebView2 的環境變數）。

## 「不記錄此檔案」

- 在開啟的文件上，「⋯」→「不記錄此檔案」（核取）。
  - 勾選：檔案從清單移除，之後再開也不記錄；
  - 取消勾選：可以再記錄，因為檔案正開著，所以立刻放到清單最前面。
- **不存路徑**：存的是 `SHA-256(salt ‖ 小寫的路徑)`。
  - `salt` 是第一次使用時以作業系統的亂數（`getrandom`）產生的 16 bytes；
  - 光看檔案看不出是哪些檔案；有人拿著猜測的路徑逐一比對才對得上。
- 最多保留 1,000 筆，超過時丟掉最舊的。
- 路徑比對不分大小寫（Windows 的檔名不分大小寫）。
- 「清除清單」只清除最近開啟的檔案，**不清除**「不記錄」的選擇：清除後再開啟這些檔案，也不會出現在清單上。

## 流程

- **記錄**：分頁的檔案開啟成功（`opened`）時，主行程把它的路徑放到最前面。
  - 對話框、拖放、命令列、第二次啟動、重試、輸入密碼後開啟，都走同一條路。
  - 開檔失敗、還在詢問密碼的檔案不記錄。
- **清單**：`get_recent_files` 回傳 `RecentFile[]`（`id`、`displayName`）。
  - `id` 只在這次執行有效，每次啟動重新配發；
  - 主行程以 `validate` 檢查：最多 `LIMITS.maxRecentFiles`（20）筆，檔名不得含路徑分隔字元。
- **開啟**：`open_recent_file(id)` 由主行程找出路徑，開一個新分頁（與開檔對話框相同）。
  - 檔案已經不在：從清單移除並回傳 `unreadable`，畫面說明「找不到…，已從清單移除」。
- **移除**：`remove_recent_file(id)` 回傳新的清單。
- **清除**：`clear_recent_files()`。

## Windows 的「最近使用的項目」

- app 自己不呼叫 `SHAddToRecentDocs`。
- 開啟對話框設定了 `FOS_DONTADDTORECENT`（[#86](https://github.com/winner0988/Pdf-reader/issues/86)，見 [ipc-contract.md](ipc-contract.md)「開啟對話框」），在對話框中選的檔案也不會加進去。
- 不在 app 控制範圍內：在檔案總管中按兩下開啟 PDF 時，是檔案總管自己記錄。使用者可以在 Windows 設定中關閉「在開始、跳躍清單與檔案總管中顯示最近開啟的項目」。

## 驗證

- Rust（`src-tauri/src/recent.rs`）：最多 20 筆、最新的在前、不分大小寫去重；不記錄相對路徑與過長的路徑；移除與清除後不留檔案；「不記錄」只存雜湊值，重新啟動與清除後仍然有效；不是 app 寫的檔案當成沒有清單。
- IPC（`ipc_contract`）：清單最多 20 筆，檔名不得含路徑。
- 前端（`ReaderShell.test.tsx`）：列出檔名、以代號開啟、檔案不在時的說明、移除與清除、「不記錄此檔案」在選單打開時詢問主行程。
- E2E（`tests/e2e/recent.spec.ts`）：
  - `recent.json` 有完整路徑，但整個頁面的 HTML 都沒有資料夾名稱；
  - 從開始畫面重新開啟；
  - 最新的在前，清除後刪除檔案；
  - 「不記錄此檔案」之後，`recent.json` 沒有檔名，再開啟也不記錄。
