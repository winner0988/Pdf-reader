# 書籤（目錄）編輯

工作卡 [#305](https://github.com/winner0988/Pdf-reader/issues/305)（B3-17）；規格 §6「書籤導覽」；ADR 0013（編輯與存檔）。畫面與快捷鍵見 [screen-map.md](../ux/screen-map.md)「書籤編輯（B3-17）」。

在側欄的目錄中新增、改名、刪除、移動書籤。每個動作是一筆型別化的編輯，在該文件的 worker 中套用；可以復原、重做，也寫進崩潰復原的日誌；存檔照現有流程。

## 編輯指令

| 指令 | 意思 |
|---|---|
| `AddBookmark { parent, index, title, page }` | 在 `parent`（`null` 為最上層）底下第 `index` 個位置加一個書籤，指向第 `page` 頁（0 起算）；`index` 超過就放最後 |
| `RenameBookmark { id, title }` | 改名 |
| `DeleteBookmark { id }` | 刪除書籤和它底下的所有書籤 |
| `MoveBookmark { id, parent, index }` | 把書籤（連同底下的）移到 `parent` 底下第 `index` 個位置；上移、下移、升級、降級都是它 |

主行程的 `validate`：標題最多 `MAX_TEXT_BYTES`（1,024 位元組），必須是乾淨的顯示文字（沒有控制字元、看不見的格式字元、頭尾或連續空白），不能空白；頁碼與 `index` 有上限；書籤不能是自己的父項目（移到自己更深的子孫底下由 worker 拒絕）。作者不允許修改（`permissions.modify`）時拒絕。

## 書籤代號

`BookmarkId` 是書籤在 PDF 裡的物件編號，讀目錄（`GetOutline`）時給前端。編輯不會改變既有書籤的物件編號；新增的書籤由 MuPDF 依序配號，所以復原或崩潰後從原始檔重新套用同一串編輯，得到的編號相同。

物件編號可以指向文件裡的任何物件，所以 **worker 只在代號是目前目錄裡的書籤時才接受**：每次編輯先把目錄讀成一棵樹，代號不在樹上就拒絕。頁面、目錄本身、目錄根節點或任何其他物件的編號都改不到。

## worker 的做法（`crates/pdf_worker/src/engine/outline.rs`）

1. **照顯示的方式讀成樹**：從 `/Outlines` 經 `/First`、`/Next` 走，順序與讀目錄（`PdfDocument::outline`）相同（項目、它的子項目、再下一個同層項目），用堆疊而不是遞迴；走過的項目再遇到就結束那一支（循環、或同一個項目掛在兩處，都只留第一次出現的位置，和畫面一樣）。
2. **檢查**：每個項目必須是間接物件的字典；有 `/Parent` 的話必須是走到它的那個父項目（頁面的 `/Parent` 是頁面樹，所以頁面不會被當成書籤）；根節點必須是間接物件、`/Type` 為空或 `/Outlines`。不符合，或超過 `MAX_OUTLINE_ITEMS`（10,000）項、`MAX_OUTLINE_DEPTH`（64）層，整份目錄拒絕編輯，不做一半。照樣可以看。
3. **在樹上做編輯**：新增時層數與總數不能超過上限；移動時不能移到自己或底下的書籤之下，移過去之後的層數也不能超過上限。
4. **整棵樹重寫連結**：每一種編輯（包括改名）之後，依樹重寫每個項目的 `/Parent`、`/First`、`/Last`、`/Prev`、`/Next` 與 `/Count`。原本有循環或連結錯亂的目錄，編輯後就是畫面上看到的那個樣子。
5. **`/Count`**：由下往上算。展開的項目是正數（展開時看得到的子孫數）；原本收合（負數）的項目保持收合，數值依新的子孫數重算；沒有子項目就刪掉 `/Count`。根節點是整份目錄看得到的項目數。
6. **新增書籤的目標**：顯式目的地 `[頁面 /XYZ 左 上 null]`，左、上是該頁**顯示時**左上角換算回頁面座標（考慮 CropBox 與 `/Rotate`），縮放不變；沒有 `/A` 動作。沒有目錄的文件，第一次新增時建立 `/Outlines`。
7. **刪除**：書籤從父項目移除後，再用與刪除頁面相同的 `unlink` 把文件中仍指向這些書籤的參照改成 `null`；存檔時（`garbage`）它們不會留在檔案裡，標題也不會。

## 前端（`src/features/outline/`）

- 每次編輯都讓文件換一個新的 `doc`（B2-02），目錄會重新讀。重新讀的時候，同一個檔案（`session`）先繼續顯示前一份目錄（`useOutline`），目錄樹不會消失再出現。
- 展開狀態、焦點與改名中的項目都以書籤代號（`keyOf`）記，不用清單位置，所以編輯後仍跟著同一個書籤。編輯送出後，到新的目錄出現之前不接受下一個編輯；新目錄出現時，焦點回到移動或改名的書籤（刪除則移到下一個），新增的書籤直接進入改名。
- 標題送出前照主行程的規則整理（`cleanTitle`）。編輯失敗時在目錄上方顯示訊息。

## 驗證

- worker 單元（`engine/outline.rs`）：新增、改名、移動、刪除後每個連結一致（逐一檢查 `/Parent`、`/Prev`、`/Last`、`/Count`）；沒有目錄的文件建立目錄；目錄之外的物件編號（目錄、頁面樹、頁面、根節點）一律拒絕且頁面沒有被改；目錄項目其實是頁面時拒絕編輯；有循環的目錄編輯後與畫面相同且沒有循環；收合的項目保持收合；新書籤指向裁切與旋轉後顯示的左上角；層數上限；刪除的書籤存檔後不在檔案中。
- 真的沙盒（`crates/pdf_worker/tests/outline_edit.rs`）：新增、子項目、改名、刪除、移動、防止移到自己底下、經 `Revert` 重新套用後相同；目錄外的物件編號一律拒絕且 worker 繼續服務。
- 前端（`OutlineTree.test.tsx`、`tree.test.ts`）：快捷鍵、右鍵、改名、刪除確認、一次一個編輯、編輯後焦點、失敗訊息、作者不允許時沒有編輯。
- E2E（`tests/e2e/outline-edit.spec.ts`）：新增、改名、移動、刪除、復原、重做、存檔、重新開啟後目錄相同。
