# 頁面管理（B2-05）

工作卡 [#94](https://github.com/winner0988/Pdf-reader/issues/94)；依 [ADR 0013](../adr/0013-editing-and-saving.md)，編輯與存檔的共同做法見 [saving.md](saving.md)。

畫面見 [screen-map.md](../ux/screen-map.md)「頁面管理」。

## 編輯指令

頁碼從 0 起算，指的是**套用這個編輯之前**的文件。

| `Edit` | 內容 | 主行程依文件檢查 | 套用後的頁數 |
|---|---|---|---|
| `rotatePages { pages, by }` | 順時針轉 `by`，疊加在原本的旋轉上（B2-02） | 頁碼存在 | 不變 |
| `deletePages { pages }` | 刪除這些頁面 | 頁碼存在；至少留一頁 | 少 `pages` 的數量 |
| `movePages { pages, before }` | 把這些頁面一起移到第 `before` 頁之前（`before` 等於頁數時移到最後）；它們保持在文件中的先後順序，其他頁面的順序也不變 | 頁碼存在；`before` 不超過頁數 | 不變 |
| `insertBlankPage { at, like }` | 在索引 `at` 插入空白頁（`at` 等於頁數時插在最後），大小與第 `like` 頁顯示的大小相同，不旋轉 | `at` 不超過頁數；第 `like` 頁存在；頁數未達上限 | 加 1 |

- **三層檢查**：
  1. `ipc_contract` 先驗證指令本身：頁碼清單不可為空、不重複、最多 `MAX_PAGE_COUNT`（100,000）個，位置也不超過這個上限；
  2. 主行程依文件的頁數檢查（上表）；
  3. worker 在改動前再檢查一次。任何參數錯誤，文件都不變。
- **權限**（MVP-19）：四種都需要 `/P` 的第 11 位元（組合文件）或第 4 位元（修改），比照 Acrobat。
- **回報**：worker 回報套用後的頁面尺寸；主行程確認頁數符合上表最後一欄，否則視為協定錯誤。
- 例：刪除第 3 頁、把第 5 頁移到最前面、把第 2 頁向右轉，依序是：
  - `deletePages { pages: [2] }`；
  - `movePages { pages: [3], before: 0 }`（刪除後第 5 頁是索引 3）；
  - `rotatePages { pages: [2], by: "cw90" }`。

## worker 的做法

- **刪除**：`mupdf` 繫結的 `delete_pages`，再處理指向被刪除頁面的參照（下一節）。
- **移動**：繫結一次只能移動一頁（`move_page`）。
  - 先把要移動的頁面依序移到最後，再整塊移到目標位置，最多 2 × 頁數次；
  - 中途失敗時，把已做的移動反向做回去。
- **插入**：繫結的 `new_page_at`。新頁面的 MediaBox 是 `[0 0 寬 高]`，寬高取自第 `like` 頁顯示的大小（已套用它的旋轉），所以在旋轉過的頁面旁插入的空白頁，看起來一樣大。
- **中途失敗**：MuPDF 在修改途中失敗（`internal`），或參照處理超過上限（`limitExceeded`）時，worker 裡的文件可能只改了一半。
  - 主行程把這份文件標記為需要重新開啟：下一個請求時，從檔案重新開啟，並重新套用之前成功的編輯。
  - 以密碼開啟的文件例外：密碼沒有保留，分頁改回「需要密碼」（見 [encryption.md](encryption.md)）。

## 被刪除的頁面真的離開檔案

- **問題**：MuPDF 刪除頁面時，只把它移出頁面樹。
  - 目錄項目、連結、具名目的地、開啟動作、結構樹等仍可能指向它。
  - 完整重寫時，被指到的物件會保留，**被刪除頁面的內容就還在檔案中**。
  - 這與 ADR 0013「刪除的內容真的從檔案中移除」不符。
- **做法**：刪除後，worker 把文件中所有指向被刪除頁面的參照改成 `null`（`crates/pdf_worker/src/unlink.rs`）。
  - 目錄項目與連結仍在，但點了沒有作用，如同指向不存在頁面的連結。
  - 存檔（完整重寫）時，被刪除的頁面，以及只有它用到的內容，一起從檔案中移除。
  - 損壞的頁面樹可能讓同一個頁面物件出現兩次；仍在頁面樹中的那一個不受影響。
  - 走訪的字典與陣列最多 2,000 萬個，與隱私匯出相同；超過就停止，文件改為重新開啟（上一節）。
- **驗證**：
  - 刪除有連結或目錄指向的頁面，存檔後，那一頁的內容不在檔案中；
  - 拿掉這一步時，同樣的測試失敗：頁面的內容還在檔案中。
- **尚未處理**（[#138](https://github.com/winner0988/Pdf-reader/issues/138)）：
  - 結構樹（標記 PDF）中描述被刪除頁面的元素（例如替代文字）仍保留；
  - 被刪除頁面上的表單欄位，連同它們的值，仍在文件的表單中；
  - 已簽章的文件以增量更新存檔，被刪除的頁面仍在原本的位元組中（見 [saving.md](saving.md)）。

## 縮圖上的操作（前端）

- `src/features/thumbnails/`：
  - `Thumbnails.tsx`：縮圖清單是可以多選的 listbox（`aria-multiselectable`，每張縮圖是 `option`，`aria-selected` 表示選取、`aria-current` 表示正在閱讀的頁面），只有一張縮圖在 Tab 順序中；
  - `selection.ts`：選取（點擊、`Ctrl`、`Shift`、全選），以及編輯後選取跟著頁面走；
  - `MovePagesDialog.tsx`：「移到…」；
  - `api.ts`：`apply_edit` 的呼叫。頁面只送文件 id 與編輯指令。
- **拖曳用指標事件**，不用 HTML5 拖放：視窗的檔案拖放（MVP-06）由 Tauri 在原生層接手，WebView 內的拖放事件因此不會觸發。
- 一次一個編輯：送出後到結果回來前，其他操作停用。下一個編輯的頁碼要以這一個的結果計算。
- 側欄以分頁的工作階段（`session`）為 key，不是文件 id：編輯後文件 id 會變，側欄不重新掛載，所以停在「縮圖」並保留選取。
- 刪除頁面後，若正在閱讀的頁碼超過頁數，改為最後一頁。

## 復原與重做

依 ADR 0013：worker 保留原始位元組，復原時重新開啟並套用前 n−1 個編輯。

- **歷程**（主行程，`src-tauri/src/history.rs`）：從檔案讀入或上次寫入後的每個編輯，依序記錄；前面若干個已套用，後面的是復原掉、可以重做的。
  - 有已套用的編輯時標示「未儲存」：全部復原後，分頁不再標示。
  - 做了新的編輯，復原掉的就不能再重做。
  - 兩次存檔之間最多 `MAX_UNDO_EDITS`（1,000）個編輯；再多時請先存檔。
- **復原**（`undo_edit`）：`WorkerRequest::Revert { edits }` 帶著最後一個以外的已套用編輯。
  - worker 從保留的位元組重新開啟，依序套用；全部成功才取代畫面上的文件，任何一個失敗，文件都維持原樣。
  - 文件換一個新的 id，與一般編輯相同。
- **重做**（`redo_edit`）：把下一個編輯再套用一次（`WorkerRequest::Edit`）。
- **存檔之後**：檔案成為新的起點。
  - 歷程清空，不能復原到存檔之前；
  - worker 改為保留剛寫好的檔案的位元組（`WorkerRequest::Rebase`，主行程交出唯讀 handle）。不解析檔案，所以以密碼開啟的文件也不需要密碼；失敗時文件改為下次請求時重新開啟。
- **worker 當掉**：在新的 worker 中從檔案開啟，重新套用已套用的編輯；復原掉的仍可以重做。新 worker 保留的是檔案的位元組，與歷程的起點相同。
- **記憶體**：worker 另外保留一份原始位元組，因為繫結開檔時會把位元組複製給 MuPDF，無法共用。所以每份文件多用一份檔案大小的記憶體；512 MB 的文件約多 512 MB，仍在 worker 的 2 GiB 上限內，但存檔時會比較緊。
- **以密碼開啟的文件，復原時再輸入一次密碼**（負責人於 2026-10-01 決定，[#94](https://github.com/winner0988/Pdf-reader/issues/94)）：
  - 密碼沒有保留（[encryption.md](encryption.md)）。worker 保留的原始位元組仍是加密的，與磁碟上的檔案相同。
  - 復原先不帶密碼送出：這類文件會得到 `encrypted`，頁面就顯示 pages.undoPassword 對話框。
  - 輸入的密碼只隨那一次 `undo_edit`／`WorkerRequest::Revert` 送到 worker，用來重新開啟原始位元組，請求送出後即清除（與開檔相同）。
  - 密碼錯誤時同樣得到 `encrypted`，頁面知道送過密碼，就說「密碼不正確」，文件不變；取消則不復原。
  - 重做不需要密碼：只是把下一個編輯套用到目前的文件。
  - 只有權限限制、沒有開啟密碼的加密文件，不必輸入密碼。
- **前端**：
  - `Ctrl+Z` 復原，`Ctrl+Y` 或 `Ctrl+Shift+Z` 重做；「⋯」選單也有這兩項，不能用時停用。
  - 焦點在文字欄位（例如搜尋框）時，這些鍵留給欄位自己的復原。

## 驗證

- `ipc_contract`：頁碼清單、位置與上限的驗證；前端送來的 JSON 形式。
- worker（`engine.rs`）：
  - 刪除（範圍、重複、至少留一頁）；
  - 移動（多頁、次序、移到最後、已在原位）；
  - 插入（最前、最後、大小取自旋轉過的頁面、不旋轉）；
  - 被刪除頁面在存檔後的檔案中消失（連結與目錄指向它時）。
- 主行程（`documents.rs`，真正的 worker）：
  - 旋轉、插入、刪除、移動依序套用，每一步的頁面尺寸都正確；
  - worker 當掉後重新開啟並重新套用，另存的檔案相同；
  - 參數錯誤在送到 worker 前被拒絕；
  - 復原與重做來回走過編輯，全部復原後不再標示未儲存；新的編輯丟掉可重做的；
  - 存檔後復原回到存好的檔案，不是最初開啟的樣子；
  - worker 當掉後，復原掉的仍可重做；
  - 以密碼開啟的文件：沒有密碼或密碼錯誤時回 `encrypted`、文件不變，密碼正確時復原；重做不需要密碼。
- worker 經由真正的沙盒（`crates/pdf_worker/tests/saving.rs`）：`Revert` 從保留的位元組重新開啟並套用；其中一個編輯失敗時文件不變；以密碼開啟的文件要帶正確的密碼；`Rebase` 之後從存好的檔案重新開啟。
- 前端（Vitest）：`selection.test.ts`（選取與編輯後的選取）、`Thumbnails.test.tsx`（點擊與修飾鍵、右鍵功能表的每一項、`Delete` 但不能刪光、「移到…」與頁碼範圍、拖曳、作者不允許時）；`Undo.test.tsx`（`Ctrl+Z`／`Ctrl+Y`／`Ctrl+Shift+Z`、選單項目、文字欄位中不作用、以密碼開啟的文件再要一次密碼、密碼錯誤時說明、取消時不復原）。
- E2E（`tests/e2e/pages.spec.ts`）：
  - 以縮圖做工作卡的第一個驗收情境：右鍵刪除第 3 頁、以「移到…」把第 5 頁移到最前面、右鍵把第 2 頁向右轉；另存後重新開啟：
    - 共 9 頁；
    - 搜尋「needle」（原本第 7 頁）落在第 6 頁，「Page 5 of 10」在第 1 頁，「Page 3 of 10」找不到；
    - 第 3 頁（原本的第 2 頁）是橫的。
  - 以滑鼠把第 2 張縮圖拖到第 1 張之前：兩頁對調；
  - 工作卡的第二個驗收情境：做了上面三個編輯後按三次 `Ctrl+Z`，回到 10 頁、順序與方向都如原本，分頁不再標示未儲存；再按 `Ctrl+Y`，第 3 頁又被刪除；
  - 以密碼開啟 `benign/encrypted-aes256.pdf`，轉一頁後按 `Ctrl+Z`：對話框要密碼，錯誤的密碼被拒絕，正確的密碼讓頁面轉回來、分頁不再標示未儲存。
