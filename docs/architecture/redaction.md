# 安全遮蔽（B2-19～B2-22）

依 [ADR 0016](../adr/0016-redaction.md)（已接受）。工作卡：[#214](https://github.com/winner0988/Pdf-reader/issues/214)（B2-19 契約與 worker）、[#215](https://github.com/winner0988/Pdf-reader/issues/215)（B2-20 存檔後驗證）、[#216](https://github.com/winner0988/Pdf-reader/issues/216)（B2-21 畫面）、[#217](https://github.com/winner0988/Pdf-reader/issues/217)（B2-22 端對端與邊界）。POC：`crates/pdf_worker/tests/redaction_poc.rs`。

遮蔽是**把範圍內的內容從檔案中拿掉**，不是蓋一個黑框。分兩步：標記範圍，確認後套用；存檔時整份重寫。

## 編輯指令

| `Edit` | 內容 |
|---|---|
| `addRedaction { page, rect }` | 在頁面上加一個標記（`Redact` 註解）：紅色外框、半透明。和其他註解一樣列在 `get_page_annotations`（`kind: "redaction"`），可以移動、縮放（`setAnnotationRect`）與刪除（`deleteAnnotation`）。還沒有移除任何東西 |
| `applyRedactions` | 套用整份文件所有的標記（見下）。沒有標記時拒絕 |

- 兩者都是一般的編輯（ADR 0013）：記在編輯歷程與崩潰復原日誌中（日誌只有範圍，沒有被遮蔽的內容），**可以復原到存檔為止**：復原從 worker 保留的原始位元組重新開啟並重播其餘的編輯。
- **權限**：作者不允許修改（`/P` 第 4 位元，MVP-19）時兩者都拒絕，標記也是（標記的目的就是改變頁面）。
- **已簽章的文件**拒絕（worker 檢查）：以增量更新存檔會留下整份舊內容，整份重寫又讓簽章失效（比照扁平化、加密與壓縮）。
- 範圍的規則與其他註解相同：有限的數字、寬高至少 `MIN_ANNOTATION_SIDE_PT`、頁碼在文件內。

## 套用（`PdfDocument::apply_redactions`）

對每一頁有標記的頁面：

1. **範圍內的其他註解與表單欄位刪除**（POC 6：MuPDF 不處理它們）：
   - 便條、螢光筆、手繪、印章、文字方塊等，邊界與任何一個標記重疊就刪除，連同它的彈出視窗；
   - 表單欄位（widget）重疊就刪除，而且**欄位的值一併拿掉**：該 widget 與它上層欄位的 `/V`、`/DV`（值可以繼承），以及同一個欄位其他 widget 的外觀（`/AP`、`/AS`），否則在範圍外的另一個 widget 仍會畫出那個值；
   - 其他物件對它們的參照改成 `null`（`unlink`），整份重寫時就不會留在檔案裡。
2. **MuPDF 套用**（`pdf_redact_page`），選項固定為 ADR 的決定：
   - `black_boxes`：在原處畫黑框，看得出哪裡被遮蔽；
   - 圖片：`Pixels`，範圍內的像素在圖片資料中被換掉；
   - 向量圖形：`RemoveIfTouched`，碰到範圍就整個移除；
   - 文字：`Remove`，含看不見的文字（例如 OCR 圖層）與表單物件裡的文字。

   不使用只蓋住的選項（POC 4）。範圍內的連結由 MuPDF 一併移除。標記在套用後就沒有了。
3. **辨識的文字**（ADR 0015）：那些頁面在 worker 記憶體中的 OCR 結果丟掉（圖片的像素變了）；分頁的文件換了新的代號，OCR 會重新看過頁面、重新辨識。

## 套用前的摘要（`get_redaction_summary`）

`RedactionSummary`：`marks`（標記數）、`pages`（有標記的頁數）、`annotations`（會一併刪除的其他註解）、`fields`（會一併刪除的表單欄位）。由文件自己的 worker 依目前的文件計算，給 B2-21 的確認對話框在套用前說明。

## 範圍之外（不會自動處理，ADR 0016）

書籤標題、頁面標籤、縮圖、內嵌的檔案、標記結構的 `ActualText`、文件資訊與 XMP、字型子集裡的字形、磁碟上舊檔案的位元組。確認對話框與完成後的說明會列出（B2-21）；中繼資料用隱私匯出。

## 存檔

沒有簽章的文件一律**整份重寫並整理垃圾**（ADR 0013），被取代的內容串流、刪除的註解與欄位都不會留在檔案裡（POC 5）。

## 存檔後驗證（B2-20）

- **套用時記下**：每個範圍在套用前的文字（字元的中心在範圍內的），連同頁面的物件編號（頁面在存檔前可能被移動）。只在這份文件的 worker 記憶體裡：不寫進崩潰復原日誌、不進日誌與錯誤訊息、不傳給主行程或前端；字串在丟掉時清除（`Zeroizing`）。
- **存檔時**（只在記下的東西還在時）：worker 先把檔案寫進記憶體，**重新開啟寫出的位元組**檢查，再寫進暫存檔：
  - 每個範圍：在寫出的檔案的那一頁（依物件編號找到現在的頁序；那一頁被刪了就不檢查範圍），範圍內不能有任何文字；
  - 整份文件的文字（空白合併成一個）不能含有任何一個範圍被移除的字（4 個字以上的才找：更短的會在一般的字裡被找到；範圍本身仍會檢查）。可能誤報：被移除的字剛好也出現在別處時算沒通過，寧可多說；
  - 加密的文件：worker 不留密碼，無法打開寫出的檔案，所以把同一份文件**不加密地**寫進記憶體再檢查（物件相同，只差加密）。
- **結果**：存檔的回應（`SaveResult.redaction`）是 `{ places }`：沒有問題是 0，否則是有文字的範圍數加上找到的字串數；沒有套用過遮蔽時是 `null`。狀態列只在 0 時說「已遮蔽並驗證」（`saving.redactionVerified`），否則說沒有通過、幾處、請先不要分享並另存新檔後再檢查（`saving.redactionFailed`）。存檔失敗時沒有任何結果。
- **何時丟掉**：存好的檔案取代原檔之後（主行程請 worker 保留新的位元組，`Rebase`），worker 丟掉記下的字串；取代失敗（例如檔案被占用）時留著，下次存檔再檢查一次。復原到套用之前，文件從原始位元組重新開啟，記下的也跟著沒有；重做會再記一次。
- 只檢查文字：圖片與向量圖形靠套用的選項（ADR 0016）。

## 測試

- worker（`crates/pdf_worker/tests/redaction.rs`，升級 MuPDF 要重跑）：
  - 標記是一個註解，列為 `redaction`，還沒移除任何東西；摘要的數字；
  - 範圍內的文字從頁面、搜尋與存檔後的位元組都消失，範圍外的文字不變；範圍內的便條與欄位（含值）、連結也不在檔案裡；書籤與文件資訊仍在（ADR 列出的洞）；
  - 圖片只在範圍內失去像素，被碰到的向量圖形整個移除；
  - 表單物件裡的文字與看不見的文字；
  - **中文字與嵌入的字型**（B3-03 從 HTML 做出的頁面，內嵌 Droid 字型）；
  - **轉過 90° 的頁面**：以搜尋找到的範圍標記；
  - 一個欄位有兩個 widget，只有一個在範圍內：值在兩處都消失；
  - 標記可以移動與刪除，沒有標記時不能套用；
  - 已簽章的文件不能標記也不能套用。
- 契約：範圍的規則、`applyRedactions` 的 JSON、摘要的上限；postcard 往返。
- 主行程（真正的 worker）：標記、套用、復原（文字與標記回來）、重做、存檔（`redaction` 是 0 處）、重新開啟，檔案的位元組裡沒有被遮蔽的字；檔案取代原檔之後，下一次存檔沒有東西要檢查；作者不允許修改時拒絕。
- 存檔後驗證（`engine/redaction.rs` 的單元測試）：套用後存檔是 0 處，取代之前再存一次仍會檢查，丟掉之後沒有結果；**負向對照**：以只蓋住文字的選項套用，結果是 2 處（範圍有字、字串也找得到）；套用後刪掉前面的頁面，範圍仍在對的頁面檢查；被遮蔽的那一頁被刪掉時不檢查範圍；太短的字不在整份文件中找；加密的文件以不加密的副本檢查，存好的檔案仍是加密的。
- 前端：0 處時說「已遮蔽並驗證」，否則說沒有通過與處數，都不說一般的「已儲存。」。
