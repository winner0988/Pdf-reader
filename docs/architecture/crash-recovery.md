# 崩潰復原（B2-13）

工作卡 [#102](https://github.com/winner0988/Pdf-reader/issues/102)（B2-13）；規格 §6「本地崩潰復原：每次編輯動作即存檔」；[ADR 0013](../adr/0013-editing-and-saving.md)「崩潰復原」。程式在 `src-tauri/src/recovery.rs`（日誌）與 `src-tauri/src/documents.rs`（何時寫、何時刪、何時提示）。

編輯途中 app 當機、被強制結束或斷電時，下次開啟同一個檔案會提示還原未儲存的變更。不需要雲端備份，也不會自動寫回原檔。

## 復原日誌

依 ADR 0013，編輯指令的清單同時就是復原日誌。

| 項目 | 內容 |
|---|---|
| 位置 | app 本機資料資料夾的 `recovery\`（與 `recent.json` 相同的資料夾，見 [local-data.md](local-data.md)） |
| 檔名 | 32 個十六進位字元的亂數加 `.json`：資料夾的檔名看不出是哪些檔案 |
| 內容 | `version`；檔案的**完整路徑**；讀取時的大小與修改時間；已套用、還沒存檔的編輯（`Edit`，與前端送來的相同格式），依序 |
| 一份文件 | 最多一個日誌，有未儲存的變更時才存在 |
| 寫入 | 每次編輯、復原、重做之後，以暫存檔改名的方式**整個重寫**：當機時不會留下半個檔案 |
| 刪除 | 存檔（含另存新檔）、復原到沒有變更、關閉分頁（關閉前已詢問「不儲存」）、關閉視窗時選擇「不儲存」 |
| 上限 | 4 MiB。會讓日誌超過上限的編輯會被拒絕（`limitExceeded`），畫面請使用者先存檔；最多 1,000 個編輯（`LIMITS.maxUndoEdits`）的限制本來就在 |

讀取日誌時把它當成**不可信任的資料**，與資料夾中其他檔案相同：

- 超過 4 MiB、不是 JSON、版本不對、有未知欄位、路徑不是絕對路徑，一律略過（不刪除，也不當成錯誤）；系統無法表示的修改時間當成檔案已經改變；
- 編輯的數量（1 到 1,000 個）與每個編輯本身都以 `validate` 檢查，與前端送來的編輯相同；
- 開啟檔案時，再以文件實際的頁數與作者的權限（MVP-19）逐一檢查：頁碼不存在、會刪掉所有頁面、作者不允許變更頁面時，日誌不能套用（見下方「無法還原」）；
- 開啟檔案時最多看 64 個日誌。

## 下次開啟同一個檔案時

開檔成功後，主行程找這個檔案的日誌（路徑比對不分大小寫，同 [recent-files.md](recent-files.md)），結果放在 `DocumentInfo.recovery`：

| `recovery` | 條件 | 畫面 |
|---|---|---|
| `none` | 沒有日誌，或已經回答過 | 無 |
| `available` | 檔案的大小與修改時間沒變，日誌的編輯都能套用在這份文件上 | 畫布上方的提示列：「還原變更」、「捨棄變更」、✕（稍後再決定） |
| `partial` | 同 `available`，但有一些編輯沒有在日誌裡（見下方「插入其他檔案的頁面」） | 提示列說明哪些無法還原：「還原變更」（還原能還原的）、「捨棄變更」、✕ |
| `lost` | 同上，但日誌裡一個編輯也沒有 | 提示列說明無法還原：「捨棄變更」、✕ |
| `stale` | 檔案在那之後被修改過，或日誌的編輯不能套用 | 提示列說明無法還原：「捨棄變更」、✕（稍後再決定） |

- **還原**（`recover_edits`）：在文件自己的 worker 中依序套用日誌的編輯，它們成為文件的編輯歷史，可以逐一復原；分頁標示未儲存。日誌改由這個分頁使用。
  - 文件已經有自己的編輯時拒絕（`invalidArgument`），畫面請使用者先復原：那些編輯是在檔案上做的，不是在日誌的編輯之後。
  - worker 中途失敗時，文件在下一個請求前從檔案重新開啟，提示仍在，可以再試。
- **捨棄**（`discard_recovered_edits`）：刪除日誌。
- **稍後再決定**（✕）：日誌保留，下次開啟這個檔案時再提示；關閉分頁也一樣。
- 同一個檔案同時開在兩個分頁時，只有一個分頁會看到提示。
- 以密碼開啟的檔案：輸入密碼、開檔成功後才提示；日誌中沒有密碼。

## 插入其他檔案的頁面（B2-06）

「插入其他檔案的頁面」（見 [merge.md](merge.md)）的編輯用到另一個檔案的副本，最多 64 MiB，4 MiB 的日誌放不下，所以（擁有者 2026-10-07 的決定）：

- 日誌只記到**第一個**插入之前的編輯，並在 `lost` 記下被留在外面的編輯有幾個：那個插入，以及在那之後的所有編輯（它們是在插入的頁面上做的，沒有那些頁面不能套用）。
- 日誌的編輯可以是零個：只要 `lost` 大於零，日誌還是有效，所以當機之後仍然知道「有變更沒有儲存」。
- 下次開啟時，提示列說明哪些無法還原（`partial`、`lost`）。因為少了一些編輯，以密碼開啟的文件在 worker 崩潰後，**不會**自動重新套用日誌，而是提示。
- 讀日誌時，含有插入其他檔案的頁面的編輯是不合格的（日誌不可能有）。
- 還原之後，編輯歷史就是還原的那些，`lost` 不再有；使用者已經被告知。

## worker 崩潰（ADR 0012）

- 一般文件：主行程本來就保留編輯，下一個請求時以新的 worker 開啟原檔並重新套用（B2-05），使用者不會遺失變更。
- 以密碼開啟的文件：密碼沒有保留（MVP-16），分頁會再要求密碼。日誌保留下來，輸入密碼、檔案重新開啟後**自動**重新套用，不再詢問（使用者沒有選擇放棄這些變更）；檔案已被修改時改為提示 `stale`。

## 隱私

- 日誌含有檔案的完整路徑，以及編輯內容；之後的編輯功能（附註、表單）會讓它含有使用者輸入的文字。
- 只存在 app 的本機資料資料夾（不漫遊，預設只有目前的 Windows 使用者能讀），app 不會上傳。
- 正常操作下（存檔、不儲存、關閉）不會留下日誌；只有 app 沒有正常結束時才會留下，並在下次開啟同一個檔案時處理。
- **清除最近開啟的檔案**、或**關閉「記錄最近開啟的檔案」**時，一併刪除目前沒有分頁使用的日誌（B2-12）。
- 關閉 app 後，也可以直接刪除整個資料夾。

## 測試

- Rust（`src-tauri/src/recovery.rs`）：只找得到同一個檔案的日誌、檔名不含路徑、使用中的日誌不重複提示、檔案已變、清除、大小上限、不可信任的日誌（不是 JSON、版本、未知欄位、沒有編輯、無效的編輯、太多編輯、相對路徑、過大、無法表示的時間）。
- Rust（`src-tauri/src/documents.rs`）：上一次執行留下的編輯在下次開啟時提示並還原、可以逐一復原、存檔後沒有日誌；檔案已變時無法還原、捨棄刪除日誌；存檔、復原到沒有變更、關閉分頁、關閉視窗、另存新檔都不留日誌；沒有回答的提示保留到清除清單；文件自己的編輯優先；日誌以實際頁數與作者權限檢查；以密碼開啟的文件在 worker 崩潰、重新輸入密碼後自動取回編輯。
- 前端（`src/features/recovery/Recovery.test.tsx`）：提示、還原、捨棄、無法還原時只能捨棄、稍後再決定、文件有自己的編輯時的說明；縮圖在變更太多時請使用者先存檔。
- E2E（`tests/e2e/recovery.spec.ts`）：刪除一頁後強制結束 app，以同一個資料資料夾重新開啟同一個檔案，提示還原；還原後少一頁、分頁標示未儲存；存檔後沒有日誌，再開啟時不再提示。
