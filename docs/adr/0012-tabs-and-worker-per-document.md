# ADR 0012：多份文件以分頁呈現，每份文件一個 worker，單一執行個體

## 狀態
提議中

（負責人於 2026-09-24 選擇「分頁」；本 ADR 記錄隨之而來的行程模型，待負責人改為「已接受」。）

## 背景
- MVP 的視窗一次只顯示一份文件，主行程只有一個 worker（`src-tauri/src/documents.rs` 的 `current`）；開啟新檔案會取代目前的文件。
- 負責人要求同時開啟多份 PDF，並選擇以分頁呈現（#69）。
- REL-03（#68）讓 PDF Reader 可以設為預設程式：app 已開啟時，從檔案總管開啟 PDF 應該加到現有的視窗，而不是再開一個程式。
- ADR 0008：worker 被惡意 PDF 攻陷時，影響要侷限在 worker 內。如果多份文件共用一個 worker，攻陷它的 PDF 就能讀到同一個 worker 裡其他文件的內容。

## 選項
| 選項 | 文件之間的隔離 | 資源 |
|---|---|---|
| A. 所有分頁共用一個 worker | 無：一份惡意 PDF 可以讀取其他開啟中的文件 | 最省 |
| **B. 每份文件一個 worker（採用）** | 有：每份文件在自己的沙盒行程中 | 每個 worker 數十 MB；以分頁上限控制 |
| C. 每個分頁一個 app 行程 | 最強，連 WebView 都分開 | 最耗；不是「一個視窗多個分頁」 |

## 決定
- **分頁**：一個視窗可以開多份文件，每份一個分頁，上限 20 份。
- **每份文件一個 `pdf_worker`**：
  - 開啟文件時啟動它自己的 worker（同一個 AppContainer profile，不同的行程與 Job Object）；
  - 關閉分頁就結束它的 worker；
  - 一個 worker 崩潰只影響它的分頁。
- **單一執行個體**：
  - 第二個執行個體把命令列上的檔案交給第一個，然後結束；
  - 檔案路徑只在兩個主行程之間傳遞，不經過前端；
  - 以 Tauri 官方的 `tauri-plugin-single-instance` 實作。在 Windows 上它以具名 mutex 判斷是否已有執行個體，再以 `WM_COPYDATA` 把命令列交給第一個執行個體的隱藏視窗：
    - 完整性等級較低的行程（例如 AppContainer 中的 `pdf_worker`，它的 Job Object 也禁止使用其他行程的視窗）受 UIPI 限制，無法送出這個訊息，不能藉此讓 app 開啟任意檔案；
    - 同一使用者、同一完整性等級的程式可以送出，但那等同於它自己帶參數啟動本程式；
    - 外掛讀取訊息時不檢查長度就當成 C 字串，只有同一完整性等級的程式能觸發，而那樣的程式本來就能讀寫本程式的記憶體。
- **前端**：仍然只看到不透明的 `DocumentId`、分頁代號與檔名。

## 後果
- **換來**：
  - 同時開多份文件；
  - 一份惡意 PDF 攻陷它的 worker 後，碰不到其他開啟中的文件；
  - 從檔案總管開啟的 PDF 都在同一個視窗。
- **付出**：
  - 每份開啟中的文件多一個行程與數十 MB 記憶體；
  - 多一個依賴（single-instance 外掛），需要安全審查。
- **之後若要改變**：
  - 改成共用 worker 會失去文件之間的隔離，需要另立 ADR；
  - 放寬分頁上限時，要重新評估記憶體。
