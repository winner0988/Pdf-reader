# ADR 0022：遠端資源永遠不由 app 載入；使用者確認完整網址後可以交給系統瀏覽器開啟

## 狀態
提議中

（工作卡 #239〔B3-08〕。接受後取代 ADR 0002 中「信任後允許該文件的遠端資源載入」這一部分，並結束 ADR 0009 對「信任後載入」的延後；ADR 0002 的預設封鎖、偵測與提示不變。負責人決定選項。）

## 背景
- ADR 0002（已接受）：遠端資源預設封鎖、偵測後提示；使用者可以逐份信任，允許該文件的遠端資源載入；信任以內容雜湊為準。
- ADR 0009（已接受）：app 唯一的連網是使用者按「檢查更新」；「信任後載入」延後，要做就另立 ADR，下載只能由主行程、只針對已信任的文件。AGENTS.md 原則 1 與 `scripts/ci/forbidden-patterns.txt` 守著這一點。
- 事實：
  - MuPDF 不會下載任何東西，也不支援外部串流（串流字典的 `/F` 指向網址）、XFA、RichMedia。即使「信任」了，現在也沒有任何遠端內容能被顯示。
  - 掃描（MVP-11）偵測得到的遠端引用是：`/FS /URL` 的檔案規格、UNC 路徑（`\\server\…`，開啟就可能送出 Windows 的 NTLM 雜湊）、`GoToR` 連到其他檔案、XFA、RichMedia。
  - 要做到「載入」，需要：主行程的下載器（新的連網路徑）、把下載的位元組交給 worker、在記憶體中把外部引用改寫成內嵌資料，以及每一種資源各自的處理。
  - 遠端引用最常見的用途正是追蹤信標：開檔的時間與 IP。
- 使用者確認後交給系統瀏覽器開啟的連結，是瀏覽器連網，不是 app 連網（ADR 0009）。

## 選項

| 選項 | 內容 | 代價 |
|---|---|---|
| A. 維持封鎖 | 遠端資源永遠只偵測、封鎖、提示；拿掉「信任」 | 少數真的需要遠端內容的文件看不到它，也沒有退路 |
| B. 信任後由主行程下載（ADR 0002 原本的設計） | 逐份信任（內容雜湊），主行程以 WinHTTP 只抓 https、只抓文件引用的位址，有大小、時間、數量上限，不帶 cookie 與識別資料；下載的內容當成資料交給 worker 改寫進文件 | 新增一條連網路徑，改核心原則、守門腳本與離線驗證；MuPDF 不支援外部引用，要自己改寫每一種資源；工作量大、收益小 |
| **C. 不載入；可以交給系統瀏覽器開啟（建議）** | 與 A 相同，app 不載入任何遠端內容；但對有網址的引用（`/FS /URL`、`GoToR` 的網址）提供「在瀏覽器開啟」，照原則 5 顯示完整網址、確認後才交給系統 | 文件本身仍看不到遠端內容；使用者要的話自己在瀏覽器看 |

## 決定（選項 C）
- app **永遠不下載** PDF 引用的遠端資源。程式碼中仍然只有 `src-tauri/src/update_check.rs` 能連網（ADR 0009 不變）。
- 橫幅照舊列出偵測到的遠端引用。有網址的那幾種多一個「在瀏覽器開啟」：
  - 顯示完整網址，使用者確認後交給系統；規則與外部連結相同（原則 5）：只允許 `http`、`https`，其他 scheme 一律封鎖；
  - 一次只開一個，由使用者逐一點選，沒有「全部開啟」。
- UNC 路徑、`file:`、`smb:` 等一律不提供開啟（避免 NTLM 外洩）。
- 「信任」不再需要：沒有東西會因為信任而載入。CONTEXT.md 的「信任（單一文件）」、規格 §3 的「信任機制」與「信任與機敏管理」清單，接受後改為「遠端資源只偵測、封鎖、提示，可交給瀏覽器開啟」；清單只剩機敏標記。

## 後果
- 換來：
  - 核心原則不變：app 不多任何連網路徑，`forbidden-patterns.txt` 與離線驗證都不用改；
  - 追蹤信標永遠不會被 app 觸發；
  - 真的想看遠端內容的使用者有退路，而且是在他看過完整網址之後、在瀏覽器裡。
- 付出：
  - 規格 §3 的「信任後載入」不做了，要改規格書與 CONTEXT.md；
  - 引用遠端內容的文件，在 app 裡永遠看不到那些內容。
- 與其他 ADR 的關係：取代 ADR 0002 的「信任後載入」部分；ADR 0009 的「延後」以本 ADR 結束；原則 5（外部連結必須確認）延伸到遠端引用。
- 之後若要改變：要讓 app 自己下載，就是選項 B，需要新的 ADR 並修改 ADR 0009 與 AGENTS.md 原則 1。
