# ADR 0009：預設網路政策

## 狀態
提議中（待專案負責人決定，見工作卡 DEC-01）

## 背景
規格書同時要求「完全離線運作、不串接任何外部 API」、「透過 GitHub Releases API 檢查更新」，以及「使用者信任的文件可以載入遠端資源」（ADR 0002）。這三條彼此衝突，必須明訂應用程式在什麼情況下可以連網，否則 agent 會各自解讀。

補充事實：MuPDF 本身不會主動下載 PDF 內引用的遠端資源；如果要「信任後載入」，需要另外寫一個下載器，等於新增一條連網路徑。另外，使用者確認後交給系統瀏覽器開啟的連結，是瀏覽器連網，不是本應用程式連網。

## 選項
- **A. 完全零網路**：應用程式沒有任何連網程式碼。更新由使用者自行到 GitHub 下載；遠端資源永遠只偵測、封鎖、提示。
- **B. 預設零網路，只允許使用者手動觸發的單一請求**：設定頁提供「檢查更新」按鈕，按下才連到 GitHub Releases，只送最基本的 HTTP 請求，不帶任何識別碼；不做自動檢查。遠端資源先維持只封鎖、只提示。
- **C. 自動檢查更新**：啟動時自動連網。違反「開檔不連網」的精神，不建議。

## 建議
採用 **B**，並將「信任後載入遠端資源」延後到確實有需求時再做（屆時另立 ADR，並規定下載只能由主行程執行、只能針對已信任文件）。MVP 期間等同 A：程式碼中不得有任何連網能力。

## 後果
- 定案前，所有 PR 一律依選項 A 執行：不得引入 HTTP client、updater 或具網路能力的 Tauri 外掛（CI 的 `scripts/ci/forbidden-patterns.txt` 會擋下）。
- 定案後需同步更新規格書 §1、§3，以及 ADR 0002 的後果段落。
