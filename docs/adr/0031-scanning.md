# ADR 0031：從掃描器掃描：主行程以 Windows 的 WIA 2.0 取得影像，驅動程式留在 Windows 的掃描服務裡；影像只在記憶體，由 worker 做成 PDF 的頁面

## 背景
- **現在掃描紙本的做法**：用 Windows 的「掃描」app 或廠商的軟體存成圖片或 PDF，再開啟，或用「從檔案建立 PDF」（B3-03，[create-pdf.md](../architecture/create-pdf.md)）。建立時圖片在 worker 中做成頁面：JPEG 原樣放入，但先拿掉 EXIF 等區段；其他格式解成像素，以 Flate 壓縮；單張最多 6,400 萬畫素。
- 這是 app 第一次直接使用硬體裝置。
- **Windows 上掃描的介面**：
  - **WIA 2.0**（Windows Image Acquisition，Vista 起）：COM 介面（`IWiaDevMgr2`、`IWiaItem2`、`IWiaTransfer`）。廠商的驅動程式在 Windows 的 WIA 服務（`stisvc`）裡執行，不在呼叫的 app 裡；影像寫進 app 給的 `IStream` 交回來。WIA 的系統對話框（`IWiaDevMgr2::GetImageDlg`）會載入廠商的介面擴充（in-process 的 COM 元件，在 app 的行程裡），並把影像寫成資料夾裡的檔案。
  - **Windows.Devices.Scanners**（WinRT，Windows 10 起）：包在 WIA 上面，有預覽；掃描的結果寫成資料夾裡的檔案（`ScanFilesToFolderAsync`）。
  - **TWAIN**：廠商的資料來源（DLL）載入 app 自己的行程；很多驅動只有 32 位元，64 位元的 app 載入不了；還要附 TWAIN 的資料來源管理員。
- **網路掃描器**（WSD、eSCL）：Windows 把它們裝成 WIA 的裝置，由 Windows 自己的驅動程式與服務連線。規格 §6「列印」已經有同樣的情況：網路印表機由作業系統處理。
- **相關的規則**：
  - ADR 0008：只有 worker 解析不受信任的資料；worker 在 AppContainer 中，沒有裝置與網路的權限。掃描的影像來自廠商的驅動程式，是不受信任的輸入。
  - ADR 0009：app 不連網。
  - 主行程已經以 `windows`、`windows-sys` crate 呼叫 Windows 的元件：CryptoAPI、DPAPI、認證管理員、系統的檔案對話框。
- **大小的上限**：IPC 的一個訊息最多 80 MiB（`MAX_FRAME_BYTES`）。插入其他檔案的頁面時，來源檔的乾淨副本由主行程保管，一份最多 64 MiB、一份文件最多 128 MiB（`MAX_SOURCE_BYTES`、`MAX_SOURCES_BYTES`）。
- **OCR**：掃描頁（CONTEXT.md）開啟時自動辨識（ADR 0015，設定 `ocr_auto`）；「另存為可搜尋的 PDF」把辨識出的文字寫成隱形的文字層（ADR 0028）。

## 選項

| 選項 | 內容 | 換來 | 付出與風險 |
|---|---|---|---|
| A. 不做 | 照現在的做法：別的 app 存成檔案，再開啟或「從檔案建立 PDF」 | 沒有新的攻擊面，也不碰硬體 | 多一個 app、多幾步；圖片檔留在磁碟上，要自己記得刪；缺口第 17 項留著 |
| **B. 主行程以 WIA 2.0 的 COM 介面取得影像，用 app 自己的對話框，影像只在記憶體（負責人 11-21 選定）** | 見「決定」 | 驅動程式不在 app 的行程裡；影像不落地；畫面與 app 一致，可以只用鍵盤 | 要自己做對話框與裝置屬性的設定；各廠商的驅動行為不一，要靠 POC 與實機 |
| C. Windows.Devices.Scanners（WinRT） | 主行程呼叫 WinRT 的 `ImageScanner` | API 比較簡單，有預覽 | 影像寫成資料夾裡的檔案，要另外保護與刪除；沒有封裝的桌面 app 能不能呼叫，要先確認；能控制的屬性比較少 |
| D. WIA 的系統對話框（`GetImageDlg`） | 用 Windows 的對話框掃描 | 幾乎不用寫畫面 | 廠商的介面擴充載入主行程；對話框的語言與樣式不是 app 的；影像寫成檔案 |
| E. TWAIN，放在另一個受限的行程 | 支援只有 TWAIN 驅動的舊掃描器 | 舊機型也能用 | 廠商的 DLL 在我們的行程裡執行，所以要另一個行程；32 與 64 位元各一份；要附 TWAIN 的資料來源管理員（新依賴）；#597 列為「不做」 |
| F. 同 B，但 WIA 在另一個受限的行程中呼叫 | 主行程只收位元組 | 主行程碰不到 WIA | 多一個行程與它的生命週期；要先確認 AppContainer 中叫得到 WIA 服務；B 的主行程本來就不解析影像，換到的不多 |

## 決定（選項 B）

### 範圍：第一版
- 入口：
  - 空白畫面與「⋯」：「從掃描器建立 PDF…」；
  - 縮圖面板的插入選單：「從掃描器插入頁面…」，插在選取的頁之後。
- 對話框（app 自己的畫面）：
  - 裝置：WIA 列出的掃描器，可以重新整理；能分辨時標示「網路裝置」（POC 確認 WIA 的屬性夠不夠分辨）。
  - 來源：平台、送紙器、雙面，只列裝置支援的。
  - 色彩：彩色、灰階、黑白。解析度：裝置支援的值，預設 300 dpi；只列一頁在上限以內的組合。紙張大小（送紙器）或平台的範圍。
  - 「掃描」：平台一次一頁，可以「再掃一頁」；送紙器一次掃完。
  - 掃到的頁以縮圖列出，可以刪除、旋轉、移動順序（鍵盤也可以）；進度以 `aria-live` 告知。
  - 完成：「建立 PDF…」（存檔的位置由 Windows 的對話框選，與「從檔案建立 PDF」相同，建立後開啟），或「插入」。取消就丟棄所有掃到的影像。
- 不做：
  - 預覽掃描、自動裁切、歪斜校正（#596）與其他影像處理；
  - 相機、雲端掃描、TWAIN；
  - 按掃描器的按鈕啟動 app：不登記 WIA 的事件，app 也不常駐。

### 誰做什麼

| 步驟 | 在哪裡 | 內容 |
|---|---|---|
| 1. 列出裝置、設定屬性、取得影像 | 主行程，專用的執行緒 | WIA 2.0：`IWiaDevMgr2` 列出裝置，`IWiaItem2` 設定來源、色彩與解析度，`IWiaTransfer::Download` 把每一頁寫進主行程給的記憶體 `IStream`。不用 WIA 的系統對話框 |
| 2. 驅動程式 | Windows 的 WIA 服務 | 廠商的驅動程式在這裡執行；app 的行程不載入廠商的 DLL（POC 確認） |
| 3. 解碼、縮圖、做成頁面 | 一個新的 worker（沙盒） | 影像是不受信任的輸入，只有 worker 解碼。縮圖由 worker 畫好再給前端，前端不直接解碼驅動程式給的資料。頁面的做法見下 |
| 4. 寫出或插入 | 主行程與 worker | 新的 PDF：照「從檔案建立 PDF」，寫進主行程交出的只能寫入的 handle。插入：做好的 PDF 就是來源檔（CONTEXT.md），走插入頁面的同一條路 |

### 影像放在哪裡、多久
- **只在記憶體**：主行程以記憶體的 `IStream` 收下每一頁，不寫暫存檔；交給 worker 時用 IPC 的位元組，與插入頁面的來源檔相同。
- **上限**：
  - 一頁的影像在 `MAX_FRAME_BYTES` 以內，確切的值由 POC 量過之後訂；
  - 一次最多 200 頁（同 `MAX_CREATE_SOURCES`），合計的上限由實作卡訂；
  - 超過上限的解析度與色彩組合，對話框不提供。
- **多久**：
  - 一頁做成 PDF 的頁面之後，原始影像就釋放；對話框關閉或取消時，全部釋放。
  - 插入時，做好的 PDF 照來源檔的規則由主行程保管（`MAX_SOURCE_BYTES`）；太大時說明要分幾次插入。
  - 當機時，掃到一半的影像就沒了（沒有寫進磁碟）。插入之後，與其他插入的頁面一樣：崩潰復原日誌放不下來源檔，當機之後那個編輯無法還原。
- 日誌不記影像的內容。

### 頁面怎麼做
- worker 把每一頁解成像素，再重新編碼：
  - 彩色與灰階預設用 JPEG（與「壓縮圖片」相同的編碼器）；對話框可以改成不失真（Flate，檔案比較大）；
  - 黑白用 Flate。
- 驅動程式給的資料裡的中繼資料（TIFF 的標籤、JPEG 的 EXIF 等）都不帶進 PDF：只放像素。PDF 也不寫 `/Info`，與「從檔案建立 PDF」相同。
- 頁面大小照掃描的解析度換算，規則與「從檔案建立 PDF」相同，所以掃 A4 就是 A4。

### 網路與權限
- **app 自己不連網**：網路掃描器與 WIA 之間的連線，是 Windows 的服務與驅動程式做的，與列印到網路印表機相同（規格 §6）。
  - app 沒有新的網路程式碼，`scripts/ci/forbidden-patterns.txt` 不變；
  - POC 用網路掃描器時，確認 app 的行程沒有任何連線；
  - 對話框與使用手冊說明：選了網路掃描器，影像經過區域網路從掃描器傳到這台電腦，由 Windows 處理。
- **worker 不碰裝置**：權限不變，沒有新的 AppContainer capability。
- **Tauri**：沒有新的外掛。新的命令（列出裝置、掃描、取消、建立、插入）加進 `capabilities/main.json`，與 app 其他自己的命令相同。
- **依賴**：沒有新的 crate。`windows` crate 加上 WIA 與 COM 的功能（例如 `Win32_Devices_ImageAcquisition`、`Win32_System_Com_StructuredStorage`），實作的 PR 照依賴變更處理。COM 的 `unsafe` 集中在一個模組。
- WIA 服務沒有執行或被停用時，說明原因。app 不啟動服務，也不改服務的設定（那要系統管理員）。

### 逾時與錯誤
- WIA 的呼叫都在專用的執行緒上，畫面不會卡住。每一頁有逾時（POC 量過之後訂），可以取消（`IWiaTransfer::Cancel`）。
- 卡紙、送紙器沒紙、裝置被拔掉、驅動程式回錯誤：說明錯誤，已經掃好的頁保留。
- worker 解不開某一頁或崩潰：那一頁說明「無法讀取這一頁的影像」，其他頁不受影響，與 worker 的其他請求相同。

### 與 OCR 的關係
- 掃出來的頁就是掃描頁（CONTEXT.md）：開啟或插入後，照 ADR 0015 的設定自動辨識，結果只在記憶體。
- 「建立 PDF」可以勾選「同時加上可搜尋的文字層」（預設不勾）：用設定的 OCR 語言辨識，照 ADR 0028 寫成隱形的文字層。新掃的 PDF 沒有簽章也沒有加密，符合 ADR 0028。
- 插入時不寫文字層；要寫的話，之後用「另存為可搜尋的 PDF」。
- 歪斜校正（#596）做好之後，辨識前的校正也適用於掃出來的頁。

### 測試
- CI 沒有掃描器：WIA 那一層放在一個介面後面，測試用假的裝置（給定的影像、錯誤、逾時、取消）。
- worker：由 `tests/corpus/generate.py` 產生 BMP、PNG、TIFF、JPEG 的掃描影像（彩色、灰階、黑白，各種解析度）。做成的頁面大小對、沒有中繼資料、沒有 `/Info`；壞掉與過大的影像是錯誤，worker 繼續服務。
- fuzz：新的 worker 請求（掃描的影像 → PDF 的頁面）加一個 fuzz 目標，或併入 `create_pdf`。
- E2E：以假的裝置走完建立與插入。
- 實機：負責人在發行前用 USB 掃描器（有網路掃描器的話也用一台）各掃一次平台與送紙器。
- `docs/security/attack-surface.md` 加上「掃描器 → 主行程 → worker」這條路。

### POC（實作前，不通過就不實作）
1. 主行程以 `windows` crate 的 WIA 2.0 介面：列出裝置，設定來源、色彩與解析度，把平台與送紙器的頁寫進記憶體的 `IStream`。
2. 掃描時列出主行程載入的模組：沒有廠商的 DLL。
3. 用網路掃描器（有的話）：app 的行程沒有任何網路連線。
4. 拔掉 USB、送紙器沒紙、取消、WIA 服務停止：都能說明錯誤，畫面不卡。
5. 量 300 與 600 dpi 的 A4，彩色、灰階、黑白：每頁的位元組、時間與記憶體，訂出每頁與每次的上限。
6. WIA 服務與驅動程式會不會在磁碟上留下暫存檔（例如服務自己的暫存資料夾）：記下來，寫進使用手冊。app 控制不了它們。

## 後果
- 換來：
  - 在 app 裡直接掃描成 PDF，或插入目前的文件；
  - 廠商的驅動程式不在 app 的行程裡；影像不落地；
  - app 仍然沒有網路程式碼；worker 的權限不變；沒有新的 crate。
- 付出：
  - 主行程第一次接觸硬體裝置的介面：多一塊 COM 程式碼、新的命令與 `capabilities/main.json` 的變更，實作的 PR 要 `needs-security-review`；
  - 只支援 WIA 驅動的掃描器：只有 TWAIN 驅動的舊機型不能用。使用手冊說明，並建議先用廠商的軟體存成檔案，再「從檔案建立 PDF」；
  - 各家驅動程式的行為不一，CI 測不到，要靠實機；
  - 一次掃很多頁時，主行程的記憶體會變大（有上限）。
- 擋不到的：
  - Windows 的 WIA 服務與廠商驅動程式本身的行為，包括網路掃描器的連線與它們自己的暫存檔；
  - 被動過手腳的驅動程式可以給出任何影像：影像只在 worker 的沙盒中解碼。
- 不改變：不連網；只有 worker 解析不受信任的資料；worker 的權限；前端拿不到路徑。
- 規格 §7「格式匯入／建立 PDF」加上從掃描器建立（中英文版）與對照清單的兩列在接受後另開文件 PR 更新（這張卡只動 `docs/adr/`）。架構文件（`create-pdf.md` 或新的 `scanning.md`）由實作的 PR 寫。
- 之後若要改變這個決定，代價是：
  - 支援 TWAIN：另寫 ADR（另一個受限的行程，32 與 64 位元）；
  - 預覽掃描、自動裁切：另開卡；
  - 按掃描器的按鈕啟動 app：要登記 WIA 的事件，牽涉「不常駐」，另寫 ADR。
