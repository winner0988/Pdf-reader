# ADR 0017：加密檔案的密碼記憶以檔案自己的密碼驗證資料為查找鍵，不寫入文件識別碼

## 狀態
已接受

（負責人於 2026-10-08 接受選項 B，「記住」預設不勾、有記住時自動使用、上限 256 項〔[#181](https://github.com/winner0988/Pdf-reader/issues/181) 的留言〕。工作卡 #181〔B2-17〕。實作卡：[#218](https://github.com/winner0988/Pdf-reader/issues/218)–[#221](https://github.com/winner0988/Pdf-reader/issues/221)。POC：`crates/pdf_worker/tests/password_key_poc.rs`。接受後取代 ADR 0006，ADR 0010 中「記住此文件的密碼」一例不再適用。）

## 背景
- ADR 0006：記住的密碼交給系統憑證庫，**查找鍵是文件識別碼**。CONTEXT.md「文件識別碼」：識別碼寫進 PDF 的中繼資料，ADR 0010 規定只在使用者明確操作時寫入，已簽章與唯讀的文件拒絕，加密文件要先有權限密碼。
- 這個設計對加密檔案行不通：
  1. **讀不到**：要找密碼的時候，檔案還打不開。PDF 規格規定加密文件除了 `/ID` 與 `/Encrypt` 字典內的字串之外，所有字串與串流都加密，`/Info` 與 XMP 中繼資料（預設）也是，解密之前讀不到 app 寫進去的識別碼；
  2. **寫不進去**：ADR 0010 擋下已簽章、唯讀、網路磁碟的文件，而加密文件常常同時有簽章（對帳單、合約），正是最需要記住密碼的檔案；
  3. **為了記住密碼而改使用者的檔案**：修改時間、內容雜湊與信任（ADR 0002）都會變；加密檔要以權限密碼重新加密才能寫入。
- ADR 0008：主行程不解析 PDF，只有 worker 讀得懂檔案；ADR 0012：每份文件有自己的 worker。密碼已經只送到那份文件的 worker（[encryption.md](../architecture/encryption.md)）；#94 的決定讓「復原以密碼開啟的文件」要再輸入一次密碼，因為密碼不保留。

### POC
`password_key_poc.rs`，用語料的兩個加密樣本（AES-256〔R6〕、RC4 40-bit〔R2〕）與 `multi-page-10.pdf`：
1. **不給密碼就讀得到**：MuPDF 回報需要密碼時，`/Encrypt` 字典的 `/R`、`/U` 與 trailer 的 `/ID` 都已經可以讀（R6 的 `/U` 是 48 位元組：雜湊、驗證鹽、金鑰鹽；R2 是 32 位元組；`/ID` 第一段 16 位元組）。這幾個值依規格不加密，也不需要寫進檔案。
2. **app 自己的存檔不改變它**：以密碼開啟、旋轉一頁、存檔（保留加密）之後，兩個樣本的 `/R`、`/U` 與 `/ID` 第一段都和原來一樣，所以記住的密碼存檔後仍然找得到。
3. **重新加密就會變**：同一份文件以同一個密碼加密兩次，`/U` 不同（鹽值是隨機的）；以另一個密碼加密，`/U` 不同，但 **`/ID` 第一段和前兩份一樣**（來源文件有 `/ID` 時，MuPDF 會保留它）。也就是說 `/ID` 認得的是「文件」，不是「這個密碼」：以它為鍵，會把舊密碼拿去開已經換了密碼的檔案；以 `/U` 為鍵則不會。

## 選項

| 選項 | 內容 | 代價 |
|---|---|---|
| A. 文件識別碼寫進 PDF（ADR 0006、0010 的原案） | 使用者記住密碼時，把 app 產生的識別碼寫進文件中繼資料，之後以它查找 | 上面三個問題：開檔前讀不到、簽章與唯讀的檔案做不到、要改使用者的檔案 |
| **B. `/Encrypt` 的 `/U`（建議）** | 以使用者密碼驗證資料（連同它的鹽值）的雜湊為鍵；它在未加密的 `/Encrypt` 字典中，開檔前就讀得到 | 文件被重新加密（換密碼、被別的軟體重新加密）後會再問一次，而這正是記住的密碼已經不一定對的時候；同一個密碼用在很多檔案時，每個檔案要各記一次（鹽值隨機）；鍵由 worker 回報（見「決定」的信任規則） |
| C. trailer 的 `/ID` 第一段 | 檔案的永久識別碼，未加密，存檔後不變 | 不綁定密碼（POC 3）：換了密碼 `/ID` 不變，會拿舊密碼去試；有些檔案沒有 `/ID`，或所有檔案共用同一個假值 |
| D. 不以檔案為鍵 | 憑證庫只存密碼，開加密檔時全部拿去試 | 每份加密檔的 worker 都會收到**所有**記住的密碼，被攻陷的 worker 一次拿走全部，違背 ADR 0012 隔離的目的；試的次數隨清單增長（R6 的驗證刻意做得慢）；也沒有「單一文件」可以忘記 |
| E. 檔案路徑 | 以完整路徑為鍵 | ADR 0006 已排除：搬移、改名就失效；路徑本身是私人資料，不該出現在憑證庫的條目名稱 |

## 決定
採用 **B**：以檔案自己的 `/Encrypt` 字典中的使用者密碼驗證資料為查找鍵，取代 ADR 0006 的「文件識別碼」。其餘沿用 ADR 0006：交給作業系統的憑證庫，app 自己不存密碼。**記住密碼不寫入、也不修改任何 PDF。**

### 鍵
- worker 在回報「需要密碼」時一併回報鍵：`SHA-256("pdf-reader/password-key/v1" ‖ R ‖ /U 的前 32 位元組〔R5 以上為 48 位元組〕)`，32 位元組。這幾個位元組就是 MuPDF 用來驗證密碼的資料。
- `/U` 不存在、不是字串或長度不足（不是標準密碼安全處理程序）時沒有鍵，那份文件就不能記住密碼。
- 鍵只用來查找，不是祕密，也不要求不可碰撞：撞到的後果只是拿一個不對的密碼去試，然後問使用者。
- 以使用者密碼或擁有者密碼開啟都一樣：記住的是使用者輸入的那一個。

### 憑證庫的條目
在主行程的 `src-tauri/src/credentials.rs`，呼叫 Windows 的 `CredWriteW`、`CredReadW`、`CredDeleteW`、`CredEnumerateW`。`windows-sys` 已是依賴，只多一個 feature，不新增套件；`unsafe` 限於這個模組（比照 `opener.rs`、`saving.rs`）。worker 不連結它：沙盒碰不到憑證庫，也不該看到別份文件的密碼。

- 類型 `CRED_TYPE_GENERIC`；`TargetName` = `PdfReader/password/v1/<64 位十六進位的鍵>`；`UserName` = `PDF Reader`；`CredentialBlob` = 密碼的 UTF-8 位元組（`MAX_PASSWORD_BYTES` 是 1,024，小於憑證庫的 2,560 位元組上限）；`Comment` 說明這是什麼；`Persist` = `CRED_PERSIST_LOCAL_MACHINE`（跨登出與重開機保留，不隨網域設定檔漫遊）。
- **條目裡沒有檔名、路徑或任何文件內容。** Windows 的認證管理員看得到這些條目，也可以從那裡刪除。
- 最多 256 項；滿了就不再記，並請使用者先到設定忘記一些，不會默默覆蓋。
- 憑證庫出錯（服務停用、原則禁止）不阻擋開檔：文件照常以輸入的密碼開啟，並說明沒有記住。

### 使用者看到的
- 密碼對話框多一個「記住這份文件的密碼（存在 Windows 認證管理員）」，**預設不勾**：與 ADR 0010 同一個原則，只在使用者明確要求時留下東西。密碼打開了文件之後才存，輸入錯誤的密碼不存。
- 有記住的文件：開檔時自動使用，不出現對話框；文件的提示列說明「已用記住的密碼開啟」並有「忘記」；「⋯」選單有「忘記這份文件的密碼」。
- 記住的密碼開不了（`/U` 相同卻不對：憑證庫的資料被改過，或 worker 回報了不實的鍵）：照常問使用者，**不刪除記錄**，避免被攻陷的 worker 藉此刪別份文件的記錄；使用者輸入新密碼並勾選「記住」時覆蓋它。
- 設定頁顯示「已記住 N 份文件的密碼」與「全部忘記」（以 `CredEnumerateW` 依前綴列舉再逐一刪除）。**沒有逐項列表**，因為條目裡沒有檔名可以顯示；單一文件的忘記從該文件的「⋯」選單做。

### 信任規則（鍵來自不受信任的 worker）
1. 鍵是固定 32 位元組，主行程只把它當**不透明的查找字串**，不信任它代表什麼；
2. 記住的密碼只送給**回報那把鍵的那份文件的 worker**（同一個分頁、依 ADR 0012 新開的那個 worker），不給別份文件，也不給前端；
3. 每次開檔最多**自動嘗試一次**，失敗就問使用者，不重試；
4. 前端拿不到鍵與記住的密碼：命令只有 `unlock_tab`（多一個 `remember`）、`forget_password`（以分頁代號）、`forget_all_passwords` 與取得項數；
5. **剩下的風險（接受）**：持有某份加密檔案副本的人知道它的 `/U`，可以做一個 `/U` 相同的惡意 PDF。使用者若記住過那份檔案的密碼、又開了這個惡意檔，那份檔案的密碼會送到它的 worker。worker 在沙盒中沒有網路也沒有檔案權限（ADR 0008），攻擊者還要有能攻陷 MuPDF 的漏洞，並等使用者把 worker 產生的東西（存檔、匯出）交給他，才拿得到密碼；密碼本身沒有檔案可用，因為 worker 碰不到那份檔案。

### 與其他功能
- **存檔（B2-02）**：保留加密時 `/U` 不變（POC 2），記住的密碼存檔後仍然找得到；
- **復原（#94）與 worker 崩潰後重開**：記住密碼的文件由主行程以同一把鍵取回密碼，不再要求輸入；沒記住的維持 #94 的決定（再問一次，不保留）；
- **加密副本（B2-15）**：新檔案有新的 `/U`，不會套用任何記錄；使用者開啟它時可以勾「記住」；
- **隱私匯出（B2-03）**：副本沒有加密，或有新的 `/U`，不繼承記錄，與原本「不繼承密碼記憶」的說明一致；
- **文件識別碼（ADR 0010）**：與記住密碼脫鉤，只剩機敏標記（ADR 0004）使用。

## 後果
- 換來：
  - 記住密碼**不改使用者的任何檔案**；已簽章、唯讀、網路磁碟上的加密檔案也能記住；
  - 搬移、改名、複製檔案都不影響（鍵在檔案裡）；
  - 密碼改了（`/U` 變了）就自動失效，不會拿舊密碼去試；
  - 沒有新的依賴；worker 只多回報一個固定長度的值。
- 付出：
  - 同一個密碼用在很多檔案要各記一次（每個檔案的鹽值不同）；這是為了不讓任何 worker 看到不屬於它的密碼（選項 D）；
  - 憑證庫成為信任邊界（ADR 0006 已記錄，SECURITY.md 也有）：同一個 Windows 帳號的任何程式都讀得到這些密碼；
  - 被別的軟體改過密碼的檔案，舊條目會留在憑證庫（沒有檔名，無從判斷），只能靠「全部忘記」與 256 項的上限；
  - IPC 多一個欄位（worker 回報的鍵）、三個命令與一個命令參數，capability 與 `check-security-config.mjs` 的允許清單要跟著改。
- 之後若要改變這個決定，代價是：
  - 條目名稱含版本（`v1`）：換鍵的算法就開 `v2`，舊條目不再被找到，使用者再輸入一次密碼；
  - 若要「同一個密碼自動套用到新檔案」，主行程得自己驗證密碼而不把密碼交給 worker，與 ADR 0008 衝突，要另寫 ADR。
- 接受時要同步：ADR 0006 改為「已取代（由 ADR 0017 取代）」；CONTEXT.md「文件識別碼」改為只有機敏標記依附，並說明密碼記憶的鍵；規格書 §3（中英文）的「密碼記憶」一段；`docs/backlog/README.md` 的第三批候選；[encryption.md](../architecture/encryption.md) 的「尚未處理」。
- 實作卡要涵蓋：worker 的鍵與 IPC（含驗證與 fuzz 種子）、`credentials.rs`（在 CI 的 Windows runner 上對真正的憑證庫測試，測試用的條目要清掉）、開檔、復原與崩潰重開的流程、對話框、設定頁、E2E。
- **需要負責人決定**：選項 B；「記住」預設不勾（規格 §3 寫「使用者仍可針對單一文件選擇不記住密碼」，可讀成預設記住，本 ADR 建議預設不勾）；有記住時自動使用，還是每次按一下確認；256 項的上限。
