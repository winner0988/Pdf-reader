## 背景
- repo 是公開的（ADR 0011），介面只有繁體中文。AGENTS.md「語言慣例」：介面文字集中管理，之後要支援多語系。
- 現在的文字在哪裡（2026-11-21 的 main）：

  | 地方 | 內容 | 量 |
  |---|---|---|
  | `src/i18n/zh-TW.ts` | WebView 的全部文字。151 個檔案 import 它（91 個是程式、60 個是測試），E2E 的 spec 也是 | 1,715 行 |
  | `src-tauri/src/strings.rs` | 主行程自己顯示的文字：系統對話框的標題與篩選、視窗標題、通知區域的圖示與選單、批次處理完成的訊息、缺少 WebView2 的訊息 | 382 行（不含測試） |
  | 同上：寫進檔案的字 | 副本的預設檔名（「（隱私匯出）」等）、批次處理報告的檔名與內容、註解摘要、文字比較的結果、匯出純文字的「（此頁沒有文字層）」、可見簽章方框的「數位簽署：」「日期：」「原因：」 | |
  | `pdf_worker` | 頁碼的兩種格式「第 n 頁」「第 n 頁／共 N 頁」（`page_marks.rs`），寫進頁面 | 2 行 |
  | 安裝檔 | 精靈已經依 Windows 的語言顯示繁體中文或英文，都不是時用第一個（繁體中文）（[packaging.md](../architecture/packaging.md)）。`installer-hooks.nsh` 的三段文字只有繁體中文：缺少 WebView2 的提示、寫進登錄的類型名稱「PDF 文件」與 app 的說明 | 3 段 |
  | `index.html` | `<html lang="zh-Hant-TW">` | |

- **錯誤已經只回代碼**：worker 與主行程回 `ErrorCode`，前端以 `strings.error.messages`（`satisfies Record<ErrorCode, string>`）轉成文字。`IpcError.message` 是給開發者看的英文，不顯示。
- 掃描頁的自動辨識語言「依介面的語言」：`ocr_languages.rs` 的 `AUTOMATIC` 先選 `chi_tra`，再選任何一種。
- 設定存在 `settings.json`（`settings.rs`）：`deny_unknown_fields`，新的欄位以 `serde(default)` 讓舊檔照樣讀得進來。
- 使用手冊（`docs/user/`）與 README 只有繁體中文。`THIRD_PARTY_LICENSES.txt`（「關於」→「第三方元件授權」）已經是英文在前的雙語，授權全文是原文。
- 第四批計畫 D3 的估計：約 2,000 行字串，加上語言設定、Rust 端的字串與測試。

## 選項

### 1. 做不做、怎麼做

| 選項 | 內容 | 換來 | 付出與風險 |
|---|---|---|---|
| A. 不做 | 維持只有繁體中文 | 不必維護第二份字串 | 看不懂中文的人用不了；公開的 repo、Acrobat Pro 替代品的方向都受限 |
| **B. 自己的字串表，每種語言一個檔案（負責人 11-21 選定）** | `src/i18n/en.ts` 與 `zh-TW.ts` 同一個型別；Rust 端每種語言一份同一個型別的結構；啟動時決定語言 | 不加依賴；少了字、參數不對，`pnpm typecheck` 與 `cargo build` 就失敗；現有的元件只改 import 的路徑 | 英文的單複數要在字串函式裡自己寫；翻譯的人要看得懂 TypeScript 與 Rust |
| C. i18n 函式庫（前端 i18next 或 FormatJS，Rust 端 fluent） | 字串放在 JSON 或 FTL 檔，執行時解析訊息格式 | 單複數、ICU 格式現成；翻譯工具認得這些檔案 | 新的 npm 與 Cargo 依賴（供應鏈，要 `needs-security-review`）；鍵與參數要另外產生型別才檢查得到；執行時多一個解析器 |

### 2. 什麼時候換語言

| 選項 | 換來 | 付出與風險 |
|---|---|---|
| **啟動時決定，改了下次啟動生效（負責人 11-21 選定）** | 一次執行只有一種語言：畫面、主行程的對話框、通知區域的選單、寫出的檔名都一致；模組載入時就選定字串表，現有的寫法不用改 | 改語言要重新啟動 app |
| 立即切換 | 不必重新啟動 | 用到字串的地方都要能重新計算，包括模組層級的常數；主行程已經建立的選單、進行中的批次也要換字；容易一半中文一半英文 |

### 3. Windows 不是中文也不是英文時

| 選項 | 換來 | 付出與風險 |
|---|---|---|
| **英文（負責人 11-21 選定）** | 其他語言的使用者讀英文的機會比讀中文大 | 安裝檔要跟著改：這些 Windows 原本看到繁體中文的精靈，之後看到英文 |
| 繁體中文（現在安裝檔的做法） | 不用改安裝檔 | 例如日文或德文的 Windows 會看到繁體中文 |

### 4. 寫進檔案的字（檔名、報告、頁碼、簽章方框）

| 選項 | 換來 | 付出與風險 |
|---|---|---|
| **跟著寫出當時的介面語言（負責人 11-21 選定）** | 規則簡單，對話框的預覽就是實際寫入的字；與 Acrobat 相同（簽章外觀的標籤跟著介面語言） | 用英文介面處理中文文件時，頁碼是英文；要中文可以用頁碼的「自訂」格式自己寫 |
| 一律繁體中文 | 不用改 | 英文介面的使用者拿到中文的檔名與頁碼 |
| 每個對話框另選語言 | 最有彈性 | 每個寫檔的對話框都多一個選項；第一版不需要 |

## 決定（選項 B）

選的是：1 的 B、2 的「啟動時決定」、3 的「英文」、4 的「跟著介面語言」。

### 語言怎麼選
- 設定新增「介面語言」：`system`（預設）、`zh-TW`、`en`。存在 `settings.json` 的 `language`；舊檔沒有這個欄位時是 `system`。
- `system`：主行程讀 Windows 的顯示語言（使用者偏好的介面語言清單的第一個，`GetUserPreferredUILanguages`）：
  - 中文，任何地區、包括簡體 → 繁體中文。沒有簡體中文的字串表時，中文的使用者讀繁體比讀英文容易；
  - 英文與其他語言 → 英文。
- 設定頁的這一項：標題寫兩種語言（「介面語言 Language」），選項用各自的語言（「繁體中文」「English」「跟隨 Windows（目前：English）」），選錯了也找得回來。
- 改了之後說明「重新啟動 PDF Reader 後生效」，不自動重新啟動。

### 語言在哪裡決定
- **主行程在啟動時決定一次**，整次執行都用它：
  - 建立視窗時交給 WebView（網址的查詢參數，或 Tauri 的初始化腳本，實作卡選一種）。前端的 `src/i18n/index.ts` 在模組載入時同步選出字串表，並設定 `<html lang>`（`zh-Hant-TW` 或 `en`）；不認得的值用繁體中文。
  - 主行程自己的文字用同一個語言。缺少 WebView2 時沒有畫面，所以語言只能由主行程決定。
- 元件改從 `@/i18n` import `strings`，用法不變。
- WebView2 自己的介面（例如文字框的右鍵選單）跟著 Windows 的語言。實作卡檢查 app 有沒有顯示這些；有的話，以 WebView2 的語言選項啟動，讓它與 app 一致。

### 字串表
- **前端**：`src/i18n/zh-TW.ts`（現有）與 `src/i18n/en.ts`。`en.ts` 宣告為 `Strings`，也就是 `zh-TW.ts` 的型別：少了鍵、多了鍵、函式的參數不同，`pnpm typecheck` 都會失敗。
- 英文的單複數在字串函式裡處理，例如 `` (n) => (n === 1 ? "1 file" : `${n} files`) ``。不引入函式庫。
- **主行程**：`strings.rs` 改成每種語言一份同一個型別的結構，文字是 `&'static str`、帶參數的是函式；少一個欄位就編譯不過。呼叫的地方取目前語言的那一份。
- **worker 不放介面語言的文字**。頁碼的兩種格式是現在唯一的例外：實作卡把字移到主行程，由編輯指令帶給 worker（例如數字前、中、後的三段字），worker 只填數字。
- `IpcError.message` 維持給開發者看的英文，不顯示，也不翻譯。新的錯誤一律加 `ErrorCode`，文字只寫在字串表。
- **英文的用語**：CONTEXT.md 的每一個詞都有固定的英文（例如機敏文件 sensitive document、安全遮蔽 redaction、文件識別碼 document ID），寫在新的 `docs/ux/glossary-en.md`。`docs/ux/screen-map.md` 第 8 節仍是繁體中文用字的依據；英文以 `en.ts` 為準。

### 寫進檔案的字
- 跟著寫出當時的介面語言：
  - 副本的預設檔名（例如 `<檔名> (privacy export).pdf`）、批次處理報告的檔名與內容、註解摘要、文字比較的結果、匯出純文字的「此頁沒有文字層」；
  - 寫進 PDF 的字：可見簽章方框的標籤、頁碼的兩種格式。對話框的預覽顯示實際寫入的字。
- 已經寫出的檔案不會因為改語言而改變。

### 其他
- **掃描頁的自動辨識語言**：照 `AUTOMATIC` 原本的意思跟著介面語言，英文介面先選 `eng`，繁體中文介面先選 `chi_tra`。設定裡選了語言就照設定。
- **安裝檔**：
  - 精靈照舊依 Windows 的語言，規則與 app 相同：中文的 Windows 看到繁體中文，其他看到英文。做法是語言清單改成英文在前（都不是時用第一個）；簡體中文的 Windows 實際看到哪一種，實作卡照 NSIS 選語言的方式確認。CI（`installer.yml`）檢查的順序跟著改。
  - `installer-hooks.nsh` 的三段文字改成兩種語言的 `LangString`。寫進登錄的類型名稱與說明用安裝當時的語言，之後改 app 的語言不會改它們。
  - 安裝檔不寫 app 的語言設定。
- **「關於」**：對話框的文字照字串表。`THIRD_PARTY_LICENSES.txt` 不變。
- **使用手冊、README**：維持繁體中文（#600 的「不做」）。app 裡沒有連到手冊的地方，不受影響。
- 鍵盤快捷鍵不變；命令面板的別名，每種語言各一份。

### 確保不漏
1. **型別**：`en.ts` 是 `Strings`；`strings.rs` 每種語言是同一個結構。少了就無法建置。
2. **沒翻到的字**：單元測試走過 `en` 的每一個值（函式用範例參數呼叫）：不能有漢字（允許清單：語言選項的「繁體中文」與雙語的標題），不能是空字串（繁體中文那份本來就是空字串的除外，例如 `cancelled`）。Rust 的英文結構做同樣的檢查。
3. **寫死在元件裡的字**：ESLint 規則：`src/` 底下、`src/i18n/` 與測試以外的字串字面值不能有漢字。Rust 端（主行程與 worker 不是測試的程式碼）怎麼檢查，實作卡決定。
4. **版面**：英文通常比中文長。E2E 加一個以英文啟動的 spec（名稱取自 `en.ts`），走過主要畫面並跑 axe，在 CI 的視窗大小下看按鈕與對話框沒有被截斷。
5. 既有的測試仍用繁體中文，不必改。

### 第一版的範圍
- 做：WebView 的所有文字、主行程的文字、寫出的檔名與報告、寫進 PDF 的兩種字、安裝檔的三段文字、`<html lang>`、設定頁的語言選項、上面的檢查。
- 不做：翻譯使用手冊與 README、其他語言（包括簡體中文）、立即切換、每個對話框另選寫進檔案的語言。

### 之後加更多語言
- 一種語言一張卡：加 `src/i18n/<BCP 47 標籤>.ts`（同一個型別）、Rust 結構多一份、設定的選項、`system` 的對應規則、安裝檔的 NSIS 語言（Tauri 有的才行）、用語表。
- 簡體中文要另外決定：從繁體轉換（例如 OpenCC）還是另外翻譯；轉換的結果也要有人看過。
- 由右到左的語言（阿拉伯文、希伯來文）要另寫 ADR：版面要鏡像，文字方塊的排版也還不支援這些文字（`textNotSupported`）。

## 後果
- 換來：
  - 看不懂中文的人也能用；
  - 之後加語言只是加檔案，不改架構；
  - 不加任何依賴（讀 Windows 的語言要 `windows-sys` 的 `Win32_Globalization`，是既有依賴的新功能）。
- 付出：
  - 每個新功能、每一次改字，都要寫兩種語言；
  - 英文的品質要有人看：第一版發行前，由負責人或英文的使用者看過主要畫面；
  - 改語言要重新啟動；
  - 設定檔多一個欄位：回到舊版時，舊版不認得它（`deny_unknown_fields`），設定回到預設，與之前加 OCR 設定時相同；
  - 不是中文也不是英文的 Windows，安裝精靈從繁體中文變成英文。
- 風險：英文字串比較長，可能把按鈕與對話框撐破；靠 E2E 與看過畫面發現。
- 不改變：不連網、零遙測、worker 的權限、IPC 的錯誤代碼；前端仍然拿不到路徑。
- 實作的 PR 會動到 `settings.json` 的結構、`index.html`、安裝檔的腳本、CI 的 `installer.yml` 與依賴的功能：要 `needs-security-review`。
- 規格（新增「介面語言」一條，中英文版）在接受後另開文件 PR 更新（這張卡只動 `docs/adr/`）。[packaging.md](../architecture/packaging.md) 的「安裝程式的語言」與 AGENTS.md「語言慣例」（介面文字有兩種語言）寫的是現在的做法，由實作的 PR 一起改。
- 之後若要改變這個決定，代價是：
  - 改成立即切換：模組層級用到字串的地方要改成每次取用，主行程的選單要能重建；
  - 改用 i18n 函式庫：兩份字串表轉成它的格式，鍵可以照用。
