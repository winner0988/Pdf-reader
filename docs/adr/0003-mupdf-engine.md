# ADR 0003：選定 MuPDF 作為 PDF 處理引擎

## 狀態
已接受

## 背景
需要在 pdf-lib、PDFium、MuPDF 三者間選定貫穿全專案的底層 PDF 處理引擎。專案已定案需要表單腳本沙盒（見 ADR 0001），且後端使用 Tauri/Rust。pdf-lib 是純 JS 函式庫，不具渲染能力，也無法執行 PDF 內嵌腳本；PDFium 渲染精確，但編輯能力有限，通常需搭配另一顆函式庫處理編輯，等於維護兩套引擎。

## 決定
採用 MuPDF 作為唯一的底層引擎，涵蓋渲染、編輯與表單腳本沙盒三項需求。有現成的 Rust 綁定可與 Tauri 後端整合。授權為 AGPLv3（或另購商業授權）；因本專案僅供個人使用、不對外散布，此授權條款不構成限制。

## 後果
- 換來：單一引擎涵蓋渲染、編輯、表單腳本三項核心需求，不需要跨引擎同步狀態。
- 付出：渲染精確度可能不如 PDFium（Chrome 採用的引擎）；未來若考慮對外散布或商業化，需要重新評估授權。
- 之後若要更換引擎，等同重寫渲染、編輯與表單腳本三層邏輯，成本很高。
