# ADR 0010：文件識別碼寫入 PDF 的安全限制

## 狀態
已接受

（負責人於 2026-09-30 選擇選項 C，搭配 A 的增量更新〔DEC-03，#103〕。MVP 不實作；機敏標記與密碼記憶依此實作。）

## 背景
CONTEXT.md 定義文件識別碼要寫進 PDF 自身的中繼資料（ADR 0004、ADR 0006 都依賴它）。但寫入識別碼等於修改 PDF：

- **已簽章文件**：簽章後再修改會讓驗證器顯示「簽章後已被修改」；若文件設定了禁止修改（DocMDP P=1），任何寫入都會讓簽章失效。
- **加密文件**：沒有權限密碼就無法正確寫入。
- **唯讀檔案、唯讀資料夾、網路磁碟**：可能無法寫入，或寫入時觸發其他同步程式。
- **與信任機制互相干擾**：信任以內容雜湊為準（ADR 0002）。寫入識別碼會改變雜湊，讓使用者剛給的信任立刻失效。
- **檔案修改時間改變**：使用者可能不預期「只是標記一下」就讓檔案變成已修改。

## 選項
- **A. 一律寫入，但採增量更新（incremental update）**，遇到已簽章、加密、唯讀文件就跳過並改存本機資料庫。
- **B. 永不寫入 PDF**，改在本機 SQLite 記錄，以 NTFS 檔案識別碼加內容雜湊追蹤搬移與改名（只在同一磁碟區內有效）。
- **C. 只在使用者明確操作時寫入**（例如按下「標記為機敏」），寫入前先檢查簽章、加密、唯讀狀態並顯示會發生什麼，由使用者確認。

## 建議
以 **C** 為主、搭配 A 的增量更新：只在明確操作時寫入；已簽章文件預設拒絕並說明原因；加密文件需先輸入權限密碼；唯讀檔案拒絕。信任雜湊的計算方式需一併調整，避免寫入識別碼讓信任失效（待 POC 確認可行作法）。

## 決定
採用 **C，搭配 A 的增量更新**：文件識別碼只在使用者明確操作時寫入 PDF。

- **何時寫入**：只在使用者明確要求、而且需要識別碼的動作時，例如「標記為機敏」（ADR 0004）、「記住此文件的密碼」（ADR 0006）。
  - 開檔、閱讀、一般存檔（ADR 0013）都**不寫入**。
- **寫入前**先檢查文件，說明會發生什麼，由使用者確認：
  - 已簽章文件：**預設拒絕**，並說明原因（寫入會讓驗證器顯示「簽章後已被修改」；DocMDP P=1 的文件會讓簽章失效）；
  - 加密文件：需要先輸入權限密碼；
  - 唯讀檔案、無法寫入的位置：拒絕，並說明原因；
  - 其他文件：說明「會修改這個檔案，修改時間也會改變」。
- **怎麼寫入**：以增量更新附加在檔案結尾，不重寫原有內容；寫檔依 ADR 0013 的存檔流程（暫存檔完整寫好才取代原檔，失敗時原檔不變）。
- **信任（ADR 0002）**：寫入識別碼會改變內容雜湊。實作機敏標記前，以 POC 決定如何避免使用者剛給的信任因此失效，並補進本 ADR。

## 後果
- 換來：
  - 開檔、閱讀與一般存檔永遠不因識別碼而改動使用者的檔案；
  - 識別碼跟著檔案本身，搬移、改名都不失效。
- 付出：
  - 已簽章、唯讀的文件不能標記為機敏或記住密碼；
  - 寫入時檔案的修改時間與內容雜湊會改變。
- 已同步：CONTEXT.md「文件識別碼」條目與規格書 §3（中英文）。
- 實作時要針對已簽章（`benign/signed*.pdf`）、加密（`benign/encrypted-*.pdf`）與唯讀的檔案補測試。
