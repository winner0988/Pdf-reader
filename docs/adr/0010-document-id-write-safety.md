# ADR 0010：文件識別碼寫入 PDF 的安全限制

## 狀態
提議中（MVP 不實作；在實作機敏標記或密碼記憶之前必須定案）

## 背景
CONTEXT.md 定義文件識別碼要寫進 PDF 自身的中繼資料（ADR 0004、ADR 0006 都依賴它）。但寫入識別碼等於修改 PDF：

- **已簽章文件**：簽章後再修改會讓驗證器顯示「簽章後已被修改」；若文件設定了禁止修改（DocMDP P=1），任何寫入都會讓簽章失效。
- **加密文件**：沒有權限密碼就無法正確寫入。
- **唯讀檔案、唯讀資料夾、網路磁碟**：可能無法寫入，或寫入時觸發其他同步程式。
- **與信任機制互相干擾**：信任以內容雜湊為準（ADR 0002）。寫入識別碼會改變雜湊，讓使用者剛給的信任立刻失效。
- **檔案修改時間改變**：使用者可能不預期「只是標記一下」就讓檔案變成已修改。

## 選項
- **A. 一律寫入，但採增量更新（incremental update）**，遇到已簽章、加密、唯讀文件就跳過並改存本機資料庫。
- **B. 永不寫入 PDF**，改在本機 SQLite 記錄，以 NTFS 檔案識別碼加內容雜湊追蹤搬移與改名（只在同一磁碟區內有效）。
- **C. 只在使用者明確操作時寫入**（例如按下「標記為機敏」），寫入前先檢查簽章、加密、唯讀狀態並顯示會發生什麼，由使用者確認。

## 建議
以 **C** 為主、搭配 A 的增量更新：只在明確操作時寫入；已簽章文件預設拒絕並說明原因；加密文件需先輸入權限密碼；唯讀檔案拒絕。信任雜湊的計算方式需一併調整，避免寫入識別碼讓信任失效（待 POC 確認可行作法）。
