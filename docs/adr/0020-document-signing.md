# ADR 0020：簽署文件時私鑰只在主行程，以 Windows CryptoAPI 簽署；憑證來自 .pfx 或 Windows 憑證存放區

## 狀態
已接受

（負責人於 2026-10-21 接受選項 B：`.pfx`／`.p12` 與 Windows 憑證存放區，含自然人憑證等智慧卡〔[#237 的留言](https://github.com/winner0988/Pdf-reader/issues/237#issuecomment-6303085444)〕。工作卡 [#237](https://github.com/winner0988/Pdf-reader/issues/237)〔B3-06〕。實作前由實作 agent 做下面的 POC。）

## 背景
- 規格 §3「本地數位簽章」：載入本機的憑證檔（`.pfx`、`.p12`）簽署文件，完全離線。驗證已由 ADR 0014 做到（在 worker 中以 Windows CryptoAPI 離線驗證）。
- 簽署牽涉最敏感的兩樣東西：**私鑰**與**密碼**。
- worker 解析不受信任的 PDF（ADR 0008）：它一旦被惡意 PDF 控制，碰得到的東西都要當成已外洩。所以私鑰與密碼不能進 worker。前端（WebView）也不能拿到私鑰。
- 台灣常用的簽章憑證（自然人憑證、工商憑證）在智慧卡上：私鑰拿不出來，只能透過 Windows 的憑證存放區與卡片的驅動程式簽署，PIN 由 Windows 或驅動程式自己的視窗詢問。
- 不連網（ADR 0009）：不查 OCSP／CRL、不下載中繼憑證（AIA）、不向時間戳記伺服器（TSA）要時間。
- ADR 0013：存檔時主行程交出暫存檔的寫入 handle；已簽章的文件以增量更新存檔。worker 已經會做增量更新（寫入文件識別碼，ADR 0010）。
- 主行程已依賴 `windows-sys`（WinHTTP、憑證管理員等）；簽署要多開 `Win32_Security_Cryptography` 這個功能，不新增套件。

## 選項

| 選項 | 內容 | 代價 |
|---|---|---|
| A. 只支援 `.pfx`／`.p12`（工作卡的草案） | 主行程以 `PFXImportCertStore` 匯入（私鑰不落地），簽完就釋放 | 只照字面做到規格；智慧卡上的憑證不能用 |
| **B. `.pfx` 加上 Windows 憑證存放區（建議）** | A，再加上從「目前使用者的個人存放區」選一張有私鑰、可用於數位簽章的憑證（含智慧卡）；兩種來源走同一段簽署程式碼 | 多一個選憑證的畫面；智慧卡 CI 測不到，要負責人用真的卡試一次 |
| C. RustCrypto 自己簽（`p12`、`cms`、`rsa`） | 純 Rust | 新增十幾個密碼學套件；`rsa` 有 RUSTSEC-2023-0071（**私鑰運算**的時序側通道，簽署正好受影響）；智慧卡做不到 |
| D. 在 worker 裡簽 | 與驗證同一個地方 | 私鑰或密碼進入處理不受信任 PDF 的行程：排除 |

## 決定（選項 B）

### 誰做什麼

| 步驟 | 在哪裡 | 內容 |
|---|---|---|
| 1. 選憑證 | 主行程與前端 | `.pfx`：主行程以系統對話框選檔（前端拿不到路徑），密碼由前端的對話框經**一次命令**送到主行程。存放區：主行程列出可用的憑證（主旨、簽發者、到期日、用途），前端只拿到清單與不透明的代號 |
| 2. 準備 | 該文件的 worker | 以增量更新加上簽章欄位、外觀（可見或不可見）與簽章字典（`/Filter /Adobe.PPKLite`、`/SubFilter /adbe.pkcs7.detached`、`/M`、`/Reason`、`/Name`），`/ByteRange` 與 `/Contents` 先預留；寫進主行程交出的暫存檔 handle（ADR 0013），回報 `/Contents` 的位移與長度 |
| 3. 簽署 | 主行程 | 檢查 worker 回報的位移（在檔案範圍內，那一段是 `<` 與 `>` 之間的十六進位零）；只讀這個自己建立的暫存檔，不解析 PDF；對 `/Contents` 前後兩段做 CMS 分離式簽章，填進 `/Contents` |
| 4. 驗證 | 新的 worker | 以 ADR 0014 的驗證器開啟簽好的暫存檔：必須「簽章有效」而且涵蓋整個檔案，才交給使用者 |
| 5. 完成 | 主行程 | 照 ADR 0013 寫到目的地；預設**另存新檔**（`…（已簽署）.pdf`），不取代原檔 |

### 私鑰與密碼
- 私鑰**永遠不出主行程，也不寫到磁碟**：`.pfx` 以 `PFXImportCertStore` 匯入，帶 `PKCS12_NO_PERSIST_KEY`（私鑰只在記憶體）、不帶 `CRYPT_EXPORTABLE`；簽完關閉存放區、釋放金鑰。
- 密碼：與加密（B2-15）的密碼同一個型別與規則；只經過一次命令，用完清除（`zeroize`）；不寫進日誌、錯誤訊息、復原日誌、設定或報告。錯誤只說「密碼不對，或檔案不是憑證」。
- 存放區的憑證：私鑰留在 Windows 或卡片裡；PIN 由 Windows 或卡片驅動程式的視窗詢問，app 不經手。
- app 不記住憑證檔的位置與密碼（不用 ADR 0017 的密碼記憶）。存放區的憑證可以記住「上次用哪一張」（憑證指紋），不含任何秘密。

### 簽章的內容
- CMS 分離式簽章，SHA-256，RSA 或 ECDSA（依憑證）；帶簽署者的憑證與本機建得出來的憑證鏈。
- 憑證鏈以 `CertGetCertificateChain` 帶 `CERT_CHAIN_CACHE_ONLY_URL_RETRIEVAL` 建立：**不擷取任何網址**；建不完整就只帶本機有的部分。
- 沒有時間戳記：`/M` 是這台電腦的時間，ADR 0014 的驗證器本來就顯示為「簽署者聲稱的時間」。沒有長期驗證（LTV）資料。
- `/Contents` 預留 32 KiB（十六進位 64 KiB 字元）；簽出來比預留大就失敗並說明，不截斷。
- 可見簽章的外觀照 ADR 0018 的方式由 worker 產生（內建的 Droid Sans Fallback 子集，不讀系統字型）：姓名（憑證主旨的 CN）、日期、原因（使用者輸入，有長度上限）。

### 第一版拒絕簽署的情況
- 加密的文件；有未存檔編輯的文件（先存檔）；DocMDP 不允許再簽的文件（P=1）；權限不允許修改的文件（`/P`）；超過 `MAX_DOCUMENT_BYTES`。
- 憑證過期、尚未生效，或用途不含數位簽章（Key Usage 的 digitalSignature／nonRepudiation）：拒絕並說明原因。

### 測試
- 測試用的憑證與 `.pfx` 由腳本產生（不放真的金鑰，照 `tests/corpus/` 的規則），密碼也是測試值。
- 簽完以 ADR 0014 的驗證器確認有效；改一個位元組就無效；密碼不出現在任何日誌或錯誤訊息。
- 存放區：CI 把測試憑證匯入目前使用者的個人存放區，測完刪除。
- 智慧卡：CI 做不到，列進手動檢查表，由負責人用自己的卡試一次。

### POC（接受前）
1. 主行程以 `PFXImportCertStore`（`PKCS12_NO_PERSIST_KEY`）匯入測試 `.pfx`，以 `CryptSignMessage`（分離式，兩段內容）簽一份 worker 準備好的文件，ADR 0014 的驗證器顯示有效。
2. 同一份文件在 Acrobat Reader 中顯示簽章完整（簽署者不受信任是預期的）。
3. 以存放區的測試憑證簽署成功（CNG 與舊 CSP 的金鑰各一）。
4. 匯入與簽署後，磁碟上沒有留下私鑰（`%APPDATA%\Microsoft\Crypto` 與 `SystemCertificates` 沒有新增）。

## 後果
- 換來：
  - 不新增套件（`windows-sys` 多一個功能）；
  - 私鑰不進 worker、不進前端、不落地；智慧卡的私鑰連 app 都不經手；
  - 自然人憑證、工商憑證這類常用的憑證可以直接用。
- 付出：
  - 主行程多一個 `unsafe` 的 CryptoAPI 模組，要安全審查；主行程不在沙盒中，所以它只處理使用者自己選的憑證與 worker 回報的兩個數字，不解析 PDF；
  - **簽署預言機的殘餘風險**：被惡意 PDF 控制的 worker 可以準備出與畫面不同的內容讓使用者簽。緩解：每次簽署都要使用者動作與密碼或 PIN；簽好的檔案由新的 worker 開啟驗證，另存成新檔讓使用者看到結果。顯示與簽署用同一個引擎，這是本機簽署的固有限制；
  - 沒有時間戳記與 LTV（不連網的代價）；只能在 Windows（與 ADR 0014 相同）。
- 與其他 ADR 的關係：ADR 0008（worker 的權限不變）、0010（簽署不寫文件識別碼）、0013（存檔流程）、0014（驗證）、0016（已簽章的文件不能遮蔽）。
- 之後若要改變：簽署的介面（兩段內容進、CMS 出）與憑證來源分開。要加時間戳記，要另寫 ADR，因為它觸及 ADR 0009 的網路政策。
