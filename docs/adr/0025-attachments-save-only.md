# ADR 0025：附件（內嵌檔案）只列出與另存，永遠不由 app 開啟；另存的檔案標記為來自網際網路

## 背景
- PDF 可以夾帶任意檔案：文件層級的 `/Names /EmbeddedFiles`，以及頁面上的附件註解（`/FileAttachment`），兩者都是帶 `/EF` 的檔案規格。主動內容掃描（MVP-11，`scan.rs`）每個 `/EF` 算一個 `embeddedFile`，安全橫幅說「文件夾帶的其他檔案（不會自動開啟）」；`/GoToE`（跳到附件裡的 PDF）是封鎖的動作。除此之外，使用者**拿不到**附件。
- 附件是常見的攻擊載體：`.exe`、`.scr`、`.js`、`.hta`、`.lnk`、含巨集的 Office 檔，名稱還可以用 RLO（U+202E）等字元把副檔名藏起來（`invoice`、U+202E、`fdp.exe` 接在一起，畫面上看起來是 `invoiceexe.pdf`）。PDF 裡的檔名、大小、說明、MIME 類型都是攻擊者寫的。
- 正當的用途也很多：報表附原始的 Excel、合約附簽名頁、PDF 作品集（portfolio）。現在使用者只能換一個閱讀器拿出來，等於把風險推給別的程式。
- Windows 對「從網路來的檔案」有一套保護：檔案的 `Zone.Identifier` 資料流（Mark of the Web）讓 SmartScreen 在執行前檢查、Office 以受保護的檢視開啟。從 PDF 拿出來的檔案和從郵件附件存下來的一樣不可信，但直接寫到磁碟就**沒有**這個標記。
- 規格沒有提到附件。ADR 0008：worker 不能自己開路徑；寫檔由主行程交出只能寫入的 handle。

## 選項

| 選項 | 內容 | 代價 |
|---|---|---|
| A. 維持只偵測 | 不變 | 正當的附件拿不出來，使用者改用別的閱讀器 |
| **B. 列出與另存；不開啟；另存的檔案加上 Mark of the Web（建議）** | 見「決定」 | 要開附件時多一步：存下來再自己開 |
| C. 列出、另存，安全的類型可以「開啟」 | 例如圖片、文字、PDF 交給系統的預設程式或開成分頁 | 「安全的類型」由副檔名判斷，而副檔名是攻擊者寫的；交給預設程式等於在 app 外執行不可信的內容；PDF 開成分頁要先寫一份暫存檔（機敏文件的附件會留在磁碟） |
| D. 列出，任何附件都可以確認後開啟 | 像外部連結一樣確認 | 違反原則 3 的精神：一次確認就執行任意檔案 |

## 決定（選項 B）

### 列出
- worker 從 `/Names /EmbeddedFiles` 與每一頁的附件註解收集附件，回傳清單：每一項是**這個 worker 的不透明代號**、清理過的名稱、宣稱的大小（`/Params /Size`，可能沒有或不實）、說明（`/Desc`，截斷）、來源（文件層級或第幾頁的註解）。數量上限 1,000，名稱與說明有長度上限，主行程 `validate`。
- 名稱的清理（worker 與主行程各做一次）：優先用 `/UF`，否則 `/F`；拿掉路徑（只留最後一段）、控制字元、雙向文字控制字元（U+202A–U+202E、U+2066–U+2069、U+200E、U+200F）、Windows 不允許的字元；拿掉結尾的點與空白；保留裝置名稱（`CON`、`NUL`、`COM1`……）前面加 `_`；空的名稱改成「附件 n」。
- 畫面：側欄或對話框的「附件」清單；名稱旁邊**另外顯示真正的副檔名**；危險的類型有警告圖示與說明。

### 另存
1. 使用者選一個附件按「另存…」：主行程顯示系統的另存對話框（建議的名稱是清理過的名稱，前端拿不到路徑）。危險的類型先多一個確認：「這是可以執行的檔案類型（.exe）。它來自 PDF，可能有害。只在你信任寄件者時才開啟它。」
2. 主行程照存檔的規則交出只能寫入的 handle（資料夾裡的臨時檔），worker 把附件**解碼後**的內容寫進去：上限 512 MiB（與 `MAX_DOCUMENT_BYTES` 相同），超過或解碼失敗就失敗、刪掉臨時檔。內容不經過 IPC 訊息，不進前端。
3. 主行程照另存的規則把臨時檔換成使用者選的名稱（要不要取代已有的檔案，系統對話框已經問過），**然後寫入 `Zone.Identifier` 資料流**：`[ZoneTransfer]` / `ZoneId=3`（網際網路）。寫入失敗（例如 FAT32 的隨身碟沒有資料流）時檔案留著，但告訴使用者「這個檔案沒有『來自網際網路』的標記，Windows 不會在開啟前額外檢查」。
4. 不開啟、不顯示檔案位置以外的任何後續動作；app 沒有「開啟附件」的按鈕。

### 危險的類型
主行程以 Windows 的 `AssocIsDangerous`（系統自己的危險類型清單，含系統管理員的原則）判斷，再加上一份固定的清單補上它不一定包含的：含巨集的 Office 格式（`.docm`、`.xlsm`、`.pptm`……）、磁碟映像（`.iso`、`.img`、`.vhd`、`.vhdx`）、`.lnk`、`.url`、`.hta`、`.js`、`.jse`、`.vbs`、`.wsf`、`.ps1`、`.msi`、`.jar`。名稱沒有副檔名也當成危險。

### 其他規則
- 機敏文件的附件另存時提醒：「存下來的檔案不在機敏保護內。」
- 附件不進最近開啟的檔案、復原日誌與日誌（日誌只有數量與結果，沒有名稱）。
- `/GoToE` 仍然封鎖；不做作品集的檢視（之後要做另寫 ADR）。
- `/Params /CheckSum` 不比對（MD5，宣稱值由攻擊者控制，比對成功也不代表安全）。

## 後果
- 換來：正當的附件拿得出來，而且帶著 Windows 會檢查的標記；app 自己永遠不執行或開啟附件，原則 3 不變。
- 付出：worker 新增兩個請求（列出、寫出），主行程新增另存與 `Zone.Identifier` 的寫入（`Win32_Storage_FileSystem`，已經有）與 `AssocIsDangerous`（`windows-sys` 的 `Win32_UI_Shell`，已經啟用），都要 `needs-security-review`；名稱清理要有完整的測試（RLO、裝置名稱、路徑、空名稱）。
- 擋不到的：使用者存下來之後自己執行；Mark of the Web 可以被使用者或其他程式拿掉；檔案系統不支援資料流時沒有標記（會告知）。
- 不改變：沒有網路；Windows 的防毒會像掃描任何新寫入的檔案一樣掃描它，這是使用者自己系統的設定，不是 app 的行為。
- 之後若要「開啟」附件（選項 C、D）或檢視作品集，要另寫 ADR。新增、刪除附件屬於編輯（ADR 0013 的流程），另開卡，不需要 ADR；分享前淨化（#303）會拿掉全部附件。
