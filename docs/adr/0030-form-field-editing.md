# ADR 0030：建立與修改表單欄位：在文件自己的 worker 中以型別化的編輯新增、修改、刪除欄位與排 Tab 順序；外觀由 MuPDF 產生；app 不寫任何動作或腳本

## 狀態
提議中

（工作卡 B6-09，[#594](https://github.com/winner0988/Pdf-reader/issues/594)，1.0 之後。來源是 Acrobat Pro 對照清單「缺口排名」第 12 項〔[acrobat-pro-parity.md](../planning/acrobat-pro-parity.md)〕；規格 §6。負責人接受之後才開實作的卡；實作前先做下面的 POC，不通過就不實作。）

## 背景
- **現在只能填寫既有的表單**（B2-09，[forms.md](../architecture/forms.md)）：
  - 列出文字欄位、核取方塊、選項按鈕、下拉選單與清單方塊；設定值；扁平化。
  - 隱藏的欄位、按鈕與簽章欄位不列出；可以複選的清單方塊、值太長的欄位、沒有「打開」外觀的按鈕，當成唯讀。
- **不執行任何腳本**：MuPDF 以 `FZ_ENABLE_JS=0` 建置（`javascript_is_compiled_out`），填寫時也不通知欄位（`ignore_trigger_events`）。ADR 0021（已接受）讓既有欄位的腳本在使用者同意後於 worker 中執行，還沒實作（#238）。
- **Acrobat Pro 的「準備表單」**：加入欄位、改屬性、Tab 順序、自動偵測欄位。欄位的格式、驗證與計算都是 JavaScript。AGENTS.md 原則 3：主動內容預設封鎖；#594 規定欄位不能有動作或腳本，也不寫 `/AA`。
- **MuPDF 1.28.6 能做的**（`pdf-appearance.c`、`pdf-form.c`）：
  - 產生外觀：
    - 文字欄位，包括多行、comb、字級 0（自動）；
    - 下拉選單與清單方塊；
    - 核取方塊與選項按鈕：打勾與實心圓兩種固定的樣子，記號一律是黑色；
    - 未簽署的簽章欄位：畫一個箭頭形的標籤。
  - 字型是標準 14 字型（`/DA` 的 `Helv`、`TiRo`、`Cour`）；有中文字時加上不嵌入的 CJK 字型（Adobe-CNS1 等）。現在填寫時就是這樣。
  - 建立：
    - 簽章欄位有 `pdf_create_signature_widget`（繫結的 `add_signature_widget`），它會加上 `/Lock /Action /All`；
    - 其他欄位沒有專用的函式：以 `create_annotation(Widget)` 建 widget，自己寫 `/FT`、`/T`、`/Ff`、`/DA`、`/MK`，再放進 `/AcroForm /Fields`。
  - 核取方塊與選項按鈕「打開」時的狀態名稱：沒有外觀時是 `Yes`；`/AS` 不是 `Off` 時用 `/AS` 的名稱。
  - 扁平化（`bake`）把每一個 widget 的外觀畫進頁面，未簽署的簽章欄位也一樣。
- **已簽章的文件**：存檔用增量更新（ADR 0013）；扁平化拒絕。簽署（ADR 0020、[signing.md](../architecture/signing.md)）一律加一個新的簽章欄位，不簽既有的空白欄位。
- **權限**（MVP-19）：PDF 32000-1 的 `/P` 第 6 位元允許加註解與填表單；第 4 位元也允許時，才可以建立或修改表單欄位（包括簽章欄位）。
- **安全遮蔽**（ADR 0016）：範圍碰到的 widget 連同欄位的值一起刪除。
- **插入其他檔案的頁面**：來源檔（CONTEXT.md）的表單欄位不帶進來；ADR 0019 只帶 app 自己的註解。
- **寫檔的檢查**：app 寫出的每一種 PDF 在整合測試中以 `qpdf --check` 檢查（[saving.md](../architecture/saving.md)）；fuzz 的 `edit_document` 目標套用 1～4 個型別化的編輯，存檔後重新開啟。

## 選項

### 1. 做不做、外觀由誰產生

| 選項 | 內容 | 換來 | 付出與風險 |
|---|---|---|---|
| A. 不做 | 只能填寫別人做好的表單 | 沒有新的寫入路徑 | 要做表單只能用 Acrobat 或線上服務，等於把文件交出去；缺口第 12 項留著 |
| **B. worker 以型別化的編輯建立與修改欄位，外觀由 MuPDF 產生（建議）** | 見「決定」 | 與填寫用同一套外觀；其他閱讀器重畫時照同一個 `/DA`；工作量最小 | 樣式受 MuPDF 限制（核取記號只有一種，而且是黑色）；中文字用閱讀器自己的中文字型 |
| C. 同 B，但外觀由 worker 以所選字型的子集自己畫（ADR 0018 文字方塊的做法） | 嵌入字型的子集 | app 裡看到的字型，其他閱讀器第一次開啟時也一樣 | 欄位的值會變：其他閱讀器填寫時照 `/DA` 重畫，子集裡也沒有之後打的字；等於多維護一套外觀程式；檔案變大 |
| D. 在主行程以 Rust 的 PDF 函式庫寫欄位 | 不經過 MuPDF | — | 違反 ADR 0008（只有 worker 解析 PDF），不考慮 |

### 2. 第一版要不要簽名欄

| 選項 | 換來 | 付出與風險 |
|---|---|---|
| **要：空白的簽名欄（建議）** | 做好的表單可以交給別人用 Acrobat 等閱讀器簽 | 本 app 簽署時仍然加一個新的欄位，不簽這個空白欄（另開卡）；外觀要在 POC 決定 |
| 不要 | 範圍小一點 | 少一種 Acrobat 使用者常用的欄位 |

### 3. 欄位的格式、驗證與計算

| 選項 | 換來 | 付出與風險 |
|---|---|---|
| **不提供（建議，也是 #594 的規定）** | 欄位沒有任何腳本，原則 3 不受影響 | 沒有「只能輸入數字」「日期格式」「加總」這類 Acrobat 以 JavaScript 做的功能；只有不需要腳本的限制：必填、唯讀、最多字數、comb、多行 |
| 寫入 Acrobat 的內建函式呼叫（例如 `AFNumber_Format`） | 在其他閱讀器裡可以計算 | 由 app 寫出主動內容，違反原則 3 與 #594；要另寫 ADR |

## 決定（選項 B）

選的是：1 的 B、2 的「要」、3 的「不提供」。

### 畫面
- 「⋯」→「編輯表單欄位」進入編輯模式；離開之後，欄位照舊可以填寫。
- 編輯模式中：
  - 選欄位的種類，在頁面上拖出位置；只用鍵盤時，欄位放在可見區域的中央，再用方向鍵移動與縮放，與註解相同；
  - 點一下欄位是選取，不是填寫；屬性面板顯示選取的欄位；`Delete` 刪除；
  - 「Tab 順序」面板（見下）。

### 第一版的欄位與屬性

| 種類 | 寫入 | 屬性 |
|---|---|---|
| 每一種 | `/T`、`/TU`、`/Ff`、`/F`、`/Rect`、`/MK`、`/BS`、`/DA` | 名稱、提示文字、唯讀、必填、列印與隱藏、位置與大小、邊框與背景的顏色、框線的粗細與樣式、字型（Helvetica、Times、Courier）、字級（0 是自動）、文字的顏色 |
| 文字欄位 | `/FT /Tx` | 預設值（`/V` 與 `/DV`）、多行、最多字數（`/MaxLen`）、comb、對齊（`/Q`）、不捲動、不檢查拼字 |
| 核取方塊 | `/FT /Btn` | 匯出值（打開時的狀態名稱）、預設打勾 |
| 選項按鈕 | `/FT /Btn` 加 Radio 與 NoToggleToOff；一個欄位，每個按鈕一個 widget（`/Kids`） | 群組名稱、每個按鈕的匯出值、預設選哪一個；可以加按鈕到既有的群組 |
| 下拉選單 | `/FT /Ch` 加 Combo | 選項（顯示的文字與匯出值）、可以自己輸入、預設值 |
| 清單方塊 | `/FT /Ch` | 選項、預設值；只能單選（填寫還不支援複選） |
| 簽名欄 | `/FT /Sig`，沒有 `/V` | 名稱、提示文字。拿掉 MuPDF 預設的 `/Lock`（簽署後鎖定哪些欄位另開卡），不寫 `/SV` |

- 不建立：按鈕、選取檔案的欄位、條碼（#594 的「不做」）、rich text（`/RV`）、密碼欄位（它的值不該存進檔案）、可以複選的清單方塊。檔案裡已經有的照現在的方式處理。

### app 一律不寫
- 欄位與 widget 的 `/A`、`/AA`，以及任何 JavaScript；
- `/AcroForm` 的 `/CO`（計算順序）、`/XFA`、`/NeedAppearances`（外觀都寫好了）；
- `/RV`、`/DS`。
- `/DA` 由 worker 從型別化的值組出（字型是三個名稱之一、字級與顏色是數字）。使用者打的字從不拼進 `/DA` 或內容串流；名稱、提示文字與選項都寫成 PDF 的字串物件。
- 測試走過每一個寫出的檔案的所有物件，確認沒有上面這些鍵。

### 修改既有的欄位
- 別人做的表單也可以改：上表的屬性、位置與大小、刪除、Tab 順序。種類不能改，要刪了再建。
- 欄位層級（名稱、旗標、值、選項）與 widget 層級（位置、顏色、框線）分開。一個欄位有多個 widget 時（例如每一頁都有同一個欄位）：
  - 改欄位層級的屬性，所有 widget 都跟著變；
  - 改 widget 層級的，只改選取的那一個；
  - 刪除 widget 只刪那一個，刪到最後一個才刪除欄位。
- 既有的 `/A`、`/AA` 原樣保留：app 不執行（ADR 0021 的規則不變）、不修改，也不新增。屬性面板說明「這個欄位有腳本，本程式不會執行；改名稱可能讓腳本找不到它」。要拿掉腳本，用「分享前淨化」。
- 刪除欄位時一併從 `/CO` 拿掉，免得留下指不到的參照。
- **名稱**：
  - 完整名稱（加上上層，以 `.` 連接）在文件中不能重複：同名的欄位在 PDF 裡共用一個值。重複一律拒絕，只有加選項按鈕到既有的群組例外。
  - 名稱不能有 `.` 與控制字元，長度上限由實作卡訂。
  - 新欄位預設用 ASCII 的名稱：`Text1`、`Check1`、`Radio1`、`Choice1`、`List1`、`Signature1`（同一類最小的、還沒用過的數字），與 Acrobat 的做法類似，匯出表單資料的工具也認得。使用者可以改成中文。
- **有 XFA 的文件**（`/AcroForm /XFA`）不能編輯欄位：只改 AcroForm 而留下 XFA，兩份表單會不一致。對話框說明原因，建議先做「分享前淨化」的副本（它移除 XFA），再編輯副本。

### Tab 順序
- 一頁一個順序，就是 widget 在頁面 `/Annots` 中的順序。app 填寫時的 `Tab` 已經照這個順序（forms.md）。
- 「Tab 順序」面板列出這一頁的欄位與號碼：可以上下移動（鍵盤也可以），或「依位置排序」（由上而下、由左而右）。只改 widget 彼此的先後，其他註解在 `/Annots` 中的位置不變。
- 頁面的 `/Tabs` 要拿掉、改成 PDF 2.0 的 `/A`，還是別的值，其他閱讀器才會照這個順序：POC 在四個閱讀器看過再決定。

### 外觀
- 由 MuPDF 產生（`pdf_update_appearance`），與填寫時相同。寫出時每個 widget 都有外觀，不靠 `/NeedAppearances`。
- 中文字由 MuPDF 加上不嵌入的 CJK 字型，其他閱讀器用自己的中文字型顯示，與現在填寫時一樣。`/AcroForm` 沒有 `/DR`、`/DA` 時補上。
- 核取方塊與選項按鈕用 MuPDF 的打勾與實心圓（黑色）；邊框與背景照屬性。
- 空白簽名欄：用 MuPDF 的箭頭形標籤，還是只畫邊框，POC 決定。

### 編輯指令
- 新的 `Edit`，定義在 `ipc_contract`，每一個值都有上限，主行程先 `validate`：
  - `AddField { page, kind, rect, properties }`：選項按鈕可以指定既有的群組；
  - `UpdateField { field, properties }`：只帶要改的屬性；
  - `MoveField { field, rect }`；
  - `DeleteField { field }`；
  - `SetTabOrder { page, fields }`。
- 上限：沿用 `MAX_FIELDS_PER_PAGE`（5,000）、`MAX_FIELD_OPTIONS`（1,000）、`MAX_FIELD_VALUE_BYTES`（16 KiB）。名稱與提示文字的長度、`/MaxLen`、框線粗細、字級的範圍，由實作卡訂在 `limits.rs`。`rect` 要是有限值、在頁面範圍內，也不能小於下限。
- 文字一律經過現有的清理（`clean_field_text`、`clean_display_text`）。
- 記入編輯歷史與崩潰復原日誌（ADR 0013）。復原與重做從原始位元組重播，新欄位的編號（widget 的物件編號）重播時相同，與註解一樣（[annotations.md](../architecture/annotations.md)「註解的識別碼」）。
- 存檔照 ADR 0013：沒有簽章的文件整份重寫。

### 與其他功能的關係
- **填寫**：新欄位與既有的一樣列出、可以填寫。
- **扁平化**：照舊。空白簽名欄的外觀也會畫進頁面，與其他欄位相同。
- **安全遮蔽**：照舊，範圍碰到的新欄位連同值一起刪除。
- **數位簽章**：
  - 有簽章的文件不能新增、修改、刪除欄位，也不能改 Tab 順序：理由與扁平化相同，簽章之後改表單的結構，驗證會顯示文件被修改過。填寫照舊。
  - app 簽署時仍然加一個新的簽章欄位（ADR 0020）。簽進既有的空白簽名欄另開卡，要 `needs-security-review`。
- **權限**：`/P` 的第 4 與第 6 位元都允許時才能編輯（`DocumentPermissions` 的 `modify` 與 `annotate`）；以擁有者密碼開啟時全部允許（#88）。
- **表單腳本**（ADR 0021、#238）：不受影響，app 建立的欄位沒有腳本。
- **插入其他檔案的頁面**：來源檔的欄位仍然不帶進來。
- **文字方塊**（ADR 0018）是註解，不是欄位，兩者在畫面上分開。
- **無障礙**：
  - 提示文字（`/TU`）是欄位在 app 與其他閱讀器裡的可讀名稱；它是空的時候，屬性面板提醒。
  - 建立與修改的每一個操作都可以只用鍵盤完成。
  - 第一版不更新有標記的 PDF（tagged PDF）的結構樹，列為已知限制。

### 測試與 fuzz
- worker（語料由 `tests/corpus/generate.py` 產生）：
  - 每一種欄位建立後存檔、重新開啟：`page_fields` 列出它，種類、名稱、屬性、位置都對；可以填寫；扁平化之後值在頁面文字裡；
  - 每一個寫出的檔案：沒有 `/A`、`/AA`、`/JS`、`/CO`、`/XFA`、`/NeedAppearances`；每個 widget 都有 `/AP /N`；通過 `qpdf --check`；
  - 拒絕，而且文件不變：重複的名稱、名稱有 `.`、`rect` 超出頁面、選項太多、comb 沒有 `/MaxLen`、有簽章或 XFA 的文件、沒有權限；
  - 多個 widget 的欄位：欄位層級與 widget 層級的修改，刪除最後一個 widget；
  - Tab 順序：widget 在 `/Annots` 的順序改了，其他註解的位置不變；
  - 既有欄位的腳本原樣保留；刪除欄位時從 `/CO` 拿掉。
- 主行程：新編輯的驗證、復原、重做，崩潰復原的重播（編號不變）。
- fuzz：`edit_document` 加入新的編輯（參數由 fuzz 輸入產生，先 `validate`），套用在 fuzz 出來的文件上，包括壞掉的表單結構：`/Kids` 與 `/Parent` 的循環、`/Fields` 不是陣列、widget 不在 `/Fields` 裡、名稱有 `.` 或重複。新增語料的種子。
- E2E：建立每一種欄位、另存新檔、重新開啟、填寫、扁平化。
- 其他閱讀器（POC 與發行前）：Acrobat Reader、Edge、Chrome、Firefox 開啟 app 做的表單，每一種欄位都能填寫，Tab 順序正確，中文的值顯示得出來。
- `docs/security/attack-surface.md` 加上新的寫入路徑。

### POC（實作前，不通過就不實作）
1. 用繫結現有的 `create_annotation(Widget)` 與 `PdfObject` 建立文字欄位、核取方塊、選項按鈕群組、下拉選單、清單方塊，用 `add_signature_widget` 建立簽名欄，MuPDF 為每一種產生外觀。需要新的 `unsafe` FFI 的話，記下來給負責人決定。
2. 核取方塊與選項按鈕：先設 `/AS` 再產生外觀，打開時的狀態名稱就是匯出值。
3. 中文的預設值與選項，在 app 與其他閱讀器裡都顯示得出來。
4. 四個閱讀器：每一種欄位都能填寫，存檔後值還在；Tab 順序照 `/Annots`（決定 `/Tabs` 寫什麼）；空白簽名欄在 Acrobat Reader 簽得了（決定它的外觀）。
5. 寫出的檔案沒有任何動作或腳本，通過 `qpdf --check`。

## 後果
- 換來：
  - 在 app 裡就能做表單、改別人的表單，不必把文件交給線上服務；
  - app 做的欄位沒有任何腳本或動作；
  - 沒有新的依賴，worker 的權限不變。
- 付出：
  - 新的寫入路徑，會改 `/AcroForm`、頁面的 `/Annots` 與欄位的結構：實作的 PR 要 `needs-security-review`，`attack-surface.md` 加列；
  - 沒有欄位的格式、驗證與計算（那些要腳本）；樣式受 MuPDF 限制；
  - 中文字靠閱讀器自己的中文字型；
  - 有簽章或 XFA 的文件不能編輯欄位；
  - tagged PDF 的結構樹不更新。
- 擋不到的：別人的閱讀器怎麼處理欄位（例如照自己的方式重畫外觀），不在 app 的控制內。
- 不改變：主動內容一律不執行；只有 worker 連結 MuPDF；worker 的權限；前端拿不到路徑。
- 接受時同步更新：規格 §6（建立表單、修改欄位與 Tab 順序，中英文版）、[forms.md](../architecture/forms.md)、對照清單的那一列。
- 之後若要改變這個決定，代價是：
  - 欄位的格式與計算：寫出腳本就是 app 寫出主動內容，要另寫 ADR；
  - 自動偵測欄位、條碼：另開卡；按鈕要有動作，要另寫 ADR；
  - 外觀改由 worker 自己畫（選項 C）：只影響之後寫出的欄位，已經存出去的檔案不變。
