# ADR 0018：文字方塊是頁面上的 FreeText 註解，外觀由 worker 以所選字型的子集自己產生

## 狀態
已接受

（負責人於 2026-10-09 接受：文字方塊用 FreeText 註解、新增 `subsetter` 與 `skrifa`、粗體與斜體只用家族的變體、第一版只做 TrueType 輪廓、復原日誌放子集；字型的來源是第一版只用已安裝的字型、匯入字型檔是第二階段〔[#185 的留言](https://github.com/winner0988/Pdf-reader/issues/185#issuecomment-6064631589)、[續](https://github.com/winner0988/Pdf-reader/issues/185#issuecomment-6064771103)〕。工作卡 [#185](https://github.com/winner0988/Pdf-reader/issues/185)〔B2-18〕。實作卡：[#224](https://github.com/winner0988/Pdf-reader/issues/224)–[#228](https://github.com/winner0988/Pdf-reader/issues/228)，第二階段 [#229](https://github.com/winner0988/Pdf-reader/issues/229)。POC：`crates/pdf_worker/tests/text_box_poc.rs`。）

## 背景
- 規格 §4：在頁面任意處新增文字方塊，可更改字型、大小、顏色、粗細與對齊方式；只讀使用者作業系統本機已安裝的字型，嚴禁連線取得字型；寫入新文字時只把用到的字形輪廓嵌入 PDF，避免亂碼，也避免檔案暴增。
- 已有的做法：註解是標準的 PDF 註解，編輯是型別化的指令，在該文件自己的 worker 中套用（ADR 0013；B2-07、B2-08）；圖片印章的外觀已經是 worker 自己做的（`add_image_stamp`）；崩潰復原日誌最大 4 MiB（B2-13）。
- ADR 0008：主行程不解析 PDF，worker 不開檔案。所以字型檔由主行程讀，以位元組交給 worker，與 OCR 的語言資料相同。
- 字型檔是不受信任的輸入：使用者可能裝了損毀、甚至惡意的字型。解析它的程式碼要在沙盒中，最好是記憶體安全的語言寫的。
- 要決定的事：文字方塊在 PDF 裡是什麼；字型從哪裡來；怎麼只嵌入用到的字形；之後還能不能改；搜尋與選取；復原與崩潰復原。

### POC
`text_box_poc.rs`，13 個測試。字型用 worker 內附的 Droid Sans Fallback（3.5 MB 的 TrueType，含中英文）。

**做得到**
1. 一個 FreeText 註解，外觀串流自己寫（用字型子集的 Type0／CIDFontType2 字型、Identity-H）：畫得出來，方框外沒有任何東西；整個檔案只有 3.4 KB（字型檔 3.5 MB）。存檔後重新開啟，註解的 `/Contents` 還在，外觀的字型名稱有子集前綴（`ABCDEF+…`）。
2. 只改 `/Rect` 就能搬移：外觀不變，在新的位置畫出來，舊的位置沒有東西。
3. 左、中、右對齊；沒有空白的中文也能在方框寬度內自己斷行。
4. 自己寫 `ToUnicode`（每個字形一筆）：同樣的字寫成頁面內容，MuPDF 的搜尋找得到「Hello」「你好」「世界」，所以其他閱讀器也找得到、複製得出來。
5. 現有的機制已經看得到它：`page_annotations` 列出一個 `Other` 註解，位置正確；`set_annotation_rect` 拒絕它（只有手繪與印章能移動，所以不會碰到 MuPDF 的重畫）；存檔（整份重寫）保留它；刪除之後字型跟著消失，檔案回到空白頁的大小。
6. 已安裝的字型由登錄檔（`HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Fonts`）列出：每個字型一筆，有名稱與檔名，粗體與斜體各自是一筆，不必開字型檔。
7. 字型的嵌入授權（OS/2 `fsType`）讀得出來；Droid 是可嵌入的。

**洞**
1. **MuPDF 會把我們的外觀換掉**：註解經過 `set_contents` 或 `set_rect`，再 `update()`（現有的移動與編輯就走這條），MuPDF 以註解的 `/DA`（Helv、12 pt、黑色）重新排版：測試的藍色字不見了（剩不到十分之一）。
2. **MuPDF 自己建的 FreeText 不能用**：`add_free_text_annotation` 多寫一條沒人要的引線（`/CL`），存檔時沒有外觀（`/AP`）：其他閱讀器沒有東西可畫，MuPDF 則在顯示頁面時用 `/DA` 的字型自己畫，不是使用者選的字型。
3. **MuPDF 的字型嵌入是整個字型**：`add_font` 讓檔案多 3.5 MB。
4. **MuPDF 的子集化太大**：`fz_subset_ttf_for_gids` 留著每個字形的位置與列出它們的表：11 個字形還是 405 KB。純 Rust 的 `subsetter`：同樣的 11 個字形 1.2 KB，一句 50 個字的話 5.2 KB（測試要求小於 8 KB）。這決定了崩潰復原日誌放得下（4 MiB 約幾百個方塊，MuPDF 的版本十個就滿）。
5. **方框裡的文字不在頁面的文字裡**：頁面的文字搜尋（`to_text_page`）只走頁面內容，不走註解的外觀；搜尋「Hello」「你好」都是零筆。要讓它可搜尋，worker 得自己把方塊的文字併進搜尋與選取。

## 選項

### 文字方塊在 PDF 裡是什麼

| 選項 | 內容 | 代價 |
|---|---|---|
| **A. FreeText 註解，外觀由 worker 自己產生（建議）** | 標準的「文字方塊」註解：`/Contents` 是文字，`/AP` 是我們做的外觀（字型子集），`/DA`、`/Q` 給其他閱讀器 | MuPDF 的註解呼叫會把外觀換掉（洞 1），要有規則與測試守住；搜尋與選取要自己併入（洞 5）；別的閱讀器編輯文字時字型會變成 `/DA` 的字型 |
| B. 自訂名稱的 Stamp 註解 | MuPDF 對不認得的印章名稱不重畫外觀（`add_image_stamp` 已經這樣做），現有的移動與縮放照用 | 別的閱讀器看到的是「印章」，不是文字方塊，也不能依文字編輯；搜尋與選取一樣要自己做 |
| C. 直接寫進頁面內容 | 文字是頁面的一部分：搜尋、選取、複製都是現成的，MuPDF 不會重畫 | 寫下去就不能再選取、移動、改字或改字型（要自己標記內容才找得回來）；之後想改只能復原，存檔後不行 |

### 子集化

| 選項 | 11 個字形 | 新增的依賴 | 出錯時 |
|---|---|---|---|
| 整個字型（MuPDF `add_font`） | 3.5 MB | 無 | — |
| MuPDF `fz_subset_ttf_for_gids` | 405 KB | 無，但要以 `mupdf-sys` 直接呼叫（`unsafe`） | 在沒有 `fz_try` 的 context 上出錯，MuPDF 直接結束行程；字型是不受信任的輸入 |
| **`subsetter`（建議）** | 1.2 KB | `subsetter` 與 `skrifa`，連同它們帶來的 8 個套件（font-types、read-fonts、write-fonts、kurbo、euclid、polycool、arrayvec、bytemuck_derive）；全是純 Rust、MIT 或 Apache-2.0，`cargo deny check` 通過 | `Result`；`subsetter` 自己 `#![deny(unsafe_code)]` |

### 字型的來源

| 選項 | 內容 | 代價 |
|---|---|---|
| **主行程列出已安裝的字型（第一版）** | 讀登錄檔（HKLM 與 HKCU 的 Fonts）得到名稱與檔名，使用者選了才讀那個檔，以位元組交給 worker。想增加字型，就在 Windows 安裝它：Windows 11 對字型檔按右鍵的「安裝」只給目前使用者，不需要系統管理員 | 登錄檔的名稱是顯示名稱（`Arial Bold (TrueType)`），家族與樣式要靠名稱整理；`.ttc` 的各個字型要再問 worker；字型只限這台電腦裝了的，不能安裝字型的電腦（例如受管理的）要等第二階段 |
| **匯入字型檔（第二階段）** | 使用者選一個本機的字型檔，主行程檢查後複製進 app 的資料資料夾，之後和已安裝的字型列在一起；只給 app 用，不改 Windows | 多一個命令、一個資料夾與一份清單；字型檔是不受信任的輸入；規格 §4 的「已安裝的字型」要補上「使用者自己選的本機字型檔」 |
| app 另外附免費字型（不做） | 安裝檔附幾套可以嵌入的字型（例如 OFL 授權的） | 安裝檔變大，授權與來源要加進第三方聲明（REL-04）；附的不是使用者的字型 |
| worker 自己掃描字型資料夾 | — | 違背 ADR 0008：worker 不能開檔案 |
| 只用 app 內附的字型 | Droid（CJK）與 MuPDF 的 14 個基本字型 | 違背規格「使用者作業系統本機已安裝的字型」，字型少 |

## 決定
採用各表中建議的選項（字型的來源：第一版用已安裝的字型，第二階段匯入字型檔）：**文字方塊是 FreeText 註解，外觀由 worker 以所選字型的子集自己產生**。

### 文字方塊
- worker **自己寫註解的字典**（不用 `add_free_text_annotation`）：`/Subtype /FreeText`、`/Rect`、`/Contents`、`/AP`、`/DA`（大小與顏色，給其他閱讀器）、`/Q`（對齊）、`/IT /FreeTextTypeWriter`、`/BS << /W 0 >>`，沒有 `/CL`。另有一個私有的字典記著使用者的選擇（字型名稱、大小、顏色、對齊），讓 worker 之後能重新產生外觀；別的閱讀器會忽略它。
- **規則：對文字方塊絕不呼叫 MuPDF 的註解 setter 或 `update()`**（洞 1）。移動只改 `/Rect`；改文字、字型、大小、顏色、對齊或調整大小時，由 worker 重新排版、重新產生外觀與字型子集，舊的字型物件隨整份重寫消失。POC 的「MuPDF 會重畫」與「現有機制看得到它」兩個測試就是守這條規則的：MuPDF 改變行為時它們會失敗。
- 排版由 worker 做：以字型的度量斷行（空白處，沒有空白就在放不下的字形前），左／中／右對齊；字形的對應與寬度由字型來。
- 現有的選取、移動、縮放、刪除、復原與重做、存檔都沿用 B2-07、B2-08 的機制；新增一種註解（`AnnotationKind::TextBox`），移動與縮放走 worker 自己的路徑。

### 字型
（負責人 2026-10-09：字型的來源第一版只用已安裝的字型，匯入字型檔是第二階段。下面前六條兩個階段都一樣，只有字型從哪裡來不同。）
- **worker 以 `skrifa` 讀字型**（字形對應、寬度、度量、授權旗標），以 `subsetter` 子集化：每個文字方塊一份自己的子集，嵌入為 Type0／CIDFontType2（Identity-H），名稱 `ABCDEF+<名稱>`，附 `ToUnicode`。字型的位元組只由記憶體安全的程式碼解析。
- **授權**（OS/2 `fsType`）：受限、只能嵌入點陣、不允許子集化的字型拒絕嵌入並說明；「預覽與列印」的字型可以用，但對話框說明「只能檢視與列印」；其他可以。app 只看字型自己標示的嵌入權限，不判斷使用者有沒有授權使用它。
- **粗體與斜體**：用字型家族的變體（已安裝的在登錄檔中各自一筆，匯入的各自是一個字型）；沒有變體時不模擬，並說明。
- **第一版只做 TrueType 輪廓（`glyf`）**；OpenType／CFF、可變字型與彩色字型拒絕並說明。缺字不要默默變成方框：實作時要不是補一個字型、就是提示使用者，細節在實作卡。
- **名稱當成文字處理**（登錄檔的、字型裡的）：去掉控制字元與看不見的格式字元、限制長度，與 PDF 來的文字一樣。
- **找不到原來的字型時**（解除安裝了、換了電腦、匯入的被移除）：文字方塊照原樣顯示與列印（外觀已經嵌在檔案裡），移動與刪除也照常；要改文字、大小、顏色、對齊或調整大小時要重新排版，請使用者先選另一個字型，不默默換掉。

#### 第一版：只用本機已安裝的字型
- **主行程**讀登錄檔：`HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Fonts`（系統的字型，值是檔名，在 Windows 的字型資料夾裡）與同一個位置的 `HKCU`（使用者自己安裝的，值是完整路徑；2026-10-09 在 Windows 11 上查過）。使用者選了才讀檔（上限另定，建議與語言資料同為 64 MiB；`.ttc` 要有字型的序號），以位元組交給 worker。畫面只拿到顯示名稱與不透明的代號，拿不到路徑；清單的項目有「來源」欄位（第一版只有「已安裝」，第二階段多一個「已匯入」）。沒有任何連網與下載。
- 讀登錄檔用 `windows-sys`（主行程已經是依賴），只多 `Win32_System_Registry` 一個 feature，不新增套件；`unsafe` 限於一個模組，只讀不寫，每個區塊寫明為什麼安全（比照 `opener.rs`、`saving.rs`）。
- **想增加字型，就在 Windows 安裝它**：對字型檔按右鍵的「安裝」只給目前使用者，不需要系統管理員（「為所有使用者安裝」才需要）。清單在每次開啟字型選單時重新讀登錄檔，所以裝完不必重新啟動 app；選單的最後一行說明這件事：「找不到要用的字型？先在 Windows 安裝它，再重新開啟這個選單。」

#### 第二階段：匯入字型檔（另開實作卡，排在文字方塊的第一版之後）
給不想、或不能把字型裝進 Windows 的人：受管理、不許安裝字型的電腦，或只想在這個 app 用一個字型。
- 「匯入字型檔…」（字型選單與設定頁）：對話框在主行程，路徑不到畫面；做法與匯入 OCR 語言資料相同（[ocr.md](../architecture/ocr.md) 的「語言資料」）。依序檢查：副檔名（`.ttf`、`.ttc`）、已匯入的數量、大小（讀取時就限制）、檔頭（`00 01 00 00`、`true` 或 `ttcf`）；通過才交給 worker 以 `skrifa` 完整檢查（讀得開、有 `glyf`、字形對應表、授權旗標、名稱）；全部通過才經暫存檔複製進 app 的資料資料夾下的 `fonts`（與設定、最近開啟的檔案同處，見 [local-data.md](../architecture/local-data.md)）。檔名由內容的雜湊值決定，不用使用者的檔名。壞掉的檔案不會留下任何東西。數量與大小的上限在實作卡定（建議最多 50 個、每個最多 64 MiB）。
- 匯入的字型和已安裝的字型列在同一份清單，標示「已匯入」；內容相同（雜湊相同）的不重複匯入。設定頁列出已匯入的字型，可以逐一移除，也可以全部移除。
- 匯入**不是安裝**：字型只在這個 app 裡，不改登錄檔，也不放進 Windows 的字型資料夾。
- 交給 worker 之前再檢查一次（資料夾裡的檔案可能是手動放進去的）。匯入的檔案是使用者自己選的本機檔案，不下載、不上傳。
- 匯入的對話框提醒「請確認你有權使用並嵌入這個字型」（授權的規則見上）。

### 搜尋、選取與復原
- worker 把文字方塊的文字併入頁面的搜尋與文字層（像 OCR 的結果）；命中的框先用方塊的矩形。
- **復原與崩潰復原日誌放字型的子集，不放整個字型**（POC：一句話 5 KB，整個字型最多 20 MB，放不進 4 MiB）：重播時不需要原來的字型檔，也就不怕字型被移除。主行程保管用過的字型位元組（像合併的來源檔），用來改字。

### 不做
修改頁面上既有的文字（規格 §4 只說新增文字方塊）；阿拉伯文、印度系文字的字形變化與直排；以選項 C「套用到頁面」把文字方塊變成頁面內容（之後可以像「扁平化表單」那樣加）；app 另外附字型；從網路取得字型（規格 §4 嚴禁）。

## 後果
- 換來：
  - 文字方塊是標準的 PDF 註解，其他閱讀器顯示得出來，使用者也能在 app 裡再選取、移動、縮放、改字與刪除；
  - 只嵌入用到的字形：一個方塊 3.4 KB，不是 3.5 MB；日誌放得下；
  - 字型檔（不受信任）由純 Rust 的程式解析，MuPDF 與 FreeType 只讀我們自己產生的子集；
  - 沙盒不放寬，沒有連網。
- 付出：
  - worker 新增兩個依賴：`subsetter` 與 `skrifa`，連同 8 個套件（要 `needs-security-review`；字型位元組進入它們，實作時建議加 fuzz 目標）；
  - 一條必須守住的規則（不對文字方塊用 MuPDF 的註解呼叫），靠測試守，新增註解相關的程式時要記得；
  - 搜尋與選取要自己做；排版（斷行、對齊）要自己寫，沒有 HarfBuzz 級的字形變化；
  - 別的閱讀器編輯文字方塊的文字時，字型會變成 `/DA` 的字型；
  - 第一版的字型只限這台電腦裝了的：不能安裝字型的電腦（例如受管理的）要等第二階段；使用者要增加字型就先在 Windows 安裝（字型選單上有說明）；
  - 第二階段多一個資料夾、一份清單、兩個命令（匯入、移除）與設定頁的一節；匯入的字型檔和 OCR 的語言資料一樣是不受信任的輸入，只有 worker 解析，主行程只檢查大小與檔頭（需要 `needs-security-review`，也要有 fuzz 目標）；
  - 使用者的字型清單（名稱）只在這台電腦的主行程裡，匯入的字型檔放在 app 的資料資料夾；嵌入的子集含字型的名稱與版權資訊。
- 之後若要改變這個決定，代價是：
  - 改成選項 C（頁面內容）：既有的文字方塊可以逐一「套用到頁面」，新的程式只要換掉產生外觀的最後一步；
  - 改用 MuPDF 的子集化：日誌要放得下 400 KB 的子集，或改存字型的參照；
  - 第二階段不做、或改成別的做法：第一版不受影響，字型清單的項目本來就有「來源」欄位。
- 接受時要同步：規格書 §4（中英文；「僅掃描並讀取…已安裝的字型」補上第二階段的「或使用者自己選的本機字型檔」）、CONTEXT.md（新增「文字方塊」詞條）、`docs/backlog/README.md` 的第三批候選、`docs/architecture/annotations.md`。
