# ADR 0011：專案以 AGPL-3.0-or-later 授權並公開原始碼

## 狀態
提議中

（負責人於 2026-09-24 選定 AGPL-3.0-or-later，並決定把 repo 改為公開；本 ADR 記錄這個決定，待負責人改為「已接受」。）

## 背景
- DEC-02（#2）要求：repo 公開或任何形式的散布之前，先決定本專案的授權。
- ADR 0003 選定 MuPDF，它以 AGPL-3.0 授權（或向 Artifex 購買商業授權）。ADR 0003 寫的是「僅供個人使用、不對外散布，此授權條款不構成限制」；repo 公開後，這個前提不再成立。
- `pdf_worker` 靜態連結 MuPDF，並與主程式一起以安裝檔散布。依 AGPL，把含有 MuPDF 的程式交給任何人時，必須以 AGPL 相容的條件提供完整對應原始碼。

## 選項
| 選項 | 內容 | 問題 |
|---|---|---|
| **AGPL-3.0-or-later**（採用） | 與 MuPDF 相同的授權 | 任何人散布修改版時，都必須以同樣授權公開原始碼 |
| 不附授權（保留所有權利） | 原始碼公開可看，但他人不得重用或修改 | 外部無法合法貢獻；把安裝檔交給任何人時，仍然要回到 AGPL 的義務 |
| 自己的程式碼用寬鬆授權（MIT／Apache-2.0） | 程式碼片段可在其他專案中重用 | 散布出去的整個程式仍受 AGPL 約束，兩種授權並存容易誤解 |

## 決定
- **授權**：本專案自己的程式碼、文件與測試語料（`tests/corpus/` 的產生器與它產生的 PDF）以 **GNU Affero General Public License v3.0 或之後的版本（AGPL-3.0-or-later）** 授權，全文在根目錄的 `LICENSE`。
- **公開**：repo 改為公開。
- **第三方元件**保留各自的授權：
  - MuPDF 為 AGPL-3.0（經由 `mupdf-sys` crate 帶入）；
  - 其他 Rust 與 npm 依賴以各套件的授權為準；
  - 依賴的授權由 MVP-13 的 `cargo-deny`（`deny.toml`）控管：`AGPL-3.0` 只以例外方式允許 `mupdf` 與 `mupdf-sys` 兩個 crate，其他依賴仍只能使用寬鬆授權；本專案未發布的 workspace crate 不在檢查範圍內。
- **散布安裝檔**：是否把安裝檔交給他人（包含朋友、同事）尚未決定；公開 repo 本身不必附安裝檔。一旦散布（交給任何人都算），就要做到：
  1. 隨安裝檔附上 `LICENSE` 與第三方授權聲明；
  2. 提供完整對應原始碼：每個發布版本在公開 repo 打上對應的 tag，並在安裝檔或「關於」中註明原始碼位置；
  3. 若修改過 MuPDF，修改後的原始碼也包含在內。
- **商業化**：尚未決定；需要的條件見「後果」。
- **與 ADR 0003 的關係**：ADR 0003 的後果已寫明「未來若考慮對外散布或商業化，需要重新評估授權」，本 ADR 就是這次重新評估。它取代 ADR 0003 中「僅供個人使用、不對外散布」的前提；選用 MuPDF 作為引擎的決定不變，所以 ADR 0003 維持「已接受」。

本 ADR 是專案的授權決定與對義務的理解，不是法律意見。

## 後果
- **換來**：
  - 授權與 MuPDF 一致，散布時的義務清楚；
  - 任何人都能檢視並驗證「不連網、零遙測、主動內容預設封鎖」的主張；
  - 外部貢獻有明確的授權依據。
- **付出**：
  - 任何人散布修改版，都必須以 AGPL 公開原始碼；
  - 若日後想以閉源方式商業化，需要向 Artifex 購買 MuPDF 商業授權，並處理外部貢獻者的授權（例如事先要求 CLA）。
- **之後若要改變**：
  - 改成寬鬆授權並不能擺脫 AGPL，因為程式仍連結 MuPDF；
  - 要擺脫 AGPL 只能更換引擎（另立 ADR，成本極高，見 ADR 0003）或購買商業授權；
  - 改成更嚴格或閉源，需要所有貢獻者同意。
- **待辦**：
  - 安裝檔附上 `LICENSE` 與第三方授權聲明（REL 工作卡）；
  - MVP-13 的 `deny.toml` 加入上述例外。
