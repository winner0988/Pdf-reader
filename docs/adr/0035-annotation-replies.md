# ADR 0035：註解的回覆：作者名稱只來自設定中自己填的顯示名稱（預設空白），填了才寫進 `/T`，時間一律不寫；刪除註解時整串回覆一起刪除

## 狀態
提議中

（工作卡 B5-08，[#445](https://github.com/winner0988/Pdf-reader/issues/445)，排在 1.2.0〔追蹤卡 [#690](https://github.com/winner0988/Pdf-reader/issues/690)〕。來源是 2026-11-03 與 pdfcraft 的比較；規格 §6「註解標記」；建立在 B4-06 註解清單〔[#414](https://github.com/winner0988/Pdf-reader/issues/414)〕上。工作卡要負責人先在 A（照舊都不寫）與 B（設定中的顯示名稱）之間選，選 B 才要 ADR；這份 ADR 寫下兩者的取捨，以及選 B 時回覆怎麼讀、怎麼寫、怎麼刪。下面五組選項由負責人決定（第 5 組要改 fork），粗體是建議的做法；接受之後才照工作卡實作。）

## 背景
- **PDF 的回覆**（ISO 32000-1 §12.5.6.2，markup 註解）：
  - 回覆是一個註解（通常是文字附註 `Text`），`/IRT` 指向被回覆的註解；`/RT` 是 `/R`（回覆，沒寫時也是）或 `/Group`（和它成為一組，不是回覆）。
  - 審閱狀態（已接受、已拒絕等）也是回覆，多了 `/State` 與 `/StateModel`。
  - `/T` 是作者（文字），`/M` 是修改時間，`/CreationDate` 是建立時間。其他閱讀器（例如 Acrobat）在被回覆的註解底下顯示回覆串，靠作者與時間辨認是誰說的。
- **app 現在**：
  - 不顯示回覆：註解摘要把回覆當成一般的附註列出（[annotation-summary.md](../architecture/annotation-summary.md)）；回覆有外觀時，頁面上照樣畫出來。
  - 刪除註解時，指向它的 `/IRT` 改成 `null`（`unlink.rs`，[annotations.md](../architecture/annotations.md)），回覆變成獨立的附註。套用遮蔽（ADR 0016）刪除範圍內的註解時也是這樣，範圍外的回覆留下。
  - **不寫入任何可識別使用者的資訊**：app 建立的註解沒有 `/T`、`/CreationDate`、`/M`、`/NM`；worker 的測試檢查它們不存在，也有「加上作者就失敗」的負向對照（annotations.md）。
  - 隱私匯出與分享前淨化拿掉所有註解的作者與時間（[privacy-export.md](../architecture/privacy-export.md)）。
  - XFDF 匯出（B5-09）寫 `inreplyto`、不寫作者；匯入（ADR 0033，提議中）在這張卡之前略過回覆。插入其他檔案的頁面時不讀 `/IRT`（ADR 0019，[merge.md](../architecture/merge.md)）：回覆符合附註的規則時，被當成一般的附註帶過來。
- **MuPDF**：`pdf_set_annot_author` 寫 `/T`（Rust 的綁定有 `set_author`）；沒有寫 `/IRT` 的函式，要直接寫進註解的字典；`pdf_set_annot_hidden_for_editing` 讓註解不畫出來，只在記憶體（C 的 API，Rust 的綁定沒有包裝）；繫結畫頁面的註解只能整批畫（`Page::run_annotations`），沒有一次畫一個的函式。建立文字附註時，MuPDF 另外加上一個彈出視窗（`Popup`）。
- **設定**（[local-data.md](../architecture/local-data.md)）：`settings.json` 由主行程讀寫；前端送回完整的一組設定（`deny_unknown_fields`），舊的檔案沒有新的項目時用預設值。
- **原則**：從檔案讀出的作者與內容是不受信任的字串（工作卡）；寫入作者是新的個資路徑（工作卡的「資安」）；零遙測、不連網（AGENTS.md 原則 1、2）。

## 選項

### 1. 作者名稱從哪裡來

| 選項 | 換來 | 付出與風險 |
|---|---|---|
| A. 照舊都不寫（工作卡的 A） | 不寫任何可識別使用者的資訊，規則與測試都不變 | 回覆串只能靠順序辨認；別人打開檔案，看不出哪幾則是你寫的 |
| **B. 設定中可以填一個顯示名稱，預設空白；填了才寫進 `/T`，時間一律不寫（工作卡的 B，建議）** | 想被認出來的人才寫；預設與現在相同；別人在 Acrobat 等閱讀器看得到是誰回覆的 | 新的個資路徑：名稱跟著存檔的檔案出去；「app 建立的註解沒有作者」的規則與測試改成「沒填名稱時沒有作者」 |
| C. 用 Windows 的帳號名稱（Acrobat 的預設就是登入的名稱） | 不必設定 | 帳號名稱常常是真名或電子郵件，使用者不知道它被寫進檔案；違反「不寫入任何可識別使用者的資訊」，**不採用** |
| D. B 再加上時間（`/M`、`/CreationDate`） | 其他閱讀器能依時間排序 | 時間透露你什麼時候在看這份文件；工作卡已經說「時間一律不寫」 |

### 2. 選 B 時，名稱寫在哪些註解上

| 選項 | 換來 | 付出與風險 |
|---|---|---|
| **A. app 新加的每一個註解與回覆（建議）** | 回覆串的第一則（被回覆的註解）也看得出是誰的；與其他閱讀器相同 | 每一種新增註解的編輯都多一件事（作者由主行程填入，見「寫入」） |
| B. 只寫在回覆上 | 改變最小 | 你的螢光筆被別人回覆時，看不出是你標的 |

### 3. 被回覆的註解刪除時

| 選項 | 換來 | 付出與風險 |
|---|---|---|
| **A. 整串回覆一起刪除（建議）** | 規則一致：使用者刪除、套用遮蔽、刪除頁面都一樣；遮蔽之後，回覆裡提到被遮蔽內容的文字不會留下；一筆編輯，一次復原就全部回來 | 刪除前要說明有幾則回覆會一起刪除 |
| B. 留著，變成獨立的附註（現在的做法：`/IRT` 改成 `null`） | 不會刪掉別人的回覆 | 回覆離開了它在說的註解，意思不清楚；套用遮蔽之後，回覆的文字還在 |
| C. 有回覆時不能刪除 | 不會誤刪 | 要先一則一則刪回覆；遮蔽也被擋住 |

### 4. 可以修改哪些回覆

| 選項 | 換來 | 付出與風險 |
|---|---|---|
| **A. 沒有作者的，或作者就是你現在的顯示名稱的（建議）** | 不會把別人的話改掉、卻留著別人的名字 | 改過顯示名稱之後，以前的回覆就不能改（還是可以刪除） |
| B. 全部都可以改 | 與現在的附註相同（任何附註都能改文字） | 可以改掉別人的話、留著別人的名字 |

### 5. 回覆要不要畫在頁面上

ISO 32000-1 要閱讀器把回覆放在串裡，不個別顯示。app 現在照樣把有外觀的回覆畫出來（通常疊在被回覆的註解上）。不畫需要 fork 沒有的函式，所以**要負責人同意改 fork**。

| 選項 | 換來 | 付出與風險 |
|---|---|---|
| **A. 不畫：在 `winner0988/mupdf-rs` 加上 `pdf_set_annot_hidden_for_editing` 的包裝函式，與 #442（圖層）要的三個函式放在同一次 fork 的修改裡，一起審查（建議）** | 與其他閱讀器相同：回覆只在串裡；頁面、縮圖、列印與匯出圖片都沒有多出的圖示 | 要改 fork；旗標只在記憶體，每次載入都要重新設定（見「讀取」） |
| B. 照現在畫，不改 fork（負責人不同意改 fork 時的做法） | 不改 fork，第一版就能做 | 有外觀的回覆照樣畫在頁面上，只在註解清單與附註的對話框裡排成一串；app 加的回覆在 app 裡也多一個圖示，疊在被回覆的註解上 |

## 決定（建議的做法：1 的 B、2 的 A、3 的 A、4 的 A、5 的 A）

負責人選了別的選項時，接受前改寫這一段。選 1 的 A 時，「作者」相關的段落拿掉，回覆的讀、寫、刪照下面的做法。

### 範圍：第一版
- 註解清單（B4-06）的每一個註解底下顯示它的回覆串（先顯示數目，可以展開）；附註的對話框顯示同一串，最下面可以回覆。
- 可以回覆任何列在註解清單裡的註解：螢光筆與文字標記、附註、手繪、印章、圖形、文字方塊。
- 設定多一項「顯示名稱」，預設空白，說明：「填了之後，你新加的註解與回覆會寫上這個名稱，別人打開檔案就看得到；不會寫時間。」
- 回覆只有純文字；作者不允許註解（`/P` 第 6 位元）時不能回覆，與其他註解相同。
- 不做（工作卡的「不做」）：審閱狀態；回覆的格式化文字（rich text）。

### 讀取（worker）
- **是回覆**：`Text` 註解，`/IRT` 指向同一頁的另一個註解，`/RT` 沒有或是 `/R`。
- **不當成回覆**：
  - `/RT /Group`：照現在當成一般的註解；
  - 有 `/State` 或 `/StateModel` 的：審閱狀態，不顯示（工作卡的「不做」），但刪除被回覆的註解時一起刪除；
  - `/IRT` 指向不存在、不在同一頁或不是註解的物件：照現在當成一般的附註。
- **回覆的回覆**屬於同一串：往上找到第一個不是回覆的註解。以走過的物件防止循環，最多 `MAX_REPLY_DEPTH`（新的常數，64）層，超過的當成一般的附註。
- **順序**：一串裡依頁面 `/Annots` 的順序（app 寫的回覆沒有時間）。
- **給前端的**：每則回覆的編號、文字、作者、時間與能不能修改（選項 4）。作者與文字是不受信任的字串：照附註現在顯示的規則清理（控制字元與連續空白變成一個空白，看不見的格式字元去掉，annotations.md），作者最多 `MAX_TEXT_BYTES`（1,024 位元組），文字照 `MAX_NOTE_TEXT_BYTES`（4,096 位元組）；畫面只以純文字顯示。時間取 `/M`，沒有時取 `/CreationDate`，照「文件內容」對話框的日期規則解析（`PdfDate`，B5-04），解析不了就不顯示。
- **回覆不畫在頁面上**（選項 5 的 A），也不再另外列成一般的附註，只在它的串裡出現：
  - 以 MuPDF 的 `pdf_set_annot_hidden_for_editing`：只在記憶體，不寫進檔案；`pdf-interpret.c` 畫註解時略過它，所以縮圖、列印與匯出圖片都一樣（POC 確認）。fork 要先加上包裝函式（選項 5）。
  - **每次載入都要重新設定**：旗標不在檔案裡，worker 每一次從位元組開啟文件都要對每則回覆重新設定：開啟、重新開啟、復原與重做的重播、崩潰後還原、worker 重啟、存檔後重新開啟；新增一則回覆之後也設定。
  - 選項 5 的 B 時，回覆照現在畫，只是不再另外列成一般的附註。

### 寫入
- **新增回覆**：新的編輯 `AddReply { page, in_reply_to, text }`（ADR 0013，一筆，可以復原）。worker 新增一個 `Text` 註解：
  - `/IRT` 是被回覆的註解（間接參照，直接寫進字典）；沒有 `/RT`（預設就是回覆）；
  - `/Contents` 是文字，與附註相同的檢查（`check_note_text`：不能是空的，最多 `MAX_NOTE_TEXT_BYTES`，不能有控制字元與看不見的格式字元）；
  - 位置與被回覆的註解相同；要不要 MuPDF 加的彈出視窗，由 POC 依其他閱讀器的顯示決定；
  - 沒有時間、沒有 `/NM`；作者見下。
- **作者**：
  - 顯示名稱填了，才以 `pdf_set_annot_author` 寫進 `/T`；空白時沒有 `/T`，與現在相同。
  - **名稱只由主行程從設定填入**：前端送的編輯沒有作者的欄位，給不了別的名稱。日誌記下當時寫入的名稱，崩潰後還原、復原與重做時照樣寫。
  - 選項 2 的 A：填了名稱之後，新加的其他註解（螢光筆、附註、手繪、印章、圖形、文字方塊）也寫上。之前建立的不改；之後改名稱，也不改已經寫進去的。
  - 顯示名稱只有一行，最多 `MAX_AUTHOR_NAME_CHARS`（新的常數，64 個字元），不能有控制字元與看不見的格式字元（與附註的規則相同），主行程檢查；只有空白就當成沒有填。
- **修改回覆**：現有的 `SetNoteText`，只限選項 4 的 A 那些回覆；主行程也檢查，不只是畫面上不給按。
- **刪除**（選項 3 的 A）：
  - `DeleteAnnotation` 刪除一個註解時，它的整串回覆（包括回覆的回覆與審閱狀態）在同一筆編輯中一起刪除，一次復原全部回來；被刪除的回覆照現在的規則清掉其他物件對它們的參照（`unlink.rs`）；
  - 刪除一則回覆時，回覆它的那些也一起刪除；
  - 套用遮蔽（ADR 0016）刪除範圍內的註解時，它們的回覆串也刪除，套用前的確認（`RedactionSummary` 的 `annotations`）把這些算進去；
  - 刪除頁面時，頁上註解的回覆一起刪除（回覆通常在同一頁）；
  - 畫面在刪除後說明「連同 N 則回覆」。

### 與其他功能的關係
- **隱私匯出與分享前淨化**：照現在拿掉所有註解的作者與時間，也包括你的顯示名稱。
- **XFDF**：匯出照舊寫 `inreplyto`、不寫作者（B5-09）。匯入（ADR 0033）帶回覆，以及匯出、匯入要不要帶作者，在這張卡之後另開卡決定。
- **插入頁面（ADR 0019）**：回覆現在被當成一般的附註帶過來；改成連同回覆的關係一起帶，另開卡。
- **可攜版（ADR 0034，提議中）**：顯示名稱在 `data\` 的設定裡，跟著程式走。
- **機敏文件**：沒有不同。

### 上限

| 項目 | 上限 | 在哪裡檢查 |
|---|---|---|
| 回覆的回覆 | `MAX_REPLY_DEPTH`（新的常數，64 層） | worker |
| 讀出的作者 | `MAX_TEXT_BYTES`（1,024 位元組） | worker 與主行程 |
| 回覆的文字 | `MAX_NOTE_TEXT_BYTES`（4,096 位元組） | 前端、主行程與 worker |
| 顯示名稱 | `MAX_AUTHOR_NAME_CHARS`（新的常數，64 個字元） | 前端與主行程 |
| 每一頁 | 回覆也算在 `MAX_ANNOTATIONS_PER_PAGE`（2,000）裡 | worker |

### 命令與請求
- 設定多一個欄位 `authorName`（沒有時是空白），走現有的設定命令；舊的 `settings.json` 沒有它時用預設值。
- 新的編輯 `AddReply`；`DeleteAnnotation` 多刪除回覆串；頁面的註解（`PageAnnotation`）與註解摘要多了回覆串的資料。都定義在 `ipc_contract`，每個值都有上限，回應先 `validate`。
- 沒有新的命令，capability 與 CSP 不變。

### 測試
- 語料（`tests/corpus/generate.py`）：一份有回覆串的檔案：兩層的回覆、`/RT /Group`、審閱狀態、指向不存在的物件的 `/IRT`、互相指向的 `/IRT`、很長的作者與文字、有雙向控制字元的作者。
- worker：
  - 讀：回覆串、順序、哪些不是回覆、循環與層數的上限、清理；
  - 加：`/IRT` 正確；沒有時間與 `/NM`；有沒有 `/T` 跟著顯示名稱；負向對照：沒填名稱卻寫了作者，測試要失敗；
  - 改、刪（整串）、套用遮蔽時整串刪除、刪除頁面；存檔後重新開啟，回覆串一樣；
  - 選項 5 的 A：開啟、復原、重做、崩潰後還原、worker 重啟之後，回覆都沒有畫出來；
  - **改寫、不刪除**：現在「刪除註解時把回覆的 `/IRT` 改成 `null`」的測試（annotations.md 的「回覆不再指向它」，以及「不切斷指向」的負向對照）改寫成整串刪除。不在同一頁、所以不算回覆的 `/IRT`，照現在改成 `null`，這個情形的測試留著。刪掉測試會被 `check-test-integrity.mjs` 擋下；實作的 PR 說明寫出改了哪些測試。
- 主行程：作者只從設定來（前端送的編輯給不了名稱）；日誌記下名稱，還原時一樣；修改的限制；顯示名稱的清理與上限；舊的設定檔。
- 前端：註解清單與附註對話框的回覆串、新增與修改、刪除的說明、設定的顯示名稱；鍵盤與焦點；無障礙（axe）。
- E2E：語料的回覆串在 app 裡看得到；加回覆、存檔、重新開啟，還在同一串。
- 負責人以 Acrobat Reader 手動確認一次：app 加的回覆在同一串，作者照顯示名稱（工作卡）。

### POC（實作前，不通過就不實作）
1. app 加的回覆（`/IRT`、位置與被回覆的註解相同，有或沒有彈出視窗）：Acrobat Reader 與另一個閱讀器都顯示在同一串，頁面上沒有多出圖示。
2. 選項 5 的 A（fork 加上 `pdf_set_annot_hidden_for_editing` 的包裝函式之後）：頁面、縮圖、列印與匯出圖片都沒有回覆的圖示；復原與重做的重播、崩潰後還原、worker 重啟之後再檢查一次；存檔的檔案裡沒有因此多出或少了旗標。

## 後果
- 換來：
  - 看得到別人在其他閱讀器做的回覆串，也能在 app 裡回覆，對方的閱讀器顯示在同一串；
  - 想被認出來才寫名稱，預設與現在一樣不寫任何可識別使用者的資訊；時間永遠不寫；
  - 名稱只由主行程填入，前端給不了別的名字；
  - 刪除與遮蔽的規則一致，回覆的文字不會在被回覆的註解刪除之後留下。
- 付出：
  - 新的編輯與寫入的欄位（`/IRT`、填了名稱時的 `/T`）：實作的 PR 要 `needs-security-review`；
  - 「app 建立的註解沒有作者」的規則與測試改成「沒填名稱時沒有作者」；刪除時把回覆的 `/IRT` 改成 `null` 的測試改寫成整串刪除；
