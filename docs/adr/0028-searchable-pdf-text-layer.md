# ADR 0028：可搜尋的 PDF 副本：辨識出的文字以 Tesseract 的空字型寫成隱形的文字層，只用於沒有簽章、沒有加密的文件

## 背景
- 規格 §2「OCR 引擎」：為掃描件產生可搜尋的文字層。ADR 0015 讓 app 在文件自己的 worker 中辨識掃描頁，但辨識出的文字只在 app 裡用（顯示、搜尋、選取）。寫進 PDF 的文字層要「另開卡」，就是 #416。
- #416 要的是另存一份新檔：在掃描頁的圖片上放隱形的文字（文字繪製模式 3，`3 Tr`），讓其他閱讀器也能搜尋與選取。頁面看起來不變，原檔不變（ADR 0013）。
- 隱形的文字還是要一個字型，把字碼對到 Unicode（`ToUnicode`）。中文字很多，嵌入一般字型的子集，檔案會隨字數變大。
- #416 規定：要在 repo 裡加入或產生新的字型，先寫 ADR。
- MuPDF 自己的 OCR 輸出（`source/fitz/output-pdfocr.c`）也嵌入 Tesseract 的空字型（572 位元組，`GlyphLessFont`），但不能直接用：
  - 它把每一頁畫成圖片，再做一份新的 PDF：向量內容、註解與表單都沒了；
  - 它用 MuPDF 的 OCR 裝置，從檔案讀語言資料，在沙盒中打不開（ADR 0015）。

### POC（#503）
- 字型：
  - **A**：Tesseract 的空字型 GlyphLessFont（`pdf_ttf.h`，573 位元組的 TrueType，只有一個空的字形）。用 Type0／CIDFontType2／Identity-H，所有 CID 都對到這個空字形，`ToUnicode` 再把 CID 對回 Unicode。
  - **B**：Droid Sans Fallback 的子集，沿用文字方塊的子集化（ADR 0018）。
  - **C**：不嵌入字型。只有估計，沒有實作。
- A 的兩種排法：
  - **A1**：一個詞一個位置，用 `Tz` 把詞拉到框的寬度（Tesseract 的做法）。
  - **A2**：每個字一個位置（`Tm`），字級是那個字框的高度，基線是字框的底。
- 量到的數字（debug 版，重跑過一次）：

  | | A1 | A2 | B |
  |---|---|---|---|
  | 英文：每頁多 | 1.76 KB | 1.85 KB | 2.05 KB |
  | 英文：位置誤差，平均／最大 | 1.75／5.04 pt | 0.01／0.01 pt | 5.00／6.61 pt |
  | 中英：每頁多 | 1.86 KB | 2.12 KB | 3.83 KB |
  | 中英：位置誤差，平均／最大 | 4.91／13.46 pt | 0.01／0.01 pt | 6.50／15.56 pt |

  - 寫一頁的文字層只要幾毫秒，比辨識快很多。三種做法畫出來的像素都跟原頁一樣（72 dpi 灰階）。
  - A2 的 0.01 pt 是照每個字框擺的，MuPDF 讀回來當然一樣。這不代表別的閱讀器會把這些字接成詞。
- **負責人在 Edge 看了 A2 的樣本（2026-11-14）**：
  - 英文大寫的掃描檔：搜得到整個片語 `PRIVACY FIRST`。
  - 中英混合的檔：
    - 搜得到 `隱私優先`；
    - `Privacy`、`FIRST` 分開都搜得到，`Privacy FIRST` 搜不到。這份檔案裡的字是 `Privacy-first`（連字號），本來就沒有這個片語。
  - 從樣本取出 A2 寫進去的字：
    - 詞與詞之間沒有空白（`Privacy-firstPDFReader`）；
    - 混合檔同一行的字級從 1.44 到 26.64 pt，例如連字號的框只有 1.44 pt 高，而且在基線上面；
    - 大寫檔整行只有一個字級（24.48 pt）、一條基線。

## 選項

### 字型

| 選項 | 換來 | 付出 |
|---|---|---|
| **A. Tesseract 的空字型（負責人 11-10 選定）** | 一個字型涵蓋所有 Unicode，不必子集化；檔案最小；Tesseract 與 MuPDF 都這樣做 | worker 裡多 573 位元組的字型資料 |
| B. Droid Sans Fallback 的子集 | 沿用現有的子集化 | 字寬跟掃描的字不一樣，位置差到 5～15 pt；檔案隨字數變大 |
| C. 不嵌入字型 | 檔案最小 | 靠閱讀器自己的字型與對應，沒有中文字型或換平台就對不上；沒有實作 |

### 排法

| 選項 | 換來 | 付出 |
|---|---|---|
| A1：一個詞一個位置，用 `Tz` 拉寬 | 跟 Tesseract 一樣，各家閱讀器都處理過這種檔 | 中文沒有空白，一整串字被當成一個詞，越後面的字偏得越多（最多 13 pt） |
| A2：每個字一個位置，字級是字框的高度 | 選取框最貼；Edge 搜得到 `PRIVACY FIRST` 與 `隱私優先` | 沒有空白：複製出來的字黏在一起，要靠閱讀器從間距猜空白；字級跟著字框跳（1.44～26.64 pt），標點與有下伸部的字最不穩 |
| **混合（建議；負責人 11-10 選定）**：同一行一個字級與基線，詞與詞之間寫空白，每個字的水平位置照 OCR 的框 | 有 Tesseract 的空白與整齊的行（大寫檔在 Edge 接得成片語，就是這種條件），也有 A2 的每字位置（中文不會越後面越偏） | 要多算每一行的字級與基線，程式比 A2 多一點 |

## 決定
1. **字型**：用 Tesseract 的空字型 GlyphLessFont（選項 A）。
   - 字型資料是 worker 程式碼裡的一個常數：`pdf_ttf.h` 的 573 位元組，(C) 2020 Google Inc.，Apache-2.0，著作權說明原樣保留。不在 repo 裡新增字型檔，也不在執行時產生字型。
   - Tesseract 已經列在第三方授權聲明裡（Apache-2.0）；聲明裡註明這個字型來自 Tesseract。
   - 一份文件只寫一個字型物件，所有加了文字層的頁共用。
   - CID 就是 UTF-16 的碼元，超過 U+FFFF 的字寫成代理對（兩個 CID）。
   - `ToUnicode` 每 256 個碼一段。PDF 32000-1 §9.10.3 規定：目的字串的最後一個位元組往上加，不能超過 255，否則結果未定義；寫成一段 `<0000> <FFFF>` 就會超過。
2. **排法**：混合。
   - 同一行一個字級與一條基線，詞與詞之間寫空白（U+0020），每個字的水平位置照 OCR 的框。
   - 字的寬度用 `Tz` 調到貼著框，選取的反白才對得上。
   - 不用 11-10 留下的 A2 例外。負責人 11-14 在 Edge 看過 A2（見上面）：A2 沒有空白，字級跟著字框跳；混合的做法保留了 A2 的每字位置。
   - 第一版只寫橫書的行。直書的行（要匯入 `*_vert` 的語言資料才辨識得出來）不加文字層，列為已知限制。
3. **哪些文件**：只做沒有簽章、沒有加密的文件。
   - 已簽章或加密的文件不適用，對話框說明原因，與「壓縮圖片並另存新檔」相同；app 裡照樣可以搜尋辨識出的文字。
   - 機敏文件的副本仍是機敏文件：另存新檔保留文件識別碼（`docs/architecture/saving.md`）。
4. **哪些頁**：只加在 `ocr_is_scan` 判定的掃描頁；已經有文字的頁不動。
   - 還沒辨識的頁先辨識，用設定裡的 OCR 語言；已經辨識過的頁直接用結果。
   - 辨識失敗、逾時（每頁最多 5 分鐘，`MAX_OCR_PAGE_MILLIS`）或沒有辨識出字的頁，不加文字層。其他頁照做，完成時列出這些頁。
5. **怎麼寫**：
   - 照 ADR 0013 另存一份新檔：整份重寫，清除沒用到的物件。原檔與開著的文件都不變。
   - 每頁原本的內容先包進 `q … Q`，再加上 `BT 3 Tr … ET`，跟 `page_overlay.rs` 加表單外觀的做法一樣。這樣原內容留下的圖形狀態（例如 `cm`）不會讓文字層偏掉。
   - 座標用頁面的轉換矩陣，處理 `/Rotate`，以及 MediaBox、CropBox 不從 (0, 0) 開始的頁。
   - 每頁的字數上限是 `MAX_PAGE_TEXT_CHARS`（10 萬），跟 app 裡的文字層一樣。
6. **畫面**：「⋯」→「另存為可搜尋的 PDF…」，有自己的對話框：顯示語言、要辨識幾頁、進度與取消。
   - 存檔位置由 Windows 的對話框選，預設檔名是 `<檔名>（可搜尋）.pdf`。
   - 照使用手冊第 4 章的規則：副本不開啟，也不加入最近開啟的檔案。
7. **不做**：
   - 批次：ADR 0024 的准入表寫著要等單一文件的版本，這份 ADR 實作之後才能加，規則 5 的時間上限到時再定；
   - 修正辨識錯的字；
   - 改變頁面的圖片。

## 後果
- 換來：
  - 掃描件可以分享給用其他閱讀器的人，對方也能搜尋與選取。每頁只多約 2 KB，看起來不變。
  - 沒有新的依賴，也沒有新的字型檔。辨識沿用 ADR 0015 的沙盒，不放寬。
- 付出：
  - 新的寫檔流程與 worker 請求：實作的 PR 要加 `needs-security-review`，`docs/security/attack-surface.md` 要加對應的列。
  - 辨識錯的字會原樣寫進副本。別的閱讀器不會像 app 一樣標示「此頁文字由 OCR 辨識，可能有誤」。
  - 已簽章與加密的掃描件不能另存成可搜尋的副本。
  - 轉了 90 度的掃描（內容側躺）辨識不出來（`docs/architecture/ocr.md` 的已知限制），這些頁不會有文字層。
- 要測的：
  - worker：寫入後重新開啟，文字擷取與搜尋都找得到；有文字的頁不變；畫出來的像素跟原頁一樣；轉動的頁、MediaBox 不從 (0, 0) 開始的頁、超過 U+FFFF 的字、原內容留下 `cm` 的頁。
  - E2E：掃描語料另存之後重新開啟，搜尋得到。
  - Edge：負責人在正式版驗收時搜 `PRIVACY FIRST`、`Privacy-first`、`PDF Reader`、`隱私優先`，再複製一行貼到記事本，看空白對不對。
- 之後若要改變這個決定，代價是：字型與排法只影響之後另存的副本，已經存出去的檔不會變。要換字型或排法，只要改 worker 寫文字層的程式與測試。
