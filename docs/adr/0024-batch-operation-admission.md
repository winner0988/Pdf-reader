# ADR 0024：批次處理的操作改為開放清單，依固定的准入規則加入

## 狀態
已接受

（負責人於 2026-10-21 接受選項 B〔[#308 的留言](https://github.com/winner0988/Pdf-reader/issues/308#issuecomment-6303088465)〕。工作卡 B3-19（[#308](https://github.com/winner0988/Pdf-reader/issues/308)），B3 擴充 E5，見 `docs/planning/2026-10-20-plan-to-nov-20.md`。修改規格 §7「批次處理佇列」的「範圍固定為四項操作」；不改 ADR 0005 與 CONTEXT.md「批次處理背景服務」的範圍。）

## 背景
- 規格 §7：批次處理「範圍固定為中繼資料清除、EXIF 清除、浮水印加註、加密四項操作」。B3-04（#235）照這四項做：`BatchOperation` 是 `RemoveMetadata`、`Encrypt`、`RemoveExif`，浮水印接在 #269 之後。
- 單一文件已經有、而且常常要對一整個資料夾做的操作，因為這條規定不能批次：壓縮圖片（B3-01，`compress-images.md` 的「不做」寫著「批次壓縮（ADR 0005）」）；之後的分享前淨化（#303）、頁碼與頁首頁尾（#304）也一樣。Bates 編號本來就是跨檔案連號的，只能一份一份做就失去意義。
- 批次處理的機制已經是通用的（`docs/architecture/batch.md`）：每個檔案在自己的 worker 中開啟、副本先寫進臨時檔、檢查後以不覆寫的移動取名、失敗只記原因、有密碼的略過、可以停止、可以在系統列繼續。加一項操作，實際上只是讓批次對每個檔案送出另一個**已經存在**的 worker 請求。
- 但不是每個操作都適合批次：遮蔽要逐筆確認（ADR 0016），簽署每份都要選憑證、可能要輸入 PIN（ADR 0020 提議中），合併是多個檔案變一份。需要一條清楚的界線，而不是逐項討論。

## 選項

| 選項 | 內容 | 代價 |
|---|---|---|
| A. 維持四項 | 規格不變 | 壓縮、淨化、頁碼要對很多檔案做時只能一份一份開；Bates 跨檔連號做不到 |
| **B. 開放清單，符合准入規則的操作以工作卡加入（建議）** | 規則寫在這個 ADR；每加一項是一張工作卡、一個 PR，照常 `needs-security-review` | 每一項仍要審查 IPC 與測試，但不必再寫 ADR |
| C. 開放清單，每加一項都要一個 ADR | 審查最嚴 | 每一項的論證都相同（重複單一文件的操作），ADR 變成形式；拖慢 |

## 決定（選項 B）

### 准入規則
一項操作要**全部**符合，才能加入 `BatchOperation`：

1. **單一文件已經有它**，已合併、有測試。批次只是對每個檔案重複**同一個** worker 請求，拒絕的規則也相同；批次不為了自己新增 worker 的能力。
2. **只產生副本**，原檔不變；照 `batch.md` 的「規則」：臨時檔、檢查輸出完整、不覆寫的移動、名稱與編號。輸出不是 PDF 的操作（例如匯出 Word）要在它的工作卡寫明「完整」怎麼檢查。
3. **不需要逐檔判斷或互動**：參數在開始前一次給完，對每個檔案都相同。唯一的例外是批次依序產生的編號（見下方 Bates）。要看過內容才能決定的操作不能批次。
4. **會讓簽章失效的操作，有簽章的檔案就失敗**（原因寫進結果），不提供「仍要做」；有密碼的檔案照舊略過，批次不詢問開啟密碼。
5. **每個檔案有時間與輸出大小的上限**；超過時這個檔案失敗、不留臨時檔，下一個照做。
6. **參數由主行程 `validate`，沒有路徑**。參數需要檔案時（例如浮水印的圖片），由主行程以系統對話框選。秘密照 `Password` 的規則（只交給每個 worker 一次、不進事件、報告與日誌）。
7. **報告與事件只有操作名稱、檔名與結果**，不含文件的內容。

加入一項操作的工作卡要寫明它怎麼符合每一條；不符合任何一條就要另寫 ADR。

### 現在的判斷

| 操作 | 判斷 | 說明 |
|---|---|---|
| 清除中繼資料、加密、清除 EXIF、浮水印 | 已有 | B3-04 |
| 壓縮圖片（B3-01） | 可以加入 | 已有單一文件版本，有簽章與加密拒絕、有時間上限（`compress::BUDGET`） |
| 分享前淨化（#303）、頁碼與頁首頁尾（#304） | 單一文件版本合併後可以加入 | 規則 1 |
| Bates 編號（#304） | 單一文件版本合併後可以加入 | 見下方 |
| 匯出 Word（B3-02） | 可以加入 | 要先寫明 `.docx` 的完整檢查（規則 2） |
| OCR 並另存為可搜尋的 PDF | 單一文件版本存在後才可以 | ADR 0015：寫進 PDF 的文字層「另開卡」，現在還沒有；OCR 慢，規則 5 的上限要在那張卡定 |
| 遮蔽、找出個資（#302） | 不可以 | 規則 3：ADR 0016 要使用者逐筆確認，不自動套用 |
| 簽署（ADR 0020 提議中） | 不可以 | 規則 3：每份都要選憑證、可能要 PIN；一次簽很多份要另寫 ADR |
| 合併、拆分、從檔案建立 PDF | 不屬於批次 | 不是「一個 PDF 一份副本」 |

### Bates 跨檔連號
- 號碼依批次的順序（對話框給的順序，`batch.md`）一個檔案接一個：下一個檔案從上一個**做好**的檔案的最後一號加一開始。
- 失敗或略過的檔案**不佔號碼**，所以做好的副本之間沒有缺號；每個檔案的結果顯示它的號碼範圍（第一號到最後一號），視窗隱藏時寫進報告。
- 停止時，已經做好的副本與它們的號碼留著；再做一次是新的一批，從使用者設定的起始號碼開始。

## 後果
- 換來：壓縮、淨化、頁碼可以對整個資料夾做；Bates 能跨檔案連號；加一項操作不必每次都寫 ADR。
- 付出：`BatchOperation` 與批次對話框會變大，每一項都要審查與測試；准入規則要在審查時實際檢查，而不是只看工作卡怎麼說。
- 不改變：批次仍是使用者主動啟動、做完就結束，背景執行與系統列圖示的範圍照 ADR 0005 與 CONTEXT.md；沒有網路。
- 接受後要一起改（不在這個 ADR 的 PR）：規格 §7（中英文）的「範圍固定為四項」改成「依 ADR 0024 的准入規則」，規格的版本摘要那一行；`docs/architecture/compress-images.md` 的「不做」拿掉「批次壓縮」；`batch.md` 加上准入規則的連結。
- 之後若要讓不符合規則的操作（例如一次簽很多份）進批次，要另寫 ADR。
