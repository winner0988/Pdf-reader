- **需求 ID**：MVP-R2、MVP-R3
- **負責角色**：核心 agent＋前端 agent（若 PR 超過約 600 行，拆成 07a worker 端渲染與快取、07b 前端虛擬滾動）
- **相依**：MVP-06

## 目標
數千頁、數百 MB 的 PDF 也能流暢捲動：只渲染看得到的頁面，記憶體用量有上限。

## 範圍
- 前端依可視範圍（上下各預載 1～2 頁）請求頁面；其他頁只放依頁面尺寸計算的占位框，捲軸長度正確。
- 快速捲動時取消已離開視窗的渲染請求。
- 依縮放比例與裝置像素比渲染，HiDPI 螢幕清晰。
- 快取：LRU，以位元組上限控制（初始 256 MB，可調）。
- 單頁點陣圖尺寸上限（例如最長邊 8192 px），超過時降低解析度；分塊（tile）渲染留到之後。
- 影像傳輸採 MVP-02 決定的方式。

## 不做什麼
- 縮放 UI（MVP-08）、縮圖、文字選取、GPU 加速調校。

## 可動的模組
- `crates/pdf_worker/`（渲染）
- `src-tauri/src/`（請求排程、快取）
- `src/features/viewer/`

## 驗收情境
以下為初始預算，在負責人的 Windows 電腦上量測，負責人可調整：
- 1000 頁、約 200 MB 的 PDF（QA-01 `large/`）：從開檔到第一頁顯示 < 1.5 秒。
- 連續快速捲動 10 秒：主行程＋worker 記憶體總和 < 1 GB，且不持續成長。
- 正常速度捲動時，空白占位不超過 300 ms。
- 捲到最後一頁再捲回第一頁，內容正確。
- 渲染中 worker 崩潰 → 受影響的頁面顯示錯誤占位與重試按鈕，其他功能正常。

## 必跑測試
- 單元測試：可視範圍計算、取消邏輯、LRU 淘汰。
- worker 渲染測試（QA-01 語料）。
- 效能量測腳本或步驟；MVP 階段可手動執行，把結果附在 PR。

## 資安限制
- worker 回傳的頁數與頁面尺寸都要驗證上限，避免惡意 PDF 宣告超大頁面導致記憶體耗盡。
- 單頁最大像素數寫成常數，並有測試覆蓋。
