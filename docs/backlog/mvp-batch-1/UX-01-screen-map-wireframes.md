- **需求 ID**：MVP-R11（並涵蓋 MVP-R1、R3～R9 的畫面部分）
- **負責角色**：前端 agent 製作，負責人驗收
- **相依**：無

## 目標
在寫 UI 程式碼之前，先有一份可以驗收的畫面地圖與行為規格，讓 MVP-05、08～12 的前端工作有共同依據。

## 範圍
- `docs/ux/screen-map.md`：列出所有畫面與區域
  - 主視窗：工具列、側欄（目錄分頁；縮圖分頁先占位）、頁面畫布、狀態列、安全警示橫幅
  - 搜尋列、外部連結確認對話框、主動內容明細面板、設定（占位）、關於（說明離線與無遙測）
  - 空狀態、載入中、錯誤狀態（損毀、非 PDF、加密不支援、worker 崩潰）
- 低保真 wireframe：每個畫面一張，以 PNG／SVG 或 Mermaid 提交進 `docs/ux/`（不需要 Figma）。
- UI 行為規格：
  - 縮放級距、適合寬度／適合頁面、捲動行為
  - 快捷鍵表（不與 Windows 慣例衝突）
  - 深色模式、焦點順序、鍵盤操作
  - 所有使用者可見文字（繁中）：錯誤訊息、安全橫幅、連結確認對話框
- 驗收截圖清單：每張 MVP UI 卡片的 PR 必須附哪些截圖。

## 不做什麼
- 高保真視覺設計、品牌識別、圖示設計。
- 任何程式碼。

## 可動的模組
- `docs/ux/`

## 驗收情境
- 負責人在 PR 中核准。
- MVP-05、08、09、10、11、12 每一張卡都能在文件中找到對應的畫面與行為描述。
- 連結確認對話框的設計能完整顯示超長 URL，且能醒目標示 scheme、主機名稱與國際化網域（IDN）。

## 必跑測試
- 無（文件）。CI `Guardrails` 通過即可。

## 資安限制
- 安全相關文字（橫幅、確認對話框）必須讓使用者看得懂「被擋下什麼、為什麼」，且不提供一鍵「全部允許」。
- 關於頁需明確說明：不連網、不收集任何資料。
