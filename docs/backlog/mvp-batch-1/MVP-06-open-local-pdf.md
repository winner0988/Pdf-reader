- **需求 ID**：MVP-R1
- **負責角色**：核心 agent（主行程）＋前端接線
- **相依**：MVP-04、MVP-05

## 目標
使用者可以用三種方式開啟本機 PDF，前端只拿到不透明的文件代號，永遠拿不到檔案路徑。

## 範圍
- 三種開啟方式：
  - `Ctrl+O`：由主行程（Rust 端）開啟原生開檔對話框，只篩選 `.pdf`
  - 拖放：在主行程處理視窗的拖放事件，不把路徑轉送給前端
  - 命令列參數：`app.exe <file.pdf>`（為之後的檔案關聯鋪路）
- 主行程檢查：檔案存在、可讀、大小上限、內容可被 worker 解析；通過後以 MVP-04 的方式交給 worker。
- 前端只收到文件代號與 `DocumentInfo`；關閉文件時釋放 worker 資源。
- 錯誤處理：損毀檔、非 PDF、加密 PDF（MVP 不支援解密，顯示「此文件已加密，目前版本尚不支援」）、權限不足。
- 一個視窗一次開一份文件；拖放多個檔案時只開第一個並提示。

## 不做什麼
- 檔案關聯註冊、最近開啟清單（牽涉 ADR 0004 的規則，另開卡）、多分頁、密碼輸入。

## 可動的模組
- `src-tauri/src/`（開檔、拖放、命令列）
- `src/features/open/`、`src/ipc/`
- `src-tauri/capabilities/`（只能新增本卡必要的最小權限）

## 驗收情境
- 三種方式都能開啟 QA-01 的一般 PDF，並顯示正確頁數。
- 開啟改副檔名的文字檔、截斷的 PDF、加密 PDF → 各自顯示對應錯誤，應用程式不崩潰。
- 在前端程式碼、IPC 訊息與前端日誌中都找不到完整路徑（可以顯示檔名）。
- 拖放 3 個檔案 → 只開第一個並提示。

## 必跑測試
- 主行程單元測試：檔案檢查、錯誤分類、命令列解析。
- 前端元件測試：各種錯誤狀態顯示。

## 資安限制
- 路徑只存在主行程。不得使用讓前端直接讀檔的外掛權限，也不得讓對話框的前端 API 把路徑回傳給前端。
- 正式建置的日誌不得記錄完整路徑或文件內容。
