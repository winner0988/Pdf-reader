- **需求 ID**：規格 §6「互動表單填寫」；ADR 0001（表單腳本沙盒：本卡不做）
- **負責角色**：前端 agent＋核心 agent
- **相依**：B2-02

## 目標
填寫標準 PDF 表單（AcroForm）的文字欄位、核取方塊、選項按鈕與下拉選單，存檔；也可以把表單「扁平化」成不能再修改的靜態內容。

## 範圍
- worker 回報每頁的欄位（類型、位置、目前的值、選項、唯讀、必填、最大長度）；前端在頁面上疊加對應的輸入元件，縮放與旋轉時位置正確。
- `Tab` 依欄位順序移動；只用鍵盤可以填完整份表單。
- 值寫回 worker（編輯指令），更新外觀串流；復原／重做。
- 扁平化：「⋯」→「扁平化表單…」，確認後把欄位外觀併入頁面內容，另存新檔。
- **不執行任何表單腳本**：計算欄位、格式化、驗證腳本都不跑；有腳本的欄位顯示提示（例如「這個欄位的自動計算不會執行」）。表單腳本沙盒（ADR 0001）另開 POC。
- 送出按鈕（`SubmitForm`）維持封鎖（MVP-11）。
- 權限（MVP-19）：`/P` 的第 9 位元（填寫表單）與第 6 位元（註解與表單）都沒有設定時，表單唯讀。

## 不做什麼
- XFA 表單（MVP-11 已偵測並提示）；簽章欄位（B2-11 之後）；表單腳本。

## 可動的模組
- `src/features/`（新的 `forms/`）、`src/features/viewer/`、`src/i18n/zh-TW.ts`
- `crates/ipc_contract/`、`crates/pdf_worker/`
- `tests/corpus/`（新增表單樣本：各種欄位類型、有計算腳本的欄位）

## 驗收情境
- 假設填寫表單樣本的文字欄位與核取方塊並存檔，當以 MuPDF 讀取輸出檔，則欄位值正確，外觀與值一致。
- 假設欄位有計算腳本，則填寫後畫面提示腳本不會執行，沒有任何腳本被執行（沿用 MVP-11 的驗證方式）。
- 假設扁平化後另存，則新檔沒有 `AcroForm` 欄位，頁面上仍看得到填好的值。

## 必跑測試
- worker 測試：讀取欄位、寫入值、扁平化、腳本不被執行。
- 前端：欄位疊加的座標、鍵盤順序。
- E2E：填寫並存檔後重新開啟。

## 資安限制
- 欄位值長度與欄位數量有上限；值經過 `ipc_contract` 驗證。
- JavaScript 維持完全不執行（MuPDF 編譯時就不含 JavaScript 引擎）。
