## ADR 0032 到 0035 的卡
- 四份 ADR 在 11-23 以「提議中」合併（PR #701、#704、#705、#706）。
- 負責人 11-24 決定：
  - 0032、0033、0035：每一組都選建議的做法。
  - 0034 照負責人的需求改寫：可攜版是一個資料夾，不安裝，資料夾裡附 Fixed Version 的 WebView2；支援 64 位元的 Windows 10 22H2 與 Windows 11，安裝版照舊只支援 Windows 11；也要能在 exFAT、FAT32 的隨身碟上執行，實作前先以 POC 確認那裡的隔離。
- **PR #721 把四份改成「已接受」**（11-25 還沒有合併）。下面四張卡都等它合併。
- 每份 ADR 都規定實作前先做 POC，不通過就不實作。

各卡在等什麼：
- **#440**（ADR 0032）：一次合併多個 PDF，每個來源一個書籤。
  - 只等 #721：合併之後就可以開始，先做 ADR 的 4 個 POC。
  - 選項 4 的 C（帶上圖層與預設的顯示狀態）等 #442 的 fork 包裝函式合併之後，另開卡。
- **#447**（ADR 0033）：從 XFDF 匯入註解。匯入的是不受信任的檔案。
  - #721 合併之後，先做 ADR 的 3 個 POC。
  - POC 1 在 worker 加 `quick-xml` 0.42.0，是依賴的變更，要 `needs-security-review`。
  - POC 2 要 Acrobat Reader 與其他常見軟體匯出的 XFDF。
- **#449**（ADR 0034）：免安裝版（可攜版）。
  - #721 合併之後，先做 ADR 的 5 個 POC。
  - POC 2 到 4 要乾淨的 Windows 11 與 Windows 10 22H2，也就是另一台電腦或虛擬機。開發機是 Windows 11 家用版，虛擬機要另外裝，由負責人決定。
  - exFAT、FAT32 的隔離比較弱時，由負責人在「啟動時提醒」與「不執行」之間選。
- **#445**（ADR 0035）：註解的回覆。作者名稱只來自設定中自己填的顯示名稱，預設空白。
  - 等 #721，也等 fork 的 `pdf_set_annot_hidden_for_editing` 包裝函式（和 #442 的圖層函式同一個 commit）：POC 2 要用到它。

## 會互相衝突的地方
後合併的 PR 先合併 `main`，再照下面處理：
- **英文介面之後的字串**：#683 合併之後，介面的每一個新字串都要同時加進 `src/i18n/en.ts`；少了的話，`pnpm typecheck` 會失敗。在那之前開的 PR，合併 `main` 時補上。
- **`Edit`、`WorkerEdit` 的新變體**（#687、#684 的頁碼格式）：加在最後，兩邊都留；`fuzz/fuzz_targets/edit_document.rs` 與 `docs/security/fuzzing.md` 的數量照合併後的總數重算。
- **新命令的權限**（#442、#588、#599、#687、#689）：加在 `src-tauri/allowed-permissions.json` 的 `permissions`，`docs/security/attack-surface.md` 的列與標題的數量跟著改。
- **語料**（#596、#686、#617）：`tests/corpus/manifest.json` 衝突時不要手改，兩邊的 `generate.py` 都留下，再用腳本重新產生。
- **`CHANGELOG.md`**：每個 PR 自己那一行留在 `## [Unreleased]`。
- **圖層的偵測**（#703、#440）：兩張用同一個偵測（ADR 0032 選項 4 的 A）。後做的那張用先合併的那一份，不要再寫一份。
- **fork**：只有困難問題解決會在 `v0.8.0-mupdf-1.28` 加 commit，而且要負責人同意；agy 不推送到 fork。
