## 等負責人決定
這些卡在負責人決定之前不開始：
- **#442**：圖層。`mupdf` 繫結沒有圖層的函式，MuPDF 的 context 與文件指標也只在繫結內部，所以卡裡寫的「經 `mupdf_sys` 呼叫」做不到。
  - 要先在 fork 加圖層的安全包裝（`pdf_count_layer_config_ui`、`pdf_layer_config_ui_info`、`pdf_toggle_layer_config_ui`），由困難問題解決做，要負責人同意；之後 agy 做 worker 與畫面。
  - Claude Code 建議這樣做。
- **#672**：縮圖等小倍率下，畫不完的 tiling pattern 仍會等到 30 秒。卡裡有三個做法。
  - Claude Code 建議選項 3：在兩個迴圈裡檢查時限，先做原型。
- **#551**：記憶體到達上限的那一個檔案。卡的留言裡有 JPEG 2000 降低解析度解碼的做法，要先做原型。
- **#663**：CodeQL 對測試碼裡密碼的警示。
  - 方案 A：改用進階設定，Rust 的 extractor 用 `cargo_cfg_overrides=-test` 不分析 `cfg(test)`，並略過測試路徑。不用 `query-filters` 排除整條規則：那樣正式程式碼裡寫死的金鑰也抓不到。
  - 方案 B：維持預設設定，由負責人標記。
  - Claude Code 建議方案 A。切換設定由負責人做。
- **#664**：WebView2 對被擋下的 `<iframe>` 先預先連線。要處理，或寫進 `SECURITY.md` 的已知邊界。
- **#687**：建立與修改表單欄位。要等 #686 的 POC 通過，而且負責人在其他閱讀器裡看過結果。
- **#688、#689**：從掃描器掃描。POC 要一台掃描器，或虛擬的 WIA 掃描器；安裝驅動程式由負責人決定。
- **#238**：表單腳本沙盒（ADR 0001、0021），標著 `blocked`。#453 的 POC 是它的替代方案。

## 會互相衝突的地方
後合併的 PR 先合併 `main`，再照下面處理：
- **英文介面之後的字串**：#683 合併之後，介面的每一個新字串都要同時加進 `src/i18n/en.ts`；少了的話，`pnpm typecheck` 會失敗。在那之前開的 PR，合併 `main` 時補上。
- **`Edit`、`WorkerEdit` 的新變體**（#687、#684 的頁碼格式）：加在最後，兩邊都留；`fuzz/fuzz_targets/edit_document.rs` 與 `docs/security/fuzzing.md` 的數量照合併後的總數重算。
- **新命令的權限**（#442、#588、#599、#687、#689）：加在 `src-tauri/allowed-permissions.json` 的 `permissions`，`docs/security/attack-surface.md` 的列與標題的數量跟著改。
- **語料**（#596、#686、#617）：`tests/corpus/manifest.json` 衝突時不要手改，兩邊的 `generate.py` 都留下，再用腳本重新產生。
- **`CHANGELOG.md`**：每個 PR 自己那一行留在 `## [Unreleased]`。
- **fork**：只有困難問題解決會在 `v0.8.0-mupdf-1.28` 加 commit，而且要負責人同意；agy 不推送到 fork。
