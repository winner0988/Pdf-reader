## 會互相衝突的地方
功能的 PR 之間沒有先後，但會改到同樣的地方。後合併的 PR 先合併 `main`，再照下面處理：
- **`docs/security/attack-surface.md`**：命令的數量與 `WorkerEdit` 的種類，照合併後的列重算。
- **`Edit`、`WorkerEdit` 的新變體**（#589、#590、#591）：
  - 都加在最後，兩邊都留；
  - worker 的訊息依變體的順序編號；主行程與 worker 一起建置，順序只要兩邊一致就好。
- **fuzz 的 `edit_document.rs`**（#589、#590、#591）：新的編輯種類兩邊都留，範圍照總數重算。
- **`CHANGELOG.md`**：每個 PR 自己那一行留在 `## [Unreleased]`。
- **圖片印章**：
  - #591 會放寬 `prepare_stamp_image` 的權限（註解或修改）；
  - #587 另寫一個方法，不改 `prepare_stamp_image`。
- **`mapPageAfterEdit`**：#590 會在這裡加 `replacePages`；#636 修插入頁面時，也會改同一個函式。
- **權限清單**：#653（#586）、#660（#446）、#662（#587）在 `check-security-config.mjs` 加了權限。#665 把清單移到 JSON，誰先合併都可以，做法寫在 #665。

兩個 fork 修正要照順序合併：
- #628、#629 在 fork 上的 commit 接在 #626 的後面，所以它們的 PR 用的 rev 已經包含 #626 的修補。
- 先合併 #626 的 PR，再合併 #628、#629 的；後者合併前先合併 `main`。
- 兩個 PR 都會改：
  - fork 的 rev：根目錄與 `fuzz/` 的 `Cargo.toml`、`Cargo.lock`；
  - `docs/security/bundled-libraries.md`、`docs/architecture/mupdf-binding.md`、`src/assets/THIRD_PARTY_LICENSES.txt` 與 `CHANGELOG.md`。
